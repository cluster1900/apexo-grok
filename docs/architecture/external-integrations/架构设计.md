# 外部集成架构设计

## 1. 职责与边界

本上下文负责 GitHub Action、VS Code extension、Zed extension、Slack bot、ACP/SDK 消费者等外部产品入口与 opencode-rs core 的兼容边界。上游入口包括 `github/*`、`sdks/vscode/*`、`packages/extensions/zed/*`、`packages/slack`、CLI `acp` 和 SDK。

不负责内部 session/tool/provider 规则；外部集成只通过 CLI、HTTP、SSE/WS 或 SDK 调用 application use case。

## 2. 核心概念

| 概念 | 类型 | 说明 |
|---|---|---|
| `IntegrationInstallation` | 聚合根 | 某外部平台的一次安装与授权状态。 |
| `IntegrationEvent` | 领域事件 | 外部平台输入被接收、校验、转为 opencode request 的事实。 |
| `ExternalActor` | 值对象 | GitHub user、Slack user、editor user 等来源身份。 |
| `ExternalReference` | 值对象 | issue/PR/comment/file/selection/line range/channel/thread 的引用。 |
| `IntegrationCommand` | 值对象 | `/opencode`、`/oc`、VS Code command、Slack command、ACP request。 |

## 3. 模块拓扑

| 层 | 模块 | 依赖 |
|---|---|---|
| domain | `integration`、`external_reference`、`actor` | 只建模命令、事件、授权状态和输入不变量。 |
| application | `receive_github_event`、`append_editor_context`、`run_action_task`、`sync_extension_manifest` | 将外部 DTO 转为 session prompt、tool permission、share/reply 动作。 |
| infrastructure | GitHub API、VS Code API、Zed manifest、Slack API、ACP transport | 平台 SDK 与 webhook adapter。 |
| interface | GitHub Action entrypoint、extension command、Slack HTTP endpoint、ACP stdio | 外部可见入口。 |

## 4. 对外契约

- GitHub Action 兼容 `github/action.yml` inputs/env 与 `github/index.ts` 行为：issue comment、PR comment、review comment、diff context、branch/PR/share。
- VS Code extension 兼容命令和快捷键：`opencode.openTerminal`、`opencode.openNewTerminal`、`opencode.addFilepathToTerminal`，并保留 `@File#Lx-y` 引用格式。
- Zed extension 保留 manifest、图标与同步脚本语义；Rust core 只保证 CLI/SDK 被调用时的兼容行为。
- Slack bot 通过 SDK/HTTP contract 调用 core，不泄漏 Slack DTO 到 domain。
- ACP 协议由 interface adapter 处理；domain 只接收已校验的 session/tool intent。

## 5. 关键不变量

- 外部 webhook/comment/selection 必须作为不可信输入进入 prompt，截断并包裹 `<untrusted_input>`。
- 外部平台 token 不进入日志、prompt 和命令行。
- 同一外部事件必须幂等处理，避免重复提交、重复评论或重复创建分支。
- 任何外部集成触发的文件修改都受 workspace sandbox 和 permission workflow 约束。

## 6. 错误模型

| 错误 | 类型 | 说明 |
|---|---|---|
| `IntegrationUnauthorized` | 业务错误 | 安装缺失、token 无效、actor 无权限。 |
| `ExternalEventIgnored` | 业务结果 | 评论不含触发词、事件类型不支持或已处理。 |
| `ReferenceResolutionFailed` | 业务错误 | issue/PR/file/selection 无法解析。 |
| `PlatformRateLimited` | 可重试基础设施错误 | GitHub/Slack/editor API 限流。 |
| `IntegrationReplyFailed` | 可重试基础设施错误 | 执行完成但回写外部平台失败。 |

## 7. 扩展点

- 新平台通过 `IntegrationAdapter` 接入，输出统一 `IntegrationCommand`。
- 外部回复策略作为 application policy，可按平台配置禁用 share、PR 创建或直接评论。
- Editor extension 只依赖 CLI/HTTP/SDK，不依赖 Rust 内部模块。

## 8. 未决问题

- GitHub Action 的本地 mock event schema 是否纳入 Rust 测试 fixture，需要实现阶段确定。
- VS Code 与 Zed 的发布是否继续保留 TS 项目，还是迁移为生成型薄包装，需要单独评估。
- Slack 入口的最终部署归属在 cloud-console-stats 还是独立服务，需要结合实际 package 复核。
