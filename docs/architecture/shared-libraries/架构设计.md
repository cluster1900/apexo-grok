# 共享库与协议内核架构设计

## 1. 职责与边界

本上下文负责上游共享库的 Rust 迁移边界：`packages/core`、`packages/llm`、`packages/http-recorder`、`packages/script`、`packages/effect-drizzle-sqlite` 以及 `specs/*` 中的 v2 设计输入。它抽取跨 CLI/HTTP/Desktop/Cloud/Integration 复用的 schema、typed errors、provider protocol、record/replay、plugin hook contract 和生成脚本语义。

不负责直接提供用户入口；用户入口由 interface、desktop、external integrations、cloud 上下文调用共享库。

## 2. 核心概念

| 概念 | 类型 | 说明 |
|---|---|---|
| `SharedSchema` | 值对象 | 跨上下文复用的 session/provider/tool/config/OpenAPI schema。 |
| `ProtocolAdapter` | 领域服务 | OpenAI/Anthropic/Gemini/Bedrock/OpenAI-compatible 等协议转换。 |
| `RecordedExchange` | 聚合根 | HTTP/WS 录制回放 cassette，含匹配和脱敏规则。 |
| `CorePluginHook` | 领域事件/扩展点 | v2 core 的 provider/model/account/agent hook contract。 |
| `CodegenTask` | 实体 | OpenAPI/SDK/docs/schema 生成任务。 |

## 3. 模块拓扑

| 层 | 模块 | 依赖 |
|---|---|---|
| domain | `schema_kernel`、`protocol`、`recording`、`hook_contract` | 无 I/O，定义共享类型、错误和不变量。 |
| application | `generate_schema`、`route_llm_request`、`record_http_exchange`、`run_codegen` | 编排共享能力。 |
| infrastructure | provider HTTP、SSE/WS parser、cassette filesystem、OpenAPI generator、legacy SQLite adapter | 外部协议和文件系统 adapter。 |
| interface | SDK generation、provider test harness、script CLI | 供开发/测试/发布使用。 |

## 4. 对外契约

- `packages/core` 的 v2 方向是 Rust domain 的建模输入：schemas、branded ids、typed errors、events、plugin hook contract。
- `packages/llm` 的 protocol/provider/route/tool-runtime 需要映射到 Rust Provider & Model，不得只按旧 AI SDK adapter 建模。
- `packages/http-recorder` 的 cassette、matching、redaction、websocket 语义用于 provider/HTTP 录制回放测试。
- `packages/script` 的 generate/publish/version/stats/changelog/sync-zed 等脚本语义归入 codegen/release application。
- `packages/effect-drizzle-sqlite` 只保留数据兼容语义；Rust 不复制 Effect/Drizzle 实现。
- `specs/v2/*` 是设计输入；若与旧实现冲突，先在 progress 中标注并经人类确认。

## 5. 关键不变量

- Shared schema 是跨边界契约，不能为了某个 adapter 私自改字段含义。
- 录制回放必须脱敏 auth header、API key、cookie、secret query/body 字段。
- Provider protocol adapter 必须保留 streaming event 顺序、tool call framing、usage/cost 信息。
- 生成任务必须可复现；生成物漂移要在 CI 中 fail-fast。

## 6. 错误模型

| 错误 | 类型 | 说明 |
|---|---|---|
| `SchemaDrift` | 测试/业务错误 | Rust schema 与上游 OpenAPI/SDK/specs 不一致。 |
| `ProtocolFrameInvalid` | 业务错误 | Provider stream/tool frame 解析失败。 |
| `RecordingMismatch` | 测试错误 | 请求匹配不到 cassette 或响应不一致。 |
| `RedactionViolation` | 安全错误 | cassette 或日志含 secret。 |
| `CodegenFailed` | 可恢复基础设施错误 | 生成脚本失败。 |

## 7. 扩展点

- 新 provider protocol 通过 `ProtocolAdapter` 接入 Provider & Model。
- 新生成物通过 `CodegenTask` 接入，不直接在业务代码中写生成逻辑。
- 录制回放可以替换为外部 mock server，但 redaction contract 不变。

## 8. 未决问题

- `packages/core` v2 与旧 `packages/opencode` 重叠部分的优先级需要逐模块决策。
- Rust 是否需要单独 crate 承载 schema kernel、provider protocol 和 recorder，需要在 workspace skeleton 阶段确定。
- 录制文件格式是否直接兼容上游 cassette，需要实现阶段读取样例后确认。
