# minimum-agent 架构设计

## 1. 职责与边界

`minimum-agent` 是 opencode-rs 的第一条可运行主线，目标是分阶段做出一个最小但真实的 coding agent：

- M1 先实现纯 domain kernel。
- M2 再让 CLI 通过 fake provider 跑通 text-only。
- M3 加入前期精简 `ContextPack`：instruction、skill index、memory snapshot。
- M4 增加 session 持久化。
- M5 接入真实 OpenAI-compatible provider。
- M6 定义插件 / capability 内核。
- M7 增加 workspace read tool 和 skill tool。
- M8 增加 local stdio MCP Lite。
- M9 增加 write/shell 和 permission。

本组件不负责：

- 完整 TUI / Web / Desktop。
- HTTP API / OpenAPI / SDK。
- 完整 MCP runtime（remote HTTP/SSE、OAuth、dynamic add、prompt）。
- 动态插件运行时。
- 完整 provider catalog。
- 完整长期记忆库 / 向量记忆。
- 完整 LSP / formatter / snapshot / sync / share。

这些能力必须通过后续插件或接口层安装进来，不能阻塞最小主线。

全局 DDD 边界以 [`../context-map.md`](../context-map.md) 为准；核心术语以 [`../ubiquitous-language.md`](../ubiquitous-language.md) 为准；事件 schema 以 [`../events.md`](../events.md) 为准。上游源码证据和最小范围取舍见 [`../../research/minimum-agent-scope/调研报告_2026-06-03.md`](../../research/minimum-agent-scope/调研报告_2026-06-03.md) 与 [`../../research/opencode-context-extension-surfaces/调研报告_2026-06-03.md`](../../research/opencode-context-extension-surfaces/调研报告_2026-06-03.md)。

## 2. 核心概念

| 概念 | 类型 | 所属上下文 | 说明 |
|---|---|---|---|
| `WorkspaceRoot` | 值对象 | Workspace | 显式工作区根路径，所有文件工具必须基于它做规范化和 containment。 |
| `WorkspacePath` | 值对象 | Workspace | 已确认在 workspace 内的绝对路径。 |
| `Session` | 聚合根 | Conversation | 一次用户与 agent 的连续对话。 |
| `Turn` | 实体 | Conversation | 一次用户请求和对应 assistant/tool 循环。 |
| `Message` | 实体 | Conversation | 用户、assistant、tool/system 产生的消息。 |
| `Part` | 实体 | Conversation | message 下的 text、reasoning、tool、usage、error 等片段。 |
| `AgentProfile` | 值对象 | Agent | agent 名称、prompt、权限、step 上限、模型偏好。 |
| `ContextPack` | 值对象 | Context | instruction、skill index、memory snapshot、MCP resource 等进入模型前的统一上下文包。 |
| `InstructionSource` | 值对象 | Context | `AGENTS.md` / `CONTEXT.md` 等系统指令来源。 |
| `SkillIndex` | 值对象 | Context | 可用 skill 的 name、description、location 索引。 |
| `MemorySnapshot` | 值对象 | Context | session summary、last N turns、关键 anchors 的轻量记忆快照。 |
| `ModelRef` | 值对象 | Provider | `provider_id + model_id + variant?`。 |
| `LlmRequest` | 值对象 | Provider | provider-neutral 模型请求。 |
| `LlmEvent` | 领域事件输入 | Provider | text/tool/reasoning/finish 等统一流式事件。 |
| `ToolDefinition` | 值对象 | Tool | name、description、JSON Schema、permission level、timeout。 |
| `ToolCall` | 实体 | Tool | 模型请求执行的工具调用。 |
| `PermissionRule` | 值对象 | Permission | allow / deny / ask 规则。 |
| `McpServerConfig` | 值对象 | MCP | local stdio MCP server 的命令、enabled、timeout。 |
| `McpResourceRef` | 值对象 | MCP | MCP resource 的 client、uri、mime 元数据。 |
| `PluginCapability` | 值对象 | Extension | 后续插件可注册的能力声明。 |

## 3. 模块拓扑

Rust workspace 先保持两个 crate：

```text
opencode-core
  domain/
    workspace/
    session/
    provider/
    tool/
    permission/
    agent/
    context/
    mcp/
    extension/
  application/
    run_agent/
    build_context_pack/
    project_events/
    capability_registry/
    mcp_lite/
  infrastructure/
    storage/
    provider_openai_compatible/
    instruction_loader/
    skill_loader/
    filesystem_tools/
    mcp_stdio/
    shell_tool/
  interface/
    cli_adapter/

opencode-cli
  main.rs
```

依赖方向：

```text
opencode-cli
  -> opencode-core::interface
    -> opencode-core::application
      -> opencode-core::domain

opencode-core::infrastructure
  -> application ports
  -> domain types
```

禁止：

- domain 依赖 tokio、reqwest、sql、filesystem、CLI。
- provider adapter 直接修改 session。
- tool 执行绕过 permission。
- skill / MCP / plugin 能力绕过 workspace / permission / secret / schema / ContextPack 不可信标记。

## 4. 对外契约

### 4.1 CLI 契约

M2 只暴露 mock run：

```bash
opencode run --mock <prompt>
```

M5 暴露真实 provider run：

```bash
opencode run <prompt> [--model provider/model] [--workspace <path>] [--session <id>]
```

M3 起 application 内部构造 `ContextPack`，但 CLI 不额外暴露 context 命令。M8 可通过配置启用 local stdio MCP，不暴露 HTTP MCP API。

M9 增加：

```bash
opencode run <prompt> --allow <permission-pattern>
opencode run <prompt> --deny <permission-pattern>
opencode run <prompt> --ask <permission-pattern>
```

暂不暴露 HTTP、TUI、MCP 管理 API、plugin install 命令。

### 4.2 Provider 契约

Provider adapter 对 application 暴露一个 port：

```text
stream(request: LlmRequest, cancel: CancellationToken) -> Stream<LlmEvent>
```

首个 adapter 仅支持 OpenAI-compatible streaming 子集。其它 provider 通过后续 provider plugin 安装。

### 4.3 Tool 契约

Tool registry 对 agent loop 暴露：

```text
list(agent: AgentProfile) -> Vec<ToolDefinition>
execute(call: ToolCall, context: ToolContext) -> ToolResult
```

M7/M9 内置工具：

- `read`
- `grep`
- `skill`
- `edit` 或 `write`
- `shell`

M8 通过 MCP Lite 注册命名空间化 MCP tool。

其它工具通过插件注册。

### 4.4 ContextPack 契约

M3 起 application 通过 `ContextPackBuilder` 生成 provider-neutral 上下文：

```text
build(workspace, session, agent) -> ContextPack
```

`ContextPack` 包含：

| Block | 来源 | 阶段 | 规则 |
|---|---|---|---|
| `environment` | workspace / runtime metadata | M3 | 不含 secret。 |
| `instruction` | `AGENTS.md` / `CONTEXT.md` | M3 | workspace 内读取，内容标记来源。 |
| `skill_index` | `.opencode/skill*/**/SKILL.md` frontmatter | M3 | 只列 name / description / location。 |
| `memory_snapshot` | session summary / last N turns / anchors | M3-M4 | 不含 secret，不做向量检索。 |
| `mcp_resource` | MCP resource read | M8 | 截断 + `<untrusted_input>`。 |

### 4.5 MCP Lite 契约

M8 只支持 local stdio：

```text
status() -> Map<McpServerName, McpStatus>
tools() -> Vec<ToolDefinition>
call(tool, args, context) -> ToolResult
resources() -> Vec<McpResourceRef>
read_resource(ref) -> ContextBlock
```

限制：

- 只允许配置驱动启动，不支持运行时 dynamic add。
- 只支持 local stdio，不支持 remote HTTP/SSE。
- 不支持 OAuth。
- MCP tool 名称必须带 server namespace。
- MCP 子进程必须有 timeout 和 shutdown。

### 4.6 Plugin Capability 契约

M6 只定义能力声明，不运行外部插件：

| Capability | 允许注册 | 不允许覆盖 |
|---|---|---|
| `provider_adapter` | provider endpoint/auth/stream 实现。 | secret 脱敏、trace、请求审计。 |
| `tool` | tool schema + executor。 | schema 重校验、workspace guard、permission。 |
| `prompt_asset` | system prompt / skill / command 资产。 | 外部内容不可信标记、ContextPack 顺序。 |
| `memory_source` | session summary、project memory、user memory。 | secret 脱敏、session schema、context budget。 |
| `mcp_server` | MCP server config source。 | MCP 隔离、timeout、permission。 |
| `event_subscriber` | 监听 session/tool/provider event。 | event schema 版本。 |
| `ui_extension` | TUI/Web/Desktop 插槽。 | application 用例和领域规则。 |

## 5. 关键不变量

1. 所有文件路径必须由 `WorkspaceRoot` 生成 `WorkspacePath`，不能直接用裸路径进入工具。
2. 所有 tool call 参数必须先按 JSON Schema 解码，再执行。
3. `write/edit/shell/network/dangerous` 权限必须经过 permission evaluator。
4. Session 只能通过应用用例追加 message/part，provider 和 tool 不能直接写 storage。
5. `LlmEvent` 是 provider 到 session 的唯一输入协议。
6. 外部内容进入 prompt 前必须截断并包裹 `<untrusted_input>`。
7. Secret 只允许来自 env / secret provider，不进入配置文件、prompt、日志、命令行。
8. 每次 run 必须有 `trace_id` 和 `session_id`。
9. Instruction、skill、memory、MCP resource 必须通过 `ContextPack` 进入模型上下文。
10. MCP tool 必须进入统一 `ToolRegistry`，不能直接调用 provider 或 session。
11. 插件只能注册能力，不能替换核心安全不变量。

## 6. 错误模型

| 错误 | 类型 | 触发 |
|---|---|---|
| `WorkspaceError` | 业务失败 | 路径越界、路径不存在、软链越界。 |
| `PermissionError` | 业务失败 | deny、ask 未获批准、审批超时。 |
| `ToolSchemaError` | 业务失败 | tool 参数不符合 schema。 |
| `ToolExecutionError` | 业务失败 / 基础设施 | 工具执行失败、timeout、输出超限。 |
| `ProviderError` | 基础设施 | provider 超时、限流、协议帧异常。 |
| `SessionError` | 业务失败 | session 不存在、run 已在进行、消息投影非法。 |
| `ConfigError` | 业务失败 | 配置缺字段、字段类型错误、secret 落入配置文件。 |
| `ContextPackError` | 业务失败 | instruction / skill / memory block 构造失败。 |
| `SkillError` | 业务失败 | skill frontmatter 非法、名称冲突、skill 不存在。 |
| `McpError` | 基础设施 / 业务失败 | MCP server 启动失败、协议失败、resource 不存在。 |

业务失败返回给 CLI 并记录 session event；基础设施失败记录 trace 后中止当前 turn。

## 7. 扩展点

后续功能安装路径：

- Provider：通过 `provider_adapter` capability 安装。
- Tool：通过 `tool` capability 安装。
- Skill：前期本地 workspace skill 走 ContextPack + skill tool；后续 skill source 通过 `prompt_asset` capability 安装。
- Memory：前期 session memory snapshot 走 ContextPack；长期记忆通过 `memory_source` capability 安装。
- MCP：前期 local stdio 走 `mcp_lite` 分层适配；后续 server source 通过 `mcp_server` capability 安装。
- TUI/Web/Desktop：消费 event + command API，不拥有领域规则。
- Formatter/LSP/Snapshot：作为 tool 后置增强或 workspace adapter。
- Command/Skill/Prompt：作为 prompt asset capability。
- Stats/Share/Sync：作为 event subscriber + storage adapter。

扩展点必须以稳定 port 注册，不允许插件拿到 domain 内部可变引用。

## 8. 阶段门禁

| 阶段 | 架构门禁 | 不允许跨越 |
|---|---|---|
| M1 | domain 类型和 projector 可独立测试；无 I/O 依赖。 | CLI、provider HTTP、storage、tool、plugin。 |
| M2 | CLI 只接 fake provider stream，application 编排可跑通。 | 真实 API key、真实配置、持久化。 |
| M3 | ContextPack 可由 instruction / skill index / memory snapshot 构造。 | 远程 skill、global skill、向量记忆、compaction agent。 |
| M4 | storage 只通过 `SessionRepository` port 进入 application。 | provider adapter 直接写库、复杂 migration。 |
| M5 | provider adapter 只输出 `LlmEvent`，不拥有 session 规则。 | 完整 provider catalog、OAuth、tool loop。 |
| M6 | 插件只注册 capability，核心安全不变量不可替换。 | 外部插件进程、动态安装。 |
| M7 | workspace read 和 skill tool 必须经 `WorkspaceRoot` / permission。 | write/shell、skill marketplace。 |
| M8 | MCP Lite 只通过 local stdio + ToolRegistry + ContextPack 暴露。 | remote HTTP/SSE、OAuth、dynamic add。 |
| M9 | write/shell 必须经 permission evaluator。 | TUI 审批、dangerous 自动放行。 |

3. JSON Schema crate 选型需单独 research。
4. Skill frontmatter parser、markdown parser 和目录扫描 crate 需单独 research。
5. MCP Rust crate、stdio transport 和子进程隔离方案需单独 research。
6. 插件运行时是 WASM、子进程 JSON-RPC 还是配置驱动，需单独 research。
7. M4 的临时 session repository 是否使用 JSON 文件，待实现前确认；正式 SQLite 仍需单独 research。
