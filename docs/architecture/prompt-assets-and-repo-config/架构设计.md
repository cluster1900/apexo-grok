# Prompt 资产与仓库配置架构设计

## 1. 职责与边界

本上下文负责上游 `.opencode/*`、repo-local agent/command/skill/tool/theme/glossary/TUI 配置、prompt 资产版本化、翻译词表和本仓库协作资产的加载规则。它覆盖 `.opencode/opencode.jsonc`、`.opencode/tui.json`、`.opencode/agent/*`、`.opencode/command/*`、`.opencode/skills/*`、`.opencode/tool/*`、`.opencode/themes/*`、`.opencode/glossary/*`。

不负责内置 tool 的执行逻辑，也不负责全局用户配置合并；这些分别属于 Tool Execution 和 Configuration。

## 2. 核心概念

| 概念 | 类型 | 说明 |
|---|---|---|
| `PromptAsset` | 聚合根 | 一个版本化 prompt、agent、command、skill 或 glossary 文件。 |
| `RepoLocalConfig` | 聚合根 | 某 workspace 内 `.opencode` 的配置集合。 |
| `AssetVersion` | 值对象 | prompt/skill/command 的语义版本或文件 hash。 |
| `CustomCommand` | 实体 | Markdown command 转为 session prompt 的入口。 |
| `CustomToolAsset` | 实体 | repo-local TS/JS tool 的声明和执行策略。 |
| `ThemeAsset` | 值对象 | TUI/WebJS 主题配置。 |

## 3. 模块拓扑

| 层 | 模块 | 依赖 |
|---|---|---|
| domain | `prompt_asset`、`repo_local_config`、`asset_version` | 建模资产来源、版本、权限和校验。 |
| application | `load_repo_assets`、`resolve_agent_profile`、`execute_custom_command`、`register_custom_tool` | 将资产接入 session/tool/plugin。 |
| infrastructure | filesystem、JSONC/Markdown parser、frontmatter、repo watcher | 读取 `.opencode` 并监听变化。 |
| interface | CLI/TUI/WebJS settings、prompt regression、docs tooling | 展示和测试入口。 |

## 4. 对外契约

- 所有 prompt 资产迁移到 `prompts/<scope>.<kind>.<version>.md` 或以 repo-local asset 方式加载；Rust 代码只引用路径和版本。
- `.opencode/agent/*.md` 和 `.opencode/command/*.md` 必须能生成兼容的 agent profile/custom command。
- `.opencode/skills/*/SKILL.md` 兼容 skill loader；外部内容进入模型前仍按不可信输入处理。
- `.opencode/tool/*.ts` 这类 repo-local tool 默认不受信，权限不高于 `ask`，并通过 plugin/tool sandbox adapter 执行。
- `glossary` 和 README locale 同步属于 docs/productization 资产，不进入 domain。

## 5. 关键不变量

- repo-local 资产只能从 workspace root 内规范化路径加载，禁止 symlink/path traversal 越界。
- prompt 版本变化必须触发 Prompt 回归报告。
- custom command 和 skill 中的外部内容不得直接拼入 system prompt；必须经过安全包装。
- 自定义 tool/theme/plugin 加载失败不得破坏核心 session 运行。

## 6. 错误模型

| 错误 | 类型 | 说明 |
|---|---|---|
| `AssetNotFound` | 业务错误 | 指定 agent/command/skill/theme 不存在。 |
| `AssetSchemaInvalid` | 业务错误 | JSONC/frontmatter/markdown schema 不合法。 |
| `AssetPathViolation` | 业务错误 | repo-local 资产路径越界。 |
| `PromptRegressionFailed` | 测试错误 | prompt 输出或快照不符合基线。 |
| `CustomToolLoadFailed` | 可恢复基础设施错误 | 自定义 tool 编译或加载失败。 |

## 7. 扩展点

- 新资产类型通过 `AssetLoader` 接入，不直接修改 session domain。
- Prompt regression 可以按 agent、tool、provider、locale 分组。
- 主题资产通过 TUI/WebJS adapter 消费，不影响 domain。

## 8. 未决问题

- `.opencode/tool/*.ts` 在 Rust 迁移中是保留 JS sandbox，还是改为 WASI/进程隔离，需要原型验证。
- prompt 文件的最终目录和版本命名要与 `AGENTS.md` 的 `prompts/<scope>.<kind>.<version>.md` 完全对齐。
- locale/glossary 是否迁入 docs pipeline，还是保留 upstream 结构，需要与 docs 站点设计一起确认。
