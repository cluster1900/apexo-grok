# Configuration 架构设计

## 1. 职责与边界

本上下文负责配置文件、默认值、env、CLI flag、remote config、MDM/managed config、plugin origin、依赖安装和旧字段迁移。不直接执行业务用例。

上游证据：`packages/opencode/src/config/config.ts` 与 `config/*.ts`。

## 2. 核心概念

| 类型 | 名称 | 说明 |
|---|---|---|
| 聚合根 | `ResolvedConfig` | 合并后的只读运行配置。 |
| 值对象 | `ConfigSource` | global/project/remote/env/cli/managed。 |
| 值对象 | `ConfigPath` | 配置文件路径，必须在允许位置。 |
| 值对象 | `SecretRef` | secret 引用，不存明文。 |
| 领域服务 | `ConfigResolver` | 加载、校验、合并、迁移。 |

## 3. 模块拓扑

| 层 | 模块 |
|---|---|
| domain | `config/schema.rs`、`source.rs`、`merge.rs` |
| application | `load_config.rs`、`update_config.rs`、`install_config_dependencies.rs` |
| infrastructure | `jsonc_loader.rs`、`remote_config_client.rs`、`npm_installer.rs`、`managed_config.rs` |
| interface | `/config`、`/global/config`、CLI flags、Desktop store bridge |

## 4. 对外契约

配置 schema 以 `packages/opencode/src/config/config.ts` 的 `Info` 为迁移基线，必须覆盖：

`$schema`、`shell`、`logLevel`、`server`、`command`、`skills`、`reference`、`watcher`、`snapshot`、`plugin`、`share/autoshare`、`autoupdate`、`enabled_providers/disabled_providers`、`model/small_model`、`default_agent`、`username`、`agent/mode`、`provider`、`mcp`、`formatter`、`lsp`、`instructions`、`permission`、`tools`、`attachment`、`enterprise`、`tool_output`、`compaction`、`experimental`。

## 5. 关键不变量

- 加载链：默认值 -> 配置文件 -> env `OPENCODE_*` -> CLI flag；后者覆盖前者。
- 反序列化错误必须包含字段路径和行号。
- 禁 `serde(default)` 掩盖必填；默认值显式写入 resolver。
- 旧 `tools` 字段迁移为 permission 规则，但 progress 中必须记录偏差。
- secret 字段只允许 env/secret manager。

## 6. 错误模型

| 错误 | 类型 | 场景 |
|---|---|---|
| `ConfigParseError` | application | JSONC/markdown/frontmatter 解析失败。 |
| `ConfigValidationError` | domain | schema 校验失败。 |
| `ConfigSourceUnavailable` | infrastructure | remote/managed config 读取失败。 |
| `DependencyInstallFailed` | infrastructure | plugin dependency 安装失败。 |

## 7. 扩展点

- 新配置字段必须先更新 schema、接口文档、迁移策略和测试矩阵。
- plugin/config hook 只能修改公开 config DTO，domain 只读取解析后的值对象。

## 8. 未决问题

- remote config 的鉴权和缓存 TTL 需在 deployment 文档补充。
