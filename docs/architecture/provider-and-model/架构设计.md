# Provider & Model 架构设计

## 1. 职责与边界

本上下文负责 Provider catalog、模型列表、能力/成本/限制/状态、认证、OAuth、provider 请求和 streaming 响应转换。不负责 prompt 业务决策、tool 执行、HTTP 路由。

上游证据：`packages/opencode/src/provider/`、`packages/core/src/provider.ts`、`packages/core/src/catalog.ts`、GitHub Copilot adapter。

## 2. 核心概念

| 类型 | 名称 | 说明 |
|---|---|---|
| 聚合根 | `ProviderCatalog` | 所有 provider 与 model 的合并视图。 |
| 实体 | `Provider` | id、name、auth methods、adapter、options。 |
| 实体 | `Model` | id、name、capabilities、limits、cost、status、variants。 |
| 值对象 | `ProviderID`、`ModelID` | 领域 ID，不用裸字符串。 |
| 值对象 | `ModelCapability` | attachment、reasoning、tool_call、modalities。 |
| 领域服务 | `ModelSelector` | 默认/小模型/variant 选择。 |
| 领域服务 | `ProviderAuthFlow` | env、API key、OAuth callback、logout。 |

## 3. 模块拓扑

| 层 | 模块 |
|---|---|
| domain | `provider/catalog.rs`、`model.rs`、`auth.rs`、`capability.rs` |
| application | `list_providers.rs`、`authorize_provider.rs`、`send_chat.rs`、`select_model.rs` |
| infrastructure | `providers/openai.rs`、`anthropic.rs`、`github_copilot.rs`、`openai_compatible.rs`、`models_dev_client.rs` |
| interface | `/provider*`、`/config/providers`、`models` CLI、SDK provider methods |

## 4. 对外契约

- HTTP：`provider.list`、`provider.auth`、`provider.oauth.authorize`、`provider.oauth.callback`。
- CLI：`providers list/login/logout`、`models [provider] --verbose --refresh`。
- Config：`provider.<id>.options/models`，字段见 `packages/opencode/src/config/provider.ts`。

## 5. 关键不变量

- Provider catalog 合并顺序必须保留：models.dev、config、env/auth、plugin hook。
- `enabled_providers` 存在时白名单优先；`disabled_providers`/blacklist 过滤不可用模型。
- secret 只从 env/secret store 读取，不写配置、日志和 prompt。
- streaming chunk timeout/header timeout/full timeout 都必须可配置。
- 模型不支持 tool_call 时不可暴露 tool schema。

## 6. 错误模型

| 错误 | 类型 | 场景 |
|---|---|---|
| `ProviderAuthError` | application | 凭据缺失、OAuth callback 失败。 |
| `ModelNotFound` | domain/application | provider/model 不存在或被过滤。 |
| `ProviderApiError` | infrastructure | HTTP status、rate limit、retryable。 |
| `StreamInterrupted` | infrastructure | SSE/stream 中断。 |

## 7. 扩展点

- 新 provider adapter 必须实现 `ChatProviderPort`，并登记 auth methods 和 model capability mapper。
- 插件 provider 通过 ACL adapter 注册，不能把 JS DTO 泄漏进 domain。
