# 云端 Console 与统计架构设计

## 1. 职责与边界

本上下文负责上游云端产品和运维统计入口：`packages/console/*`、`packages/stats/*`、`packages/enterprise/*`、`packages/function/*`、`infra/*`、`sst.config.ts`。它处理账号/API key/billing/usage/share/docs proxy、统计 ingest/lake、企业分享页、GitHub App/Worker API、监控和 secret/stage 配置。

不负责本地 agent loop 的领域不变量；本地 core 与云端只通过 SDK/HTTP、share/sync、telemetry 或显式 API 交互。

## 2. 核心概念

| 概念 | 类型 | 说明 |
|---|---|---|
| `CloudAccount` | 聚合根 | 云端账号、workspace、API key、billing 状态。 |
| `UsageReport` | 实体 | 模型、provider、token、cost、latency、geo 的统计事实。 |
| `SharedSessionView` | 聚合根 | 远端 share/storage/routes 暴露的会话视图。 |
| `DeploymentStage` | 值对象 | dev/staging/production 与资源命名策略。 |
| `CloudSecretRef` | 值对象 | secret manager 中的引用，不含 secret 明文。 |

## 3. 模块拓扑

| 层 | 模块 | 依赖 |
|---|---|---|
| domain | `account`、`usage`、`shared_view`、`stage` | 只建模云端业务事实和不变量。 |
| application | `sync_usage`、`publish_share`、`resolve_api_key`、`ingest_stats` | 编排本地事件与云端 API。 |
| infrastructure | SST、Cloudflare Worker、AWS lake/Athena、console DB、GitHub App API、Sentry/monitoring | 云资源和第三方 API adapter。 |
| interface | Console Web、Stats Web/API、Enterprise share route、Function API | 云端入口。 |

## 4. 对外契约

- Console/Stats/Enterprise 保留与本地 CLI/SDK 的认证、workspace、share、usage contract。
- `packages/function` 的 GitHub App/JWT/Worker API 作为外部集成 adapter，不能把云端 DTO 泄漏到 core domain。
- `infra/*` 中 console、enterprise、lake、monitoring、secret、stats、stage 的资源职责需要在 Rust 迁移部署文档中保留。
- telemetry 字段遵守 `docs/architecture/observability.md` 的 `trace_id/session_id/gen_ai.*` 约定。

## 5. 关键不变量

- 云端 share 链接不能绕过本地 share policy；禁用/取消分享必须最终一致地移除远端可访问视图。
- usage/cost 统计必须可追溯到 session、model、provider 和 trace。
- secret 只能以 `CloudSecretRef` 形式进入应用层，不进配置文件、prompt、日志。
- stats ingest 必须幂等，避免重放导致 usage/cost 翻倍。

## 6. 错误模型

| 错误 | 类型 | 说明 |
|---|---|---|
| `CloudAuthRequired` | 业务错误 | 需要登录或 API key。 |
| `SharePolicyDenied` | 业务错误 | 配置禁止 auto/manual share。 |
| `UsageIngestConflict` | 业务错误 | 同一 event 重复或 seq 不连续。 |
| `CloudServiceUnavailable` | 可重试基础设施错误 | 云端 API、lake、Worker 不可用。 |
| `SecretResolutionFailed` | 不可重试基础设施错误 | secret ref 缺失或权限错误。 |

## 7. 扩展点

- 云端功能通过 `CloudSyncPort`、`ShareRemotePort`、`UsageSinkPort` 接入 application。
- 本地离线模式下 cloud adapter 可被 noop implementation 替代，但事件要保留待重放。
- 新统计维度必须先扩展 schema 版本和 migration，再进入 ingest。

## 8. 未决问题

- Console/Stats/Enterprise 是否随 Rust 迁移同步重写，还是继续保留 TS/Solid/SST，需要按产品优先级决策。
- share-next 与 enterprise share 的边界需要实现阶段以源码再做一次字段级对照。
- Stats lake/Athena schema 需要补充独立数据设计文档。
