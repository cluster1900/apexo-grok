# Project & Workspace 架构设计

## 1. 职责与边界

本上下文负责 project 识别、workspace/worktree、VCS、文件列表/读取/搜索、watcher、LSP 状态和 workspace routing。不负责 session 消息持久化、tool schema、Desktop 窗口。

上游证据：`packages/opencode/src/project/`、`file/`、`lsp/`、`worktree/`、`control-plane/workspace.ts`。

## 2. 核心概念

| 类型 | 名称 | 说明 |
|---|---|---|
| 聚合根 | `Project` | id、worktree、vcs、name、icon、sandboxes、commands、initialized。 |
| 实体 | `Workspace` | type、name、branch、directory、project_id、adapter extra。 |
| 值对象 | `WorkspaceRoot` | 允许文件操作的根。 |
| 值对象 | `ProjectPath` | 规范化路径，必须落在边界内。 |
| 领域服务 | `ProjectResolver` | 从 directory/worktree 解析 project。 |
| 领域服务 | `VcsService` | status/diff/apply/initGit。 |
| 领域服务 | `FileExplorer` | list/read/find text/find file/find symbol。 |
| 领域服务 | `LspCoordinator` | LSP lifecycle、diagnostics、symbols。 |

## 4. 对外契约

HTTP 入参/出参见 [HTTP 清单](../../research/opencode-upstream-analysis/附件/http-api-inventory.generated.md) 中 `instance`、`file`、`project`、`workspace`、`experimental.worktree` 分组。

Workspace routing 兼容：

- query：`directory`、`workspace`。
- header：`x-opencode-directory`、`x-opencode-workspace`。

## 5. 关键不变量

- 所有路径先规范化再校验，越界返回 `WorkspaceViolation` 并写 trace。
- 非 git project 的 `worktree="/"` 不能当作全路径安全边界。
- `vcs.apply` 只允许干净状态或显式兼容上游 `not-clean` 错误。
- binary 非图片读取返回空内容；图片返回 base64 metadata。
- watcher 事件必须去抖并按 workspace/project 分发。

## 6. 错误模型

| 错误 | 类型 | 场景 |
|---|---|---|
| `ProjectNotFound` | application | directory 无法解析。 |
| `WorkspaceNotFound` | application | workspace id 不存在。 |
| `WorkspaceViolation` | domain | 路径越界。 |
| `VcsApplyError(non-git/not-clean)` | domain/application | patch 不能应用。 |
| `LspUnavailable` | infrastructure | LSP server 不可用。 |

## 7. 扩展点

- Workspace adapter 由 MCP/plugin/control-plane 注册，但转为 `Workspace` 领域实体。
- LSP server 配置由 config 注入，启动和进程管理在 infrastructure。
