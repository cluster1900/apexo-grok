# 部署与分发架构设计

## 1. 职责与边界

本上下文负责 opencode-rs 的构建、打包、安装、发布、CI 容器、Nix derivation、平台能力探测和运行时配置交付。它覆盖上游 `install`、`.github/workflows/*`、`script/*`、`nix/*`、`flake.nix`、`packages/containers/*`、`patches/*`、root `package.json` scripts。

不负责 agent 会话、tool 执行、provider 调用和 Web UI 交互；这些由其他上下文提供可打包产物和测试契约。

## 2. 核心概念

| 概念 | 类型 | 说明 |
|---|---|---|
| `ReleaseArtifact` | 值对象 | CLI、desktop、SDK、extension、container、Nix package 的发布物标识。 |
| `PlatformTarget` | 值对象 | OS、arch、libc、CPU baseline、desktop runtime 的组合。 |
| `InstallerPlan` | 聚合根 | 从版本、平台、安装目录、PATH 策略生成安装步骤。 |
| `BuildPipeline` | 实体 | CI workflow、container image、publish script、signing step 的组合。 |
| `DependencyPatch` | 值对象 | 上游 `patches/*` 对依赖行为的兼容性修正。 |

## 3. 模块拓扑

| 层 | 模块 | 依赖 |
|---|---|---|
| domain | `release`、`platform`、`installer` | 只建模 target、artifact、version、checksum、PATH policy。 |
| application | `build_release`、`install_binary`、`publish_artifact`、`verify_packaging` | 编排平台探测、checksum、签名、上传、rollback。 |
| infrastructure | GitHub Releases、GitHub Actions、Nix、Docker/Buildx、codesign/notary、S3/CDN | 所有外部命令参数化执行，secret 只来自 env/secret manager。 |
| interface | `install` shell、CLI `upgrade`/`version`、CI workflow、release scripts | 用户和 CI 的入口。 |

## 4. 对外契约

- 安装脚本兼容上游 `install`：`--version`、`--binary`、`--no-modify-path`、`VERSION` env、平台探测、musl 与 x64 baseline 处理。
- Nix 输出兼容上游 `flake.nix`：`opencode`、`opencode-desktop`、`node_modules_updater` 等产物语义。
- CI 容器兼容上游 `packages/containers`：`base`、`bun-node`、`rust`、`tauri-linux`、`publish`。
- 发布脚本需要覆盖 CLI、desktop、GitHub Action、VS Code、Zed 同步、docs/locale、stats/deploy workflow。
- 依赖 patch 必须逐项登记对应 Rust/JS 侧替代方案；不能静默丢弃。

## 5. 关键不变量

- 相同 `ReleaseArtifact` 的版本、checksum、平台 target 必须一致且可追溯。
- 安装脚本不得在未确认时覆盖用户自定义 PATH；`--no-modify-path` 必须完全禁止 shell rc 修改。
- secret 不进入 artifact、日志、命令行和配置文件。
- 发布必须可回滚；协议或存储 schema 变更必须引用 `docs/deployment/migration/`。

## 6. 错误模型

| 错误 | 类型 | 说明 |
|---|---|---|
| `UnsupportedPlatform` | 业务错误 | OS/arch/libc/CPU baseline 不支持。 |
| `ArtifactNotFound` | 业务错误 | 指定版本或平台产物不存在。 |
| `ChecksumMismatch` | 不可重试基础设施错误 | 下载内容与 manifest 不一致。 |
| `SigningFailed` | 可重试基础设施错误 | 平台签名/公证失败。 |
| `PublishConflict` | 业务错误 | 同版本已发布或 tag 状态冲突。 |

## 7. 扩展点

- 新增平台 target 时，只扩展 `PlatformTarget` 与 build pipeline，不改业务上下文。
- 新增包管理器时，实现新的 `ArtifactPublisher` adapter。
- CI 镜像可独立版本化；runtime 功能不得依赖 CI 镜像内隐含状态。

## 8. 未决问题

- Rust desktop 采用 Tauri、Electron sidecar 还是混合保留，需要单独 ADR。
- Windows 签名、公证和 baseline binary 的最终发布矩阵需实现阶段确认。
- 上游 JS dependency patch 哪些仍影响 WebJS/SDK，需要逐项补迁移表。
