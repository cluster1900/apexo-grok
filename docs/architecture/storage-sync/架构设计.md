# Storage & Sync 架构设计

## 1. 职责与边界

本上下文负责 SQLite schema、repository、JSON migration、event store、projector、sync replay/history/steal、share sync 和 event bridge。不负责业务聚合不变量本身。

上游证据：`packages/opencode/src/storage/`、`session/session.sql.ts`、`sync/index.ts`、`share/share-next.ts`、[SQLite 清单](../../research/opencode-upstream-analysis/附件/storage-schema.generated.md)。

## 2. 核心概念

| 类型 | 名称 | 说明 |
|---|---|---|
| 聚合根 | `SyncAggregateHistory` | aggregate_id、seq、events、owner。 |
| 实体 | `Projection` | session/project/workspace/account/share 等读模型。 |
| 值对象 | `EventID`、`AggregateID`、`Sequence` | event store 顺序保证。 |
| 领域服务 | `EventStore` | append/replay/history/claim/remove。 |
| 领域服务 | `ProjectorRunner` | 幂等投影到 SQLite 表。 |

## 3. 模块拓扑

| 层 | 模块 |
|---|---|
| domain | `sync_event.rs`、`aggregate_history.rs`、`migration_state.rs` |
| application | `replay_sync.rs`、`list_history.rs`、`run_projectors.rs`、`migrate_json.rs` |
| infrastructure | `sqlite_repository.rs`、`json_migration.rs`、`flock.rs` |
| interface | `/sync/*`、Desktop SQLite migration progress、`db` CLI |

## 4. 对外契约

- SQLite 表以 [SQLite 清单](../../research/opencode-upstream-analysis/附件/storage-schema.generated.md) 为规划基线。
- HTTP sync：`sync.start`、`sync.replay`、`sync.steal`、`sync.history.list`。
- CLI DB：`db [query] --format json|tsv`、`db path`、`db migrate`。

## 5. 关键不变量

- Event replay 必须同 aggregate 且 seq 连续；缺口/乱序返回 BadRequest。
- Projector 必须幂等，重复 replay 不产生重复读模型。
- JSON migration 与 SQLite migration 要可重入，有 `data_migration` 标记。
- share sync 的 secret/url 不写日志。
- Desktop migration progress 必须能回传 `{InProgress|Done}`。

## 6. 错误模型

| 错误 | 类型 | 场景 |
|---|---|---|
| `EventSequenceConflict` | domain/application | seq 不连续或 owner 冲突。 |
| `ProjectionFailed` | infrastructure | projector 写库失败。 |
| `MigrationFailed` | infrastructure | JSON/SQLite migration 失败。 |
| `StorageNotFound` | infrastructure/application | repository 查无数据。 |

## 7. 扩展点

- 新读模型表必须有迁移和回滚脚本，登记到 `docs/deployment/migration/`。
- 新 sync event 必须登记 schema version 和 projector。
