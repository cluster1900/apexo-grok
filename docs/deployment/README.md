# deployment/ 目录规范

存放 **构建、分发、运行环境、配置、迁移、回滚** 相关的文档与脚本说明。opencode-rs 主要形态是单二进制 CLI，但仍可能附带辅助进程（MCP server、daemon、容器化部署），本目录覆盖全部分发与运行场景。

## 1. 目录结构

```text
deployment/
├── README.md
├── build/                       ← 构建相关
│   ├── 本地构建.md
│   ├── 交叉编译.md               ← 多 target 支持时必有
│   └── 发布构建.md               ← release 流水线
├── distribution/                ← 分发渠道
│   ├── github-release.md
│   ├── homebrew.md              ← 如有
│   ├── cargo-install.md         ← 如发布到 crates.io
│   └── docker.md                ← 如发布镜像
├── runtime/                     ← 运行时环境
│   ├── 配置说明.md               ← 配置文件位置、字段、默认值
│   ├── 环境变量.md
│   ├── 数据目录.md               ← session / 缓存 / 日志路径
│   └── 系统依赖.md               ← git、bash、ripgrep 等运行期外部依赖
├── migration/                   ← 数据 / 配置迁移
│   └── <版本号>_<简述>.md
└── runbook/                     ← 应急手册
    ├── 升级.md
    ├── 回滚.md
    └── 故障排查.md
```

子目录按需创建，初期可以只放 `runtime/配置说明.md` 与 `build/本地构建.md`，其余等到对应能力出现再补。

## 2. 写作要求

### 2.1 通用要求

- 所有命令必须 **可复制运行**：含完整路径、版本号、环境变量；不要写 `cd 项目根目录`，写绝对相对路径假设。
- 出现版本号的位置必须明确是 **当前推荐** 还是 **最低支持**。
- 平台差异（macOS / Linux / Windows）显式分节，不混写。

### 2.2 配置说明.md 必含

- 配置文件查找顺序与最终路径（含 OS 差异、XDG 规范遵循情况）。
- 完整字段表：字段名 / 类型 / 默认值 / 含义 / 是否敏感（敏感字段必须标注）。
- 校验规则：必填、互斥、范围限制。
- 示例：最小可用配置、完整配置各一份。
- 与环境变量的优先级关系。

### 2.3 环境变量.md 必含

- 按前缀分类（`OPENCODE_*`、`RUST_LOG`、`HTTP(S)_PROXY` 等）。
- 每个变量：作用、默认值、是否敏感、生效时机（启动 / 热更）。

### 2.4 迁移文档（migration/）

任何不向后兼容的配置 / 持久化结构 / 协议变更必须出一份 `<版本号>_<简述>.md`：

- **影响面**：哪些用户 / 数据会被波及。
- **判断脚本**：用户怎么判断自己是否受影响。
- **迁移步骤**：手动 / 自动迁移命令。
- **回滚步骤**：迁移失败如何回到旧版本。
- **风险**：迁移过程中可能丢失的数据、需要的停机时间。

### 2.5 Runbook（runbook/）

应急用，要求 **5 分钟内能照着做**：

- 每个步骤是命令或检查点，不要长段文字。
- 每个步骤标注预期输出，便于判断是否成功。
- 失败分支必须给出"接下来怎么办"，不要断头。

## 3. 与其它目录的关系

| 目录 | 关系 |
|---|---|
| `architecture/` | 部署形态变化先改架构，再落到本目录 |
| `development/<feature>/数据设计.md` | 数据迁移脚本的源头 |
| `progress/` | 上线状态以本目录的发布说明为锚点 |
| `testing/` | 升级 / 回滚演练记录写入 `testing/`，本目录给步骤 |

## 4. 安全注意

- **禁止把任何 secret / token / 私钥** 写入本目录任何文件，包括示例配置中的占位也必须显式标 `<REPLACE-ME>` 而非真实样例。
- 涉及密钥管理的章节明确指向 **secret manager / 受控 env**，不要给出"复制到剪贴板"等不安全步骤。
- 发布流程中如有签名 / 公证（macOS notarization、Windows code signing），密钥获取方式只写"参见内部凭据库链接 X"，不写凭据本身。

## 5. 维护

- 分发渠道下线时直接删除对应文档，git 历史已经留痕。
- 当前已发布版本与下一个发布版本之间的迁移文档必须存在；更早版本的迁移文档可在确认无人需要从该版本升级后清理。
