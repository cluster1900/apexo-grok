# Storage、Sync 与 Share数据设计

## 1. 数据形态

- project/workspace/session/message/part/todo/account/share/event/data_migration。
- JSON migration files。
- outbox/projectors。

## 2. 生命周期

- startup migration -> repositories ready。
- event append validates seq and projectors idempotent。
- share/unshare keeps local and remote eventually consistent。

## 3. 索引与查询模式

- 以功能主聚合 ID 建索引；跨 project/workspace/session 的查询必须包含 workspace routing 或 aggregate id。
- 高频读路径需要 repository 方法和 contract test，禁止由 interface 层拼接 ad-hoc SQL 或文件路径。
- 缓存键必须包含配置来源、workspace root、schema version 或 asset hash，避免跨 workspace 污染。

## 4. 迁移脚本

- 新增表、字段、文件格式或 cassette/schema version 时，必须在 `docs/deployment/migration/` 记录 up/down、回滚步骤和校验命令。
- 只读兼容阶段不得破坏上游数据；写入新格式前必须提供 replay/diff 测试。

## 5. 保留兼容

- 保留上游已有数据语义和外部 contract；Rust 内部可以重建类型和值对象，但不能改变持久化语义。
- secret、token、credential 只保存引用，不保存明文。

## 6. SQLite 字段级基线 — 2026-05-27

| 表 | 字段基线 |
|---|---|
| project | id、worktree、vcs、name、icon_url、icon_url_override、icon_color、time_initialized、sandboxes、commands |
| workspace | id、type、name、branch、directory、extra、project_id、time_used |
| session | id、project_id、workspace_id、parent_id、slug、directory、path、title、version、share_url、summary fields、cost/tokens、revert、permission、agent、model |
| message / part | id、foreign ids、data JSON；session_message legacy 保留迁移路径 |
| todo | session_id、content、status、priority、position |
| permission | project_id、data |
| event_sequence / event | aggregate seq、owner、event type/data |
| account / account_state / control_account | token refs/state/legacy active account |
| session_share | session_id、id、secret、url |
| data_migration | name、time_completed |

Sync payload 必须保留 versionedType/aggregate seq/projector 幂等语义；sync.start/replay/history/steal 的 payload 和 response 以 HTTP inventory 为准。
