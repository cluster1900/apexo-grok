# minimum-agent 功能设计

## 1. 目标与非目标

### 目标

完整阶段拆分见 [`阶段拆分.md`](阶段拆分.md)。本功能按小里程碑推进：

| 阶段 | 目标 |
|---|---|
| M1 | 只做纯 domain kernel：Session、Message、Part、ModelRef、FinishReason、LlmEvent、SessionProjector。 |
| M2 | 增加 mock CLI run：`opencode run --mock "prompt"`，不调真实 provider。 |
| M3 | 增加 `ContextPack`：instruction loader、skill index、memory snapshot。 |
| M4 | 增加 session repository，保存 M2/M3 的 user/assistant/part/context metadata。 |
| M5 | 接入一个 OpenAI-compatible provider adapter。 |
| M6 | 定义 provider/tool/prompt/memory/mcp capability kernel，但不运行外部插件。 |
| M7 | 增加 workspace read tools 和精简 `skill` tool。 |
| M8 | 增加 local stdio MCP Lite：tool/resource bridge。 |
| M9 | 增加 `edit/write`、`shell` 和 allow/deny/ask permission。 |

### 非目标

- 不实现完整上游 CLI 命令矩阵。
- 不实现 TUI、Web、Desktop。
- 不实现 HTTP API、OpenAPI、SDK。
- 不实现完整 MCP runtime：remote HTTP/SSE、OAuth、dynamic add、MCP prompt 后置。
- 不实现完整 provider catalog。
- 不实现长期用户记忆库、embedding / vector memory。
- 不实现 share/sync/cloud/stats。
- 不实现完整 LSP/formatter/snapshot/revert。

## 2. 背景

调研依据：

- `docs/research/restart-2026-06-03.md`

上游 `opencode` 的核心是 Session 主循环、Provider 统一事件协议、Tool/Permission 门禁和 Plugin/MCP 扩展平台。重启后的 opencode-rs 不能再次提前拆出大量未验证模块，应先完成最小纵向闭环。

当前设计只支撑 M1 开工。M2-M9 的边界已写入设计，但每个阶段进入实现前必须再次确认前一阶段验收结果和对应调研是否齐备。

## 4. 用例编排

### 4.1 M1 `ProjectLlmEvents`

1. 创建 `Session`。
2. 在 `Session` 内开启一个 `Turn`，记录本轮 `trace_id`，状态置为 `running`。
3. 追加 user message（归属当前 `Turn`）。
4. 创建 assistant message（归属当前 `Turn`）。
5. 输入 fake `LlmEvent::TextDelta`。
6. `SessionProjector` 追加 text part。
7. 输入 `LlmEvent::Finished`。
8. `SessionProjector` 写 finish reason，并将当前 `Turn` 置为 `completed`。

M1 不解析 CLI，不连接 provider，不写 storage。M1 不投影 usage：`UsageDelta` 是 M5 事件，token 计数在 M5 才进入 part；M1 的 `Finished` payload 只有 `finish_reason`（见 [`../../architecture/events.md`](../../architecture/events.md)）。

### 4.2 M2 `RunPromptWithMockProvider`

1. CLI 解析 prompt、workspace、session、model。
2. Application 创建 `trace_id`。
3. 创建内存 session。
4. 追加 user message。
5. fake provider 返回 deterministic `LlmEvent` stream。
6. `SessionProjector` 生成 assistant message/part。
7. CLI 输出文本。

M2 不加载真实配置，不调真实 provider，不写磁盘。

### 4.3 M3 `BuildContextPack`

1. CLI/application 确认 workspace root。
2. `InstructionLoader` 读取 workspace root 下 `AGENTS.md` / `CONTEXT.md`。
3. `SkillIndexLoader` 扫描 `.opencode/skill/**/SKILL.md` 和 `.opencode/skills/**/SKILL.md`。
4. `MemorySnapshotBuilder` 从当前内存 session 构造 last N turns、facts、anchors。
5. `ContextPackBuilder` 生成 `ContextPack`。
6. M2 fake provider run 将 `ContextPack` 转成 system context。

M3 不加载完整 skill 正文，不做 skill tool，不访问 workspace 外路径，不写 memory 到磁盘。

### 4.4 M4 `PersistSession`

1. M3 步骤 1-6。
2. `SessionRepository` 保存 session/message/part/context metadata。
3. CLI 输出 session id。
4. 用户传 `--session` 时恢复历史。
5. 恢复后重建 `MemorySnapshot` 并进入下一轮 `ContextPack`。

### 4.5 M5 `RunPromptWithProvider`

1. CLI 解析 prompt、workspace、session、model。
2. Config loader 加载 provider/model/API key。
3. Application 创建 `trace_id`。
4. Session repository 创建或恢复 session。
5. 追加 user message。
6. Agent service 解析默认 `build` agent。
7. `ContextPackBuilder` 构造 system context。
8. Provider service 构造 `LlmRequest`。
9. Provider adapter 返回 `LlmEvent` stream。
10. Session projector 将 `text-delta` 写入 assistant part。
11. Provider `finish` 后写 usage 和 finish reason。
12. CLI 输出完整或流式文本。

### 4.6 M6 `RegisterCapability`

1. Capability manifest 被解析。
2. Capability 进入 registry。
3. Registry 校验 capability 类型和权限上限。
4. provider/tool/prompt/memory/mcp/event subscriber 注册到对应 port。
5. Application 运行时只通过 port 调用 capability。

### 4.7 M7 `RunReadAndSkillToolLoop`

1. M5 步骤 1-9。
2. Provider 发出 `tool-call`。
3. Tool registry 查找 tool definition。
4. Tool schema decode 参数。
5. `read` / `grep` / `skill` 按权限执行。
6. `skill` tool 按名称加载 `SkillDefinition` 正文。
7. Tool result 追加到下一轮 `LlmRequest`。
8. 循环直到 finish、max steps、用户取消、provider/tool 错误。

### 4.8 M8 `RunMcpLiteToolLoop`

1. Config loader 读取 local stdio MCP server。
2. `McpLiteGateway` 启动 enabled server 并记录 status。
3. `tools/list` 转换为命名空间化 `ToolDefinition`。
4. MCP tool call 进入统一 ToolRegistry 和 PermissionEvaluator。
5. MCP `resources/list` / `resources/read` 转为 `ContextBlock`。
6. MCP 输出截断并标记为 `<untrusted_input>`。

### 4.9 M9 `RunWriteShellLoop`

1. M7/M8 的 tool loop 基础上增加 `edit/write` 和 `shell`。
2. Permission evaluator 判定 allow/deny/ask。
3. ask 时 CLI 提示用户 once/always/reject。
4. Tool executor 执行工具。
5. 写入 tool running/completed/error part。
6. Tool result 追加到下一轮 `LlmRequest`。

## 5. 关键 crate / trait 边界

先不新增 crate。所有能力落在：

- `opencode-core`
- `opencode-cli`

`opencode-core` 内部允许定义 application ports，但不暴露空公共 API。各阶段 port 边界：

M1 不需要 trait，先用纯 domain 方法和 projector。ID 在 M1 一律由固定字符串经值对象 `TryFrom` 构造，domain 不铸造 ID、不读时钟（见 [`../../architecture/minimum-agent/架构设计.md`](../../architecture/minimum-agent/架构设计.md) §2.1）。

M2 需要：

- `ProviderStream` 的 fake 实现可以先是 application 内部结构，不提公共 API。
- `IdFactory` / `Clock` 端口：application 铸造 `SessionId` / `TurnId` / `MessageId` / `PartId`、缺失时铸造内部 `TraceId`，并读取 UTC 时间的唯一入口；外部传入 trace id 必须优先复用。底层 crate 选型是 M2 前置 research（见 §10）。

M3 需要：

- `ContextPackBuilder`
- `InstructionLoader`
- `SkillIndexLoader`
- `MemorySnapshotBuilder`

M4 需要：

- `SessionRepository`

M5 需要：

- `ProviderStream`
- `ConfigRepository`

M6 需要：

- `CapabilityRegistry`

M7 增加：

- `ToolRegistry`
- `WorkspaceFileSystem`
- `SkillRepository`

M8 增加：

- `McpGateway`

M9 增加：

- `PermissionGateway`
- `CommandRunner`

trait 只有在当前阶段存在真实调用方和真实实现时创建；未来插件需求不能单独作为创建 trait 的理由。

## 7. Agent 类功能附加设计

### 模型档位选择

M1/M2 使用 fake provider，不选择真实模型。M5 起默认使用 `standard` 档模型。`cheap` 仅用于后续 title/summary/compaction；`strong` 不在最小实现中自动选择。

### Tool 设计

| Tool | permission_level | idempotent | timeout | output_schema |
|---|---|---|---|---|
| `read` | `read` | true | 5s | text/file metadata |
| `grep` | `read` | true | 10s | matches |
| `skill` | `skill` | true | 5s | skill content + sampled file list |
| MCP tool | MCP server capability 声明 | 由 MCP schema 决定 | server timeout | text/json/resource |
| `edit/write` | `write` | false | 10s | diff summary |
| `shell` | `execute` | false | 默认 30s | stdout/stderr/exit code |

### Prompt 设计

- Prompt 资产放 `prompts/build.system.v1.md`。
- 代码只引用路径 + 版本。
- 文件、命令输出、工具返回进入模型前使用 `<untrusted_input>` 包裹。
- M1/M2 不需要真实 prompt 资产。
- M3 引入 `ContextPack`，包含 instruction、skill index、memory snapshot。
- M5 引入 `prompts/build.system.v1.md`。
- M7/M8 按 system / skill index / tool definitions / MCP resources / latest user turn 预留 cache 边界，但先不实现 provider-specific cache。

### 审批 / 权限

- `read` 默认 allow，`.env*` 默认 ask。
- `skill` 默认 ask，可对 skill name once/always。
- MCP tool 默认 ask，permission pattern 使用 `mcp:<server>:<tool>`。
- `write/edit` 默认 ask。
- `shell` 默认 ask。
- `network` 默认 deny，除非后续插件显式申请。
- `dangerous` 默认 deny。

### 停止条件

- M1：projector 收到 finish 即结束。
- M2：fake provider finish 或 fake provider error。
- M5：单轮 provider finish 或 provider error。
- M7/M8/M9：最多 10 个 agent step。
- 用户 Ctrl+C 触发 cancellation。
- 单 tool timeout 后该 tool call 失败，agent 可继续一轮自修正。
- Provider context overflow 先失败并记录事件，compaction 后置。
- MCP server timeout 后禁用当前 server，不影响其它 tool。

- `turn_id`
- `model.provider`
- `model.id`
- `tool.name`

### Eval 设计

M1：

- domain projector 单元测试，断言 session/message/part/finish。

M2：

- 5 条 mock text-only prompt，断言 CLI 输出和内存 session。

M3：

- 5 条 instruction / skill / memory context 组装用例，断言来源、顺序、不可信标记。

M7/M8/M9：

- 10 条 tool-use trajectory。
- 工具选择正确率初始门槛 70%。
- tool 参数 schema 通过率 100%。
- workspace 越界成功拦截率 100%。

## 9. 回滚方案

M1/M2 上线后若失败：

- CLI 保留旧的基线 status 输出作为 fallback。
- 新 session storage 如写入失败，不覆盖旧数据。
- Provider adapter 出错不自动重试写入工具动作。
- M7/M8/M9 tool 功能可通过配置关闭，仅保留 text-only。
