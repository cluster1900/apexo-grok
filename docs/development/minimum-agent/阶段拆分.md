# minimum-agent 阶段拆分

## 1. 拆分原则

最小实现不再使用“大 M1 = CLI + Session + Provider + Storage”的方式。每个阶段必须满足：

- 能在 1 个小 PR 内完成。
- 有明确输入和输出。
- 不依赖未调研的新 crate。
- 只引入当前阶段真实需要的 trait / 类型。
- 阶段结束后能用测试证明一个行为边界。

## 2. 阶段总览

| 阶段 | 名称 | 目标 | 不做 |
|---|---|---|---|
| M0 | 文档确认 | 人工确认本拆分和最小实现路线。 | 不写代码。 |
| M1 | Domain Kernel | 实现 Session / Message / Part / ModelRef / LlmEvent 等纯 domain 类型和 projector。 | 不做 CLI、Provider、Storage、Tool。 |
| M2 | Mock CLI Run | `opencode run --mock "prompt"` 通过 fake provider stream 输出文本。 | 不调真实模型、不持久化、不执行工具。 |
| M3 | Context Pack | 增加 instruction loader、skill index、memory snapshot 的精简版。 | 不做远程 skill、全局 skill、向量记忆、compaction agent。 |
| M4 | Session Store | 增加 session repository，保存 M2/M3 的 user/assistant/part/context metadata。 | 不做 SQLite 复杂迁移，不做真实 compaction。 |
| M5 | Provider Adapter | 接入一个 OpenAI-compatible streaming adapter，并使用 ContextPack 组装 prompt。 | 不做完整 provider catalog，不做 OAuth。 |
| M6 | Extension Kernel | 定义 provider/tool/prompt/memory/mcp capability schema 和注册校验。 | 不运行外部插件进程。 |
| M7 | Workspace Read + Skill Tool | 增加 `WorkspaceRoot`、`read`、`grep/glob`，并增加精简 `skill` tool。 | 不写文件、不执行 shell、不做 skill marketplace。 |
| M8 | MCP Lite Bridge | 增加 local stdio MCP：status、list tools、call tool、list/read resource。 | 不做 remote HTTP/SSE、OAuth、dynamic add。 |
| M9 | Write/Shell + Permission | 增加 `edit/write`、`shell`、allow/deny/ask。 | 不做 dangerous 自动放行，不做 TUI 审批。 |

## 3. 每阶段验收

### M1：Domain Kernel

交付：

- `SessionId`、`TurnId`、`MessageId`、`PartId`、`TraceId`（仅 `TryFrom<&str>` 校验 / 重建，含稳定 envelope；`TraceId` 允许外部 W3C trace id，不铸造新 ID）。
- `Session` 聚合根，含 `Turn` 状态转换（running → completed/failed/cancelled）。
- `Message` / `Part`。
- `ModelRef`（`provider/model[:variant]` 解析，见接口设计 §2.1）。
- `FinishReason` 值对象枚举（M1 取值 stop/length/error/cancelled）。
- 最小 `LlmRequest`（`trace_id + model + messages`）/ `LlmEvent`（`TextDelta` / `Finished` / `ProviderError`）。
- `SessionProjector`：把 text / finish / provider-error event 投影成 assistant message/part。

验收：

- `cargo test -p opencode-core domain::...` 通过。
- domain 不依赖 tokio、reqwest、sql、filesystem，**不铸造 ID、不读时钟**（测试用固定字符串构造 ID）。
- 测试覆盖：创建 session、开启 turn、追加 user、投影 text delta、finish reason、turn 收尾、非法状态拒绝。
- M1 不引入 ID crate；不实现 `IdFactory` / `Clock`（M2 引入）。

### M2：Mock CLI Run

前置 research：

- `IdFactory` 底层 crate（`uuid` v4/v7 vs `ulid`）与 `Clock` 选型完成并人工确认，归档 `docs/research/id-generation/`；M2 是第一个真实铸造 ID 的阶段。

交付：

- CLI 增加 `opencode run --mock "hello"`。
- `IdFactory` / `Clock` 端口 + 实现：application 铸造各类 ID 和读取 UTC 时间的唯一入口。
- fake provider 输出固定 `LlmEvent` stream。
- application 用例串起 prompt -> fake stream -> projector -> stdout。

验收：

- `opencode run --mock "hello"` 输出 deterministic 文本（fake stream 内容固定；ID/时间经端口注入，测试用确定性 fake `IdFactory`/`Clock`）。
- 不需要 API key。
- 不写磁盘。
- E2E 覆盖退出码 0 和 provider error 两种路径。

### M3：Context Pack

交付：

- `WorkspaceRoot` / context-only `WorkspacePath`：只服务 instruction / skill index / memory snapshot 的来源定位和 workspace containment。
- `ContextPack` / `ContextBlock`。
- `InstructionSource`：读取 workspace root 下 `AGENTS.md` / `CONTEXT.md`。
- `SkillIndex`：扫描 `.opencode/skill/**/SKILL.md` 和 `.opencode/skills/**/SKILL.md`。
- `MemorySnapshot`：保存 last N turns 摘要、关键文件引用和当前 session facts；M3 先在内存中构造。
- `ContextPackBuilder`：把 instruction、skill index、memory snapshot 拼成 provider-neutral system context。

验收：

- `opencode run --mock` 可带 ContextPack 运行。
- `AGENTS.md` / `CONTEXT.md` 读取只允许 workspace 内路径。
- skill frontmatter 缺失或非法时给 typed error，不污染 prompt。
- skill index 只列 name / description / location，不直接注入完整 skill 正文。
- MemorySnapshot 不写磁盘、不包含 secret。

说明：

- M3 是前期纳入 skills / memory 的最小版本，不实现 `skill` tool；`skill` tool 放 M7。
- `memory` 在 M3 不是长期用户记忆库，而是 session context 的轻量 snapshot。

### M4：Session Store

交付：

- `SessionRepository` port。
- 一个最小本地实现，保存 session/message/part/context metadata。
- CLI 输出 session id。
- 保存 `MemorySnapshot` / `ContextPack` 元数据，便于恢复时重建 prompt。

验收：

- 同一 session id 可恢复历史。
- 保存失败不破坏 CLI 输出。
- 数据不包含 secret。
- MemorySnapshot 恢复后可参与下一轮 ContextPack。

说明：

- SQLite 选型未完成前，可以先使用临时 JSON repository；一旦 SQLite research 确认，再迁移到正式 storage。

### M5：Provider Adapter

交付：

- Provider streaming crate research。
- OpenAI-compatible adapter。
- SSE/JSON frame -> `LlmEvent`。
- env API key 加载，secret 不落盘。

验收：

- mock fixture 覆盖 text delta / finish / provider error。
- 真实 provider 调用只作为手工验证，不进默认 CI。
- Provider adapter 不能直接写 session。

### M6：Extension Kernel

交付：

- capability manifest schema。
- provider/tool/prompt/memory/mcp capability 类型。
- capability 权限上限校验。
- registry 只保存声明和可用 port，不运行外部插件。

验收：

- 合法 manifest 可解析。
- provider/tool/prompt/memory/mcp capability 可注册到对应 port。
- 越权 capability 被拒绝。
- capability 不能覆盖 workspace guard、permission、secret redaction、session schema、ContextPack 不可信标记。

### M7：Workspace Read + Skill Tool

交付：

- 将 M3 的 `WorkspaceRoot` / `WorkspacePath` 扩展到 tool 入参、软链 containment 和敏感文件策略。
- `read` tool。
- `grep` 或 `glob` tool。
- `skill` tool：按 M3 的 SkillIndex 加载 `SKILL.md` 正文，并返回 `<skill_content>`。
- Tool result 进入下一轮 `LlmRequest`。

验收：

- 读取 workspace 内文件成功。
- 读取 workspace 外路径失败。
- `.env*` 默认 ask 或拒绝。
- tool output 被 `<untrusted_input>` 包裹后进入 prompt。
- `skill` tool 默认 ask，reject 不读取 skill 正文。
- skill 正文和相关文件列表都作为不可信内容进入上下文。

### M8：MCP Lite Bridge

交付：

- `McpServerConfig`：local stdio、enabled、timeout。
- `McpLiteGateway`：connect / disconnect / status。
- MCP `tools/list` -> `ToolDefinition`。
- MCP `tools/call` -> `ToolResult`。
- MCP `resources/list` / `resources/read` -> `ContextBlock`。

验收：

- disabled MCP 不连接。
- local stdio server 启动失败返回 `mcp.failed`，不阻塞主 run。
- MCP tool 名称必须命名空间化，避免覆盖 builtin/skill tool。
- MCP tool 调用必须经过 permission evaluator。
- MCP resource 内容必须被截断并包裹 `<untrusted_input>`。
- Ctrl+C / timeout 会关闭 MCP 子进程。

### M9：Write/Shell + Permission

交付：

- `PermissionRule` / `PermissionEvaluator`。
- CLI ask once/always/reject。
- `edit/write` tool。
- `shell` tool。

验收：

- write/shell 默认 ask。
- reject 不执行。
- always 只在当前 scope 生效。
- shell timeout 会生成 tool error。
- dangerous 命令不自动执行。

## 4. 第一段开发入口

第一段只做 M1。不要在 M1 提前写 CLI、Provider、SQLite、Tool、Plugin、Skill、MCP、Memory；这些能力已经分别落到 M2-M9，必须按阶段进入。

M1 推荐文件方向：

```text
crates/opencode-core/src/domain/session/
crates/opencode-core/src/domain/provider/
crates/opencode-core/src/domain/agent/
```

M1 完成后再评审 M2，不跨阶段提前实现。

## 5. phase / milestone 执行粒度

每个 milestone 至少拆成一个独立 PR；如果实现超过 1 个工作日或触碰两个以上上下文，必须继续拆小。

| 阶段 | PR 粒度 | 完成标志 |
|---|---|---|
| M0 | 文档确认 PR | 人工确认本阶段拆分、架构边界、测试计划。 |
| M1.1 | ID / 值对象 | `SessionId`、`TraceId`、`ModelRef`、`FinishReason` 等不变量测试通过。 |
| M1.2 | Session 聚合 | session / turn / message / part 状态转换测试通过。 |
| M1.3 | LlmEvent projector | `TextDelta`、`Finished`、`ProviderError` 投影测试通过。 |
| M2.0 | ID 生成 research | `IdFactory` 方案（复刻上游/ulid/uuid v7）+ `Clock` 选型确认并归档 `docs/research/id-generation/`。 |
| M2.1 | CLI mock 参数 | `opencode run --mock` 参数校验和错误码测试通过；`IdFactory`/`Clock` 端口接入。 |
| M2.2 | fake stream 编排 | fake provider -> projector -> stdout E2E 通过。 |
| M3.1 | Instruction loader | 最小 `WorkspaceRoot` + `AGENTS.md` / `CONTEXT.md` workspace-local 读取测试通过。 |
| M3.2 | Skill index | `.opencode/skill*` frontmatter 解析、非法 skill 拒绝测试通过。 |

## 6. milestone 级 Definition of Done

每个 milestone 完成时必须同时满足四件事：代码只覆盖本 milestone、对应 CIT 有实际执行记录、`progress/minimum-agent/功能现状.md` 回写状态、后续 milestone 的能力没有被提前实现。

| Milestone | 完成标准 | 必测 / 证据 | 文档回写 | 禁止越界 |
|---|---|---|---|---|
| M0 | 人工确认 research、architecture、development、testing 路线。 | `rg` 检查 M0-M9、ContextPack、Skill、MCP、Memory、CIT 对齐。 | `progress/overview.md` 和本功能进度标记“文档已确认 / 代码未开始”。 | 不写 Rust 代码，不新增 crate。 |
| M1.1 | ID / 值对象 newtype + `TryFrom` 校验落地，`ModelRef` / `FinishReason` 不用裸字符串表达语义。 | `CIT-0002`；空值、非法前缀、非法 body、外部 trace、非法 provider/model、非法 variant、未知 finish reason、合法 round-trip。 | 记录 M1.1 已完成、覆盖率和未完成项。 | 不创建 provider/storage/tool trait；不铸造 ID、不建 `IdFactory`/`Clock`。 |
| M1.2 | `Session` 聚合保护 turn/message/part 状态转换。 | `CIT-0001`；创建 session、追加 user、开始 assistant、非法状态拒绝。 | 回写聚合已完成和已知不变量。 | 不做 CLI 参数解析、不写磁盘。 |
| M1.3 | `SessionProjector` 可投影 `TextDelta`、`Finished`、`ProviderError`。 | `CIT-0001`；finish 后 delta 被拒绝，provider error 形成 error part。 | 回写 projector 行为和错误码。 | 不连接 fake/real provider。 |
