# minimum-agent 接口设计

## 1. 接口形态

M2 开始提供 mock CLI：

```bash
opencode run --mock <prompt> [options]
```

M5 开始提供真实 provider CLI：

```bash
opencode run <prompt> [options]
```

M7/M8 继续使用同一入口，增加 read / skill / MCP tool；M9 增加 write / shell 权限和工具开关。

不提供：

- HTTP API
- TUI API
- SDK
- MCP 管理 API
- plugin install API

## 2. CLI 请求 schema

| 字段 | 类型 | 必填 | 默认 | 校验 |
|---|---|---|---|---|
| `prompt` | string | 是 | 无 | 非空，最大长度由配置控制。 |
| `--workspace` | path | 否 | 当前目录 | M3 起必须生成 `WorkspaceRoot`。 |
| `--session` | string | 否 | 新建 | M4 起支持；必须匹配 `ses_` 前缀。 |
| `--model` | string | 否 | config 默认 | M5 起支持；格式见 §2.1 `ModelRef` 语法。 |
| `--agent` | string | 否 | `build` | M5 起支持；最小实现只允许 `build`。 |
| `--format` | enum | 否 | `text` | M2 起支持 `text`，预留 `json`。 |
| `--no-context` | bool | 否 | false | M3 起禁用 instruction / skill index / memory snapshot，用于调试。 |
| `--allow` | string[] | 否 | 空 | M7 起 skill/read/MCP 可用，M9 起 write/shell 可用。 |
| `--deny` | string[] | 否 | 空 | M7 起权限规则。 |
| `--ask` | string[] | 否 | 空 | M7 起权限规则。 |
| `--no-tools` | bool | 否 | false | M7 起禁用工具循环。 |
| `--no-mcp` | bool | 否 | false | M8 起禁用 MCP Lite。 |

### 2.1 ModelRef 语法

`ModelRef` 是值对象（`AGENTS.md §3.3` 禁止裸字符串），由 `TryFrom<&str>` 构造校验。文法：

```text
model_ref := provider "/" model [ ":" variant ]
provider  := segment
model     := segment
variant   := segment
segment   := 1*( ALPHA / DIGIT / "-" / "_" / "." )   ; 非空，不含空白、'/'、':'
```

- `provider` / `model` 必填且非空；`variant` 可选，用于区分同一模型的档位/能力（如 `:thinking`、`:fast`）。
- 示例：`openai/gpt-4o-mini`、`anthropic/claude-sonnet-4-6`、`openai/gpt-5:thinking`。
- 校验规则：恰好一个 `/`；至多一个 `:` 且必须在 `/` 之后；任一 segment 为空、含非法字符、含空白即拒绝并返回字段定位错误。
- M1 只做该值对象的解析 / 校验 / round-trip（`CIT-0002`），不绑定真实 provider 目录；真实模型可用性在 M5 由 config / provider adapter 校验。

### 2.2 ID / TraceId 语法

M1 的 ID 值对象只校验稳定 envelope，不绑定最终生成算法。M2.0 选定 `IdFactory` 主体方案后，若需要收紧 body 长度或排序规则，必须同步更新本节、`阶段拆分.md` 和 `CIT-0002`。

```text
entity_id := entity_prefix "_" id_body
entity_prefix := "ses" / "turn" / "msg" / "part" / "ctx" / "per"
id_body := 8*64( ALPHA / DIGIT / "-" / "_" / "." )

internal_trace_id := "trc_" id_body
external_trace_id := 32HEXDIG / traceparent
```

- `SessionId` / `TurnId` / `MessageId` / `PartId` 使用实体前缀；`ctx_` / `per_` 是 M4/M9 的存储辅助 ID。
- `TraceId` 优先复用外部传入值：允许 W3C trace id（32 hex）或 `traceparent` 头，经解析后保存 trace id；没有外部 trace 时才由 `IdFactory` 生成 `trc_` 内部 trace。
- M1 只测试 envelope、前缀、body 长度、body 字符集、外部 trace 解析；上游复刻 / `ulid` / `uuid` v7 的具体主体形态是 M2.0 research gate。

## 3. CLI 响应 schema

### 成功 text 输出

```text
<assistant text stream>
```

退出码：`0`。

### 失败输出

```text
error: <code>
detail: <human readable message>
session: <session_id if available>
trace: <trace_id>
```

退出码：非 `0`。

## 4. 内部 Provider 请求

### 4.1 LlmRequest（最终态）

下面是 `LlmRequest` 的**最终目标形态**，逐字段标注引入阶段。**禁止在早期阶段提前实现尚未到位的字段**（违反 `AGENTS.md §3.1 禁半成品 API`）。

```rust
struct LlmRequest {
    trace_id: TraceId,            // M1
    model: ModelRef,              // M1
    messages: Vec<LlmMessage>,    // M1
    context: ContextPack,         // M3
    system: Vec<PromptPart>,      // M5（prompts/build.system.v1.md）
    tools: Vec<ToolDefinition>,   // M7
    tool_choice: ToolChoice,      // M7
    generation: GenerationOptions,// M5
}
```

### 4.2 M1 最小 LlmRequest

M1 的 `LlmRequest` 只承载下列字段，不得包含 `context` / `system` / `tools` / `tool_choice` / `generation`：

```rust
struct LlmRequest {
    trace_id: TraceId,
    model: ModelRef,
    messages: Vec<LlmMessage>,
}
```

`context` 在 M3 加入，`system` / `generation` 在 M5 加入，`tools` / `tool_choice` 在 M7 加入。字段随阶段扩展时同步更新本节与 [`../../architecture/events.md`](../../architecture/events.md)。

### 4.3 LlmEvent

| 事件 | 字段 |
|---|---|
| `TextDelta` | `message_id?`, `text` |
| `ReasoningDelta` | `text` |
| `ToolCallDelta` | `tool_call_id`, `name?`, `arguments_delta` |
| `ToolCallFinished` | `tool_call_id`, `name`, `arguments_json` |
| `UsageDelta` | `input_tokens?`, `output_tokens?`, `cache_tokens?` |
| `Finished` | `finish_reason: FinishReason` |
| `ProviderError` | `code`, `message`, `retryable` |

M1 只实现 `TextDelta`、`Finished`、`ProviderError`；M5-M9 再按 [`../../architecture/events.md`](../../architecture/events.md) 打开其它事件。

### 4.4 FinishReason

`finish_reason` 是值对象（枚举），**禁止用裸 `String` 表达**（`AGENTS.md §3.3`）。反序列化未知值必须报错并定位字段，不得静默丢弃。

| 取值 | 引入阶段 | 含义 |
|---|---|---|
| `stop` | M1 | 模型正常结束。 |
| `length` | M1 | 触达输出长度上限。 |
| `error` | M1 | provider 报错结束（与 `ProviderError` 配合，turn 置 `failed`）。 |
| `cancelled` | M1 | 用户取消 / cancellation token 触发（M1 建模，M2 起真实触发）。 |
| `tool_calls` | M7 | 模型请求工具调用后让出。 |
| `content_filter` | M5 | provider 内容过滤结束。 |

M1 的投影只需识别 `stop` / `length` / `error` / `cancelled`；`tool_calls` 在 M7 进入 tool loop 时启用，`content_filter` 在 M5 provider adapter 接入时启用。

## 5. ContextPack 协议

```rust
struct ContextPack {
    trace_id: TraceId,
    session_id: SessionId,
    blocks: Vec<ContextBlock>,
    token_budget: TokenBudget,
}

struct ContextBlock {
    kind: ContextBlockKind,
    source: ContextSource,
    trust: TrustLevel,
    content: String,
}
```

`ContextBlockKind`：

| kind | 阶段 | 来源 |
|---|---|---|
| `environment` | M3 | workspace metadata。 |
| `instruction` | M3 | `AGENTS.md` / `CONTEXT.md`。 |
| `skill_index` | M3 | skill frontmatter。 |
| `memory_snapshot` | M3/M4 | session summary / last N turns / anchors。 |
| `mcp_resource` | M8 | MCP resource read。 |

除 `environment` 外，外部内容进入 provider 前必须保留 source，并按需要包裹 `<untrusted_input>`。

## 6. Skill 协议

```rust
struct SkillDefinition {
    name: SkillName,
    description: Option<String>,
    location: WorkspacePath,
    content: String,
}
```

M3 只使用 name / description / location 生成 skill index。M7 的 `skill` tool 才能加载完整 content。

## 7. Tool 协议

```rust
struct ToolDefinition {
    name: ToolName,
    description: String,
    input_schema: JsonSchema,
    permission_level: PermissionLevel,
    timeout_ms: u64,
}
```

MCP tool 进入 registry 前必须命名空间化：

```text
mcp:<server_name>:<tool_name>
```

Tool result：

```rust
enum ToolResult {
    Text { output: String },
    Json { value: serde_json::Value },
    Error { message: String },
}
```

## 8. MCP Lite 协议

M8 配置只支持 local stdio：

```rust
struct McpServerConfig {
    name: McpServerName,
    command: Vec<String>,
    enabled: bool,
    timeout_ms: u64,
}
```

状态：

```rust
enum McpStatus {
    Connected,
    Disabled,
    Failed { message: String },
}
```

MCP Lite port：

```rust
trait McpGateway {
    fn status(&self) -> HashMap<McpServerName, McpStatus>;
    fn tools(&self) -> Vec<ToolDefinition>;
    fn call_tool(&self, call: ToolCall, context: ToolContext) -> ToolResult;
    fn resources(&self) -> Vec<McpResourceRef>;
    fn read_resource(&self, resource: McpResourceRef) -> ContextBlock;
}
```

## 9. Permission 响应

M7 起 CLI ask 交互：

```text
  pattern: cargo test
  description: Run test suite

[o] once  [a] always  [r] reject
```

```rust
enum PermissionReply {

    Always,
    Reject,
}
```

## 10. 错误码

| 错误码 | 触发 |
|---|---|
| `config.invalid` | 配置解析或校验失败。 |
| `config.secret_in_file` | secret 出现在配置文件。 |
| `session.not_found` | 指定 session 不存在。 |
| `session.busy` | session 已有 run 在执行。 |
| `provider.unavailable` | provider 未配置或不可用。 |
| `provider.protocol` | provider stream 无法解析。 |
| `context.invalid` | ContextPack 构造失败。 |
| `instruction.invalid` | instruction 文件读取或解析失败。 |
| `skill.invalid` | skill frontmatter 或正文非法。 |
| `skill.not_found` | 请求加载的 skill 不存在。 |
| `workspace.outside_root` | 路径越界。 |
| `permission.denied` | 权限规则拒绝。 |
| `permission.rejected` | 用户拒绝 ask。 |
| `tool.invalid_args` | tool 参数 schema 失败。 |
| `tool.timeout` | tool 执行超时。 |
| `mcp.config_invalid` | MCP local stdio 配置非法。 |
| `mcp.failed` | MCP server 启动或协议失败。 |
| `mcp.resource_not_found` | MCP resource 不存在。 |

## 11. 兼容性

当前仓库还没有真实 CLI agent API；本设计不破坏既有客户端。

后续 HTTP/SDK 必须以本接口中的 domain DTO 为源，不允许单独发明另一套 session/message/tool schema。
