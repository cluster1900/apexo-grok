# Project、Workspace、VCS 与 File 开发设计

## 1. 目标与非目标

- 目标：迁移 project/workspace/worktree、VCS/git、file tree/content/status/search/watcher、repository reference 和 workspace adapters。
- 非目标：LSP 语义和 Web UI 文件树展示。

## 2. 背景

上游入口：`project/*`、`control-plane/*`、`worktree/*`、`git/*`、`file/*`、`reference/*`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `Project` | id、root、name、icon、init、worktree。 |
| `Workspace` | directory、adapter、status、time_used、routing key。 |
| `VcsState` | branch、diff、status、cleanliness、apply result。 |
| `FileNode` | path、content kind、status、watch event。 |

## 4. 用例编排

- project init -> resolve root -> detect git/worktree -> create workspace。
- file request -> workspace guard -> ignore/protected rules -> read/list/search/status。
- VCS apply -> assert clean/non-git policy -> apply patch -> publish file/project events。

## 5. 关键边界

- `WorkspaceResolver`、`WorkspaceGuard`、`VcsPort`、`FileSystemPort`、`RipgrepPort`、`ReferenceResolver`。

## 6. 错误模型

`ProjectNotFound`、`WorkspaceNotFound`、`WorkspaceViolation`、`FileNotFound`、`BinaryFileUnsupported`、`VcsNotClean`、`VcsApplyFailed`。

## 7. 测试与验收

- project/worktree migration、workspace routing、path traversal、ignore/protected、ripgrep、file watcher、git apply。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 Project / Workspace 字段

`Project.Info` 必须包含 `sandboxes: string[]`，用于限制可访问 sandbox path。workspace 需要作为 HTTP routing key，贯穿 instance store、session list、sync 和 control-plane；不得只用 directory 识别实例。

### 8.2 Worktree Start Command

创建 worktree 时可执行 project-level start command。该命令必须走 command execution permission、timeout、日志脱敏、失败可恢复和 UI 状态展示。

### 8.3 Icon Discovery

project icon 策略按优先级建模：`icon_url_override` > `icon_url` > `icon_color` / discovered icon。`experimentalIconDiscovery` 控制异步 discovery；结果需要缓存并发布 project update。

### 8.4 File Ignore / Protected

文件访问必须同时考虑硬编码默认忽略、`.gitignore`、`.ignore` 和 `file/protected.ts`。protected critical files 默认拒绝写入或要求更高权限；ignore 影响 list/search/watch，但不能掩盖显式用户指定文件的安全校验。

**注意**：上游使用 `.gitignore` + `.ignore`（不是 `.opencodeignore`），两者从 worktree 根目录读取后合并为 ignore 规则。

硬编码默认忽略（`file/ignore.ts`）：

| 类别 | 内容 |
|---|---|
| FOLDERS（32 项，路径段匹配） | `node_modules`、`bower_components`、`.pnpm-store`、`vendor`、`.npm`、`dist`、`build`、`out`、`.next`、`target`、`bin`、`obj`、`.git`、`.svn`、`.hg`、`.vscode`、`.idea`、`.turbo`、`.output`、`desktop`、`.sst`、`.cache`、`.webkit-cache`、`__pycache__`、`.pytest_cache`、`mypy_cache`、`.history`、`.gradle`。 |
| FILES（glob 模式） | `**/*.swp`、`**/*.swo`、`**/*.pyc`、`**/.DS_Store`、`**/Thumbs.db`、`**/logs/**`、`**/tmp/**`、`**/temp/**`、`**/*.log`、`**/coverage/**`、`**/.nyc_output/**`。 |

匹配算法：

- whitelist 优先：若路径匹配任一 whitelist pattern，直接返回不忽略。
- FOLDERS 按路径段匹配：将路径按 `/` 或 `\` 拆分为段，任一段在 FOLDERS Set 中即匹配（不是 glob，是 exact segment match）。
- FILES + extra 按 glob 匹配。
- `PATTERNS = [...FILES, ...FOLDERS]` 暴露给 watcher ignore 使用。

### 8.5 Ripgrep / Watcher / Reference Cache

`file/ripgrep.ts` 是独立快速文本搜索模块，Rust 版应封装为 port 并保留 include/exclude/limit/encoding 行为。

File Watcher 基线：

- 使用 `@parcel/watcher` 后端，backend 选择按平台 + arch + libc 动态加载。
- `SUBSCRIBE_TIMEOUT_MS = 10_000`：subscribe 超时后记录错误并 unsubscribe，不终止整个 watcher service。
- 事件类型映射：parcel `create` → bus event `add`、`update` → `change`、`delete` → `unlink`。
- ignore 列表合并：`FileIgnore.PATTERNS` + `config.watcher.ignore` + `Protected.paths(directory)`。
- `.git` 目录特殊订阅：当 project.vcs === "git" 且 `.git` 未被 config ignore 时，单独订阅 git dir（resolved via `git rev-parse --git-dir` + `realpath`），ignore 列表为 git dir 下除 `HEAD` 外的所有文件。这确保只监听 `HEAD` 变化（分支切换），不触发大量 pack/index 事件。
- `OPENCODE_EXPERIMENTAL_FILEWATCHER` flag 控制主目录 watch 是否开启；git dir watch 不受该 flag 约束。

`reference/reference.ts` 与 `repository-cache.ts` 负责外部 reference 解析、materialize 和缓存，尤其服务 experimental scout/repo overview。

### 8.6 BOM 处理

文件读写和 patch/apply_patch 必须保留 UTF-8 BOM 信息：读取时拆出 `{ bom, text }`，写回时按原状态恢复，避免对带 BOM 文件产生无意义 diff。

### 8.7 Workspace Adapter Runtime

control-plane workspace adapter 不能只实现 git worktree。上游当前内置 `worktree` adapter，但框架是可注册的 adapter runtime：

| 对象 | 字段 / 能力 |
|---|---|
| `WorkspaceInfo` | `id`、`type`、`name`、`branch?`、`directory?`、`extra?`、`projectID`。 |
| `WorkspaceAdapter` | `name`、`description`、`configure`、`create`、`list?`、`remove`、`target`。 |
| `Target.local` | 本地 directory。 |
| `Target.remote` | URL + optional headers。 |

adapter registry 需要支持内置 adapter、project-scoped custom adapter、`registerAdapter(projectID, type, adapter)`、`getAdapter()`、`listAdapters()` 和 `registeredAdapters()`。`workspace-adapter-runtime.ts` 会在 Instance/Workspace context 中包装 `target/configure/create/list/remove`，Rust 版应设计等价 application service，保证 adapter 生命周期、错误和 tracing 可统一处理。

### 8.8 Workspace ConnectionStatus

workspace 需要发布独立连接状态事件，状态枚举为 `connected`、`connecting`、`disconnected`、`error`，payload 至少包含 `workspaceID` 和 `status`。该事件服务 control-plane、Desktop/Web UI、多 instance 生命周期和 remote workspace 展示，不应被普通 file watcher 或 project update 事件替代。

### 8.9 Reference / Repository Cache 服务

`reference/reference.ts` 与 `reference/repository-cache.ts` 需要作为独立服务设计，不能只写“reference 解析”。

`Reference.Resolved` 三类型：

| kind | 字段 |
|---|---|
| `local` | `name`、`path`，path 支持绝对、相对 worktree/directory、`~/`。 |
| `git` | `name`、`repository`、`reference`、`path`、`branch?`；`path` 使用 repository cache path。 |
| `invalid` | `name`、`repository?`、`message`。 |

resolve 规则：

- git repository 必须是 git URL、host/path reference 或 GitHub owner/repo shorthand；`file:` 和无法解析的 repository 返回 invalid。
- 同一 cache path 的 git reference 去重；同 path 同 branch 允许，多 name 共享 materializer。
- 同 path 不同 branch 返回 invalid，并带 conflict message，指出冲突 alias、cache path 和双方 branch/default branch。
- Windows target/path 需要 normalize 后再做 contains 判断。

materialization 基线：

- `init()` 只在 `experimentalScout` true 时预拉取所有 git references，concurrency 4。
- `list()` 返回当前 instance 已解析的全部 `Resolved[]`。
- `get(name)` 按 alias/name 返回单个 resolved reference；prompt `@alias` 解析依赖该接口。
- `ensure(target?)` 在 `experimentalScout` false 时 no-op；无 target 时 materialize all；有 target 时只 materialize 包含该 target path 的 reference。
- `contains(target?)` 只在 scout 开启时判断 target 是否位于 git reference cache path 下。
- `RepositoryCache.ensure()` 使用 flock 锁 `repo-clone:<localPath>`；校验 branch；判断已有 `.git` 的 origin 是否同 repo，stale cache 先删除。
- cache 状态：`cloned`、`refreshed`、`cached`。clone 使用 depth 100；refresh 执行 fetch all/prune、必要时 checkout branch、reset 到 requested branch / origin HEAD / 当前 branch / HEAD。
- 错误类型需要区分 invalid repository、invalid branch、clone/fetch/checkout/reset failed、lock failed、cache filesystem operation failed。

### 8.10 File Type Classification

`file/index.ts` 使用三组硬编码扩展名集合和一组 extensionless 文件名集合来判定文件类型：

| 集合 | 用途 | 示例 |
|---|---|---|
| `binary`（~60 扩展名） | 判定为 binary 类型，不读取文本内容 | `exe`、`dll`、`so`、`dylib`、`zip`、`tar`、`gz`、`pdf`、`wasm`、`appimage` 等。 |
| `image`（~20 扩展名） | 判定为 image，读取为 base64 + mimeType | `png`、`jpg`、`jpeg`、`gif`、`bmp`、`webp`、`ico`、`svg`、`avif`、`heic` 等。 |
| `text`（~40 扩展名） | 强制判定为 text | `md`、`txt`、`json`、`yaml`、`toml`、`rs`、`ts`、`py`、`go` 等。 |
| `textName`（extensionless 文件名） | 无扩展名文件匹配文件名 | `dockerfile`、`makefile`、`.gitignore`、`.env`、`license` 等。 |

判定优先级：`isImageByExtension` → `isTextByExtension` / `isTextByName` → `isBinaryByExtension` → fallback 为 text。

`mime` map 为 image 扩展名提供 MIME type（png → `image/png`、jpg/jpeg → `image/jpeg`、gif → `image/gif`、webp → `image/webp`、svg → `image/svg+xml` 等）。

上游实际有两个独立 schema：

- `File.Info`：git status 相关 — `path`、`added`、`removed`、`status`。
- `File.Content`：文件读取结果 — `type: "text" | "binary"`、`content: string`、`diff?`、`patch?`、`encoding?: "base64"`、`mimeType?: string`。

Rust 版必须区分这两个类型，不要合并成一个 struct。

### 8.11 Git Adapter 默认配置

所有 git 命令调用前必须 prepend 固定配置参数，确保跨平台行为一致：

```
--no-optional-locks
-c core.autocrlf=false
-c core.fsmonitor=false
-c core.longpaths=true
-c core.symlinks=true
-c core.quotepath=false
```

| 参数 | 作用 |
|---|---|
| `--no-optional-locks` | 避免并发 git 操作时锁冲突。 |
| `core.autocrlf=false` | 禁用 CRLF 自动转换，保留文件原始换行符。 |
| `core.fsmonitor=false` | 禁用 fsmonitor 钩子，避免性能问题和副作用。 |
| `core.longpaths=true` | Windows 上允许超过 260 字符的路径。 |
| `core.symlinks=true` | 正确处理符号链接。 |
| `core.quotepath=false` | 非 ASCII 路径不做 octal 转义，保留原始 UTF-8。 |

Rust 版 Git adapter 必须在所有 `Command::new("git")` 调用中注入这些参数。
