# Desktop WebJS 与 Web UI数据设计

## 1. 数据形态

- desktop store。
- sidecar process state。
- renderer server/session/settings/local cache。
- terminal buffers。

## 2. 生命周期

- app start -> env/proxy/cert -> sidecar -> health -> renderer。
- renderer uses SDK/SSE/WS/preload。
- updater/deeplink/native API via main process。

## 3. 索引与查询模式

- 以功能主聚合 ID 建索引；跨 project/workspace/session 的查询必须包含 workspace routing 或 aggregate id。
- 高频读路径需要 repository 方法和 contract test，禁止由 interface 层拼接 ad-hoc SQL 或文件路径。
- 缓存键必须包含配置来源、workspace root、schema version 或 asset hash，避免跨 workspace 污染。

## 4. 迁移脚本

- 新增表、字段、文件格式或 cassette/schema version 时，必须在 `docs/deployment/migration/` 记录 up/down、回滚步骤和校验命令。
- 只读兼容阶段不得破坏上游数据；写入新格式前必须提供 replay/diff 测试。

## 5. 保留兼容

- 保留上游已有数据语义和外部 contract；Rust 内部可以重建类型和值对象，但不能改变持久化语义。
- secret、token、credential 只保存引用，不保存明文。

## 6. Desktop/WebJS State Keys — 2026-05-27

必须显式管理 electron-store and WebJS state：settings.v3、permission.v3、server list、terminal workspace cache、layout/page state、language storage、command catalog、deep-link queue、update/download state、zoom/titlebar/background state、provider dialog form state、file content cache/eviction accounting.

Store migration must be versioned; renderer-only cache can be rebuilt from SDK/SSE, but desktop store changes need rollback notes.
