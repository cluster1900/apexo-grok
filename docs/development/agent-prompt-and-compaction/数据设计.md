# Agent、Prompt 与 Compaction数据设计

## 1. 数据形态

- agent registry cache。
- prompt asset hash cache。
- summary message and compaction marker。

## 2. 生命周期

- agent registry 随 config/repo asset reload 更新。
- compaction 在上下文预算触发时生成 summary，不删除原始历史。
- prompt 版本变更必须触发 Prompt 回归记录。

## 3. 索引与查询模式

- 以功能主聚合 ID 建索引；跨 project/workspace/session 的查询必须包含 workspace routing 或 aggregate id。
- 高频读路径需要 repository 方法和 contract test，禁止由 interface 层拼接 ad-hoc SQL 或文件路径。
- 缓存键必须包含配置来源、workspace root、schema version 或 asset hash，避免跨 workspace 污染。

## 4. 迁移脚本

- 新增表、字段、文件格式或 cassette/schema version 时，必须在 `docs/deployment/migration/` 记录 up/down、回滚步骤和校验命令。
- 只读兼容阶段不得破坏上游数据；写入新格式前必须提供 replay/diff 测试。

## 5. 保留兼容

- 保留上游已有数据语义和外部 contract；Rust 内部可以重建类型和值对象，但不能改变持久化语义。
- secret、token、credential 只保存引用，不保存明文。
