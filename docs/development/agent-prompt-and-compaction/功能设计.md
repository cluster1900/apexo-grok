# Agent、Prompt 与 Compaction 开发设计

## 1. 目标与非目标

- 目标：迁移 agent profile、custom agent、subagent 权限、system prompt、instructions/reminders、summary/title/compaction。
- 非目标：具体 provider transport 和 Web UI 编辑器。

## 2. 背景

上游入口：`agent/agent.ts`、`agent/generate.txt`、`session/system.ts`、`summary.ts`、`compaction.ts`、`instruction.ts`、`reminders.ts`、`.opencode/agent/*`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `AgentProfile` | mode、prompt、tool allowlist、model tier、subagent policy。 |
| `PromptTemplateRef` | prompt 文件路径、版本、hash、scope。 |
| `CompactionPolicy` | context budget、reserved tokens、tail turns、summary model。 |

## 4. 用例编排

- 解析 config/repo-local agent -> 合并内置 agent -> 生成 session system prompt。
- 超预算 -> compaction policy 选取历史 -> summary prompt -> 写 summary message。
- subagent task -> 校验父 agent 权限 -> 建子 session 或 background runner。

## 5. 关键边界

- `AgentRegistry`、`PromptAssetStore`、`CompactionPlanner`、`SummaryProviderPort`。
- prompt 资产只能引用文件和版本，不能硬编码多行 prompt 到 Rust。

## 6. 错误模型

`AgentNotFound`、`PromptAssetInvalid`、`ContextBudgetExceeded`、`SummaryFailed`、`SubagentPermissionDenied`。

## 7. 测试与验收

- agent merge、custom agent、subagent permission、compaction threshold、summary/title regression。
- Prompt 快照与 `<untrusted_input>` 包裹断言。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 内置 Agent 列表

Rust 版内置 agent registry 必须逐项对齐上游，不允许只写“agent profile”：

| Agent | mode | hidden | temperature | 关键权限 / 用途 |
|---|---|---|---|---|
| `build` | `primary` | false | 未设置 | 默认实现模式，`question`、`plan_enter` allow，其余继承默认 permission + 用户配置。 |
| `plan` | `primary` | false | 未设置 | 规划模式，`question`、`plan_exit` allow，edit 默认 deny，但 `.opencode/plans/*.md` 和全局 plans 目录允许。 |
| `general` | `subagent` | false | 未设置 | 通用子任务 agent，`todowrite` deny，其余继承默认 permission + 用户配置。 |
| `explore` | `subagent` | false | 未设置 | 只读探索，`grep`、`glob`、`list`、`bash`、`webfetch`、`websearch`、`read` allow，其他默认 deny。 |
| `scout` | `subagent` | false | 未设置 | 实验性 agent，受 `experimentalScout` 控制，`repo_clone`、`repo_overview`、repo cache 外部目录 allow。 |
| `compaction` | `primary` | true | 未设置 | 历史压缩与摘要生成，`*` deny，不作为用户可选主 agent 展示。 |
| `title` | `primary` | true | `0.5` | session title 生成，`*` deny。 |
| `summary` | `primary` | true | 未设置 | session summary 生成，`*` deny。 |

`Agent.Info` 字段基线：`name`、`description?`、`mode`、`native?`、`hidden?`、`topP?`、`temperature?`、`color?`、`permission`、`model?`、`variant?`、`prompt?`、`options`、`steps?`。默认 permission 必须保留 `doom_loop: "ask"`。

默认 permission 矩阵：

| 层级 / Agent | 默认规则 |
|---|---|
| base defaults | `* = allow`、`doom_loop = ask`、`external_directory.* = ask`，截断文件目录/临时目录/skill 目录 allow；`question = deny`、`plan_enter = deny`、`plan_exit = deny`、`repo_clone = deny`、`repo_overview = deny`；`read.* = allow`，`.env` / `.env.*` ask，`.env.example` allow。 |
| user config | `cfg.permission` 与 agent 默认规则 merge，后写入者覆盖同一 permission/pattern。 |
| `build` | base + `question = allow`、`plan_enter = allow` + user config。 |
| `plan` | base + `question = allow`、`plan_exit = allow`、global plans 目录 external allow、`edit.* = deny`，但 `.opencode/plans/*.md` 和 global plans markdown allow + user config。 |
| `general` | base + `todowrite = deny` + user config。 |
| `explore` | base + `* = deny`，`grep`、`glob`、`list`、`bash`、`webfetch`、`websearch`、`read` allow，external directory 只读 allowlist + user config。 |
| `scout` | base + `* = deny`，`grep`、`glob`、`webfetch`、`websearch`、`read`、`repo_clone`、`repo_overview` allow，repo cache external allow + user config。 |
| `compaction` / `title` / `summary` | base + `* = deny` + user config；hidden agent 不进入普通用户选择。 |

### 8.2 动态 Agent 生成

必须保留 `Agent.generate()` 能力：通过 LLM 生成自定义 agent 的 `identifier`、`whenToUse`、`systemPrompt`，并在落盘前执行 identifier 规范化、prompt 安全校验、权限默认值注入和人工确认流程。

### 8.3 Per-model System Prompt 分发

`session/system.ts` 的 model prompt selector 必须作为显式策略：

- `gpt-4`、`o1`、`o3` 前缀 -> `beast`
- `gpt` 且包含 `codex` -> `codex`
- 其他 `gpt` -> `gpt`
- `gemini-` -> `gemini`
- `claude` -> `anthropic`
- `trinity` -> `trinity`
- `kimi` -> `kimi`
- 其他 -> `default`

### 8.4 Environment Context 注入

system prompt 必须注入并可测试：model id、working directory、workspace root、是否 git repository、platform、当天日期。所有外部文件和命令输出仍按项目规则包裹为 `<untrusted_input>`。

### 8.5 Reminders

`reminders.ts` 需要建模为 synthetic text part 注入机制：plan mode 下提示当前处于 planning；plan -> build 切换时注入切换 reminder；`experimentalPlanMode` 下还要处理 plan 文件相关 reminder。该内容影响 prompt snapshot，不得忽略。

### 8.6 Compaction 参数

压缩策略的数值基线：

- `PRUNE_MINIMUM = 20_000`
- `PRUNE_PROTECT = 40_000`
- `TOOL_OUTPUT_MAX_CHARS = 2_000`
- `DEFAULT_TAIL_TURNS = 2`
- `MIN_PRESERVE_RECENT_TOKENS = 2_000`
- `MAX_PRESERVE_RECENT_TOKENS = 8_000`

compaction 需要结合 `overflow.usable()`、tail turns、recent-token preserve budget 和 tool output 擦除策略，保证压缩后仍保留最近上下文和关键 tool call 结构。

### 8.7 Instruction 服务

`session/instruction.ts` 必须作为独立服务迁移，不能只并入 system prompt 字符串拼接。

职责基线：

- instruction 文件优先级：全局 `AGENTS.md`、可选 `~/.claude/CLAUDE.md`、项目内 `AGENTS.md` / `CLAUDE.md` / deprecated `CONTEXT.md`。
- `disableClaudeCodePrompt` 为 true 时不加载 `CLAUDE.md` 路径。
- project-level 搜索从当前 directory 向 worktree/root 祖先链查找，第一类命中优先，避免祖先目录多份指令无限叠加。
- `config.instructions` 支持绝对路径、相对路径、glob、`~/` 和 HTTP/HTTPS remote instruction；remote fetch 有 5 秒 timeout，失败返回空内容而不是阻断 prompt。
- `systemPaths()` 返回全局和配置 instruction 路径集合；`system()` 输出 `Instructions from: <path-or-url>` 包裹的系统指令块。
- `resolve(messages, filepath, messageID)` 在读取文件时沿文件父目录向上查找附近 instruction，并把内容作为附加上下文注入。
- 服务必须记录每个 assistant message 已 claim 的 instruction 文件，并结合历史 read tool metadata 中的 `loaded` 列表，避免同一 message 重复注入同一 instruction。

### 8.8 Agent Steps 与 Max-Steps Prompt

`Agent.Info.steps?` 不是展示字段，而是 agent loop 的最大 tool step 轮次控制。prompt loop 每轮比较当前 step 与 `agent.steps ?? Infinity`；达到上限时，必须注入 `prompt/max-steps.txt` 的 max-steps 提示，让模型停止继续调用工具并总结已有结果。

注入方式：max-steps 内容以 **`assistant` 角色 prefill** 追加到 messages 数组末尾（不是 user-role synthetic part），使模型将其视为自己的先前输出，从而无法继续发起 tool call。

验收要求：

- `steps` 未配置时不限制。
- 达到上限的那一轮必须走 deterministic prompt 注入，不能依赖 provider max token 或外层 timeout。
- max-steps 注入要进入 message/part transcript 和 prompt snapshot，便于回归测试比对。

### 8.9 Compaction 细节基线

compaction 不只是 summary 调用，必须拆出选择、prune、overflow replay 和 summary prompt 四类行为。

#### Prune

- `PRUNE_PROTECTED_TOOLS = ["skill"]`，skill tool 输出永远不被 prune。
- prune 只在 `config.compaction.prune` 为 true 时运行。
- 从最新消息倒序扫描，跳过最近 2 个 user turn。
- 遇到 `assistant.summary = true` 停止扫描。
- 只处理 completed tool part；跳过 protected tool；遇到已有 `state.time.compacted` 的 tool 后停止扫描。
- 累计 tool output token，`total <= PRUNE_PROTECT(40_000)` 时只保护不 prune。
- 超过 protect 后开始加入待 prune；只有累计待 prune token `> PRUNE_MINIMUM(20_000)` 才实际写 compacted 标记。

#### Tail 选择与 Preserve Budget

`preserveRecentBudget` 公式：

```text
config.compaction.preserve_recent_tokens
  ?? min(8_000, max(2_000, floor(usable_context * 0.25)))
```

`tail_turns` 默认 2。选择算法以 user turn 为单位，排除 compaction user turn；从最近 turn 倒序累加 token，超预算时尝试在 turn 内拆分，返回 `tail_start_id`。若没有可保留 tail 或 tail 从第一个消息开始，则不写 `tail_start_id`。

#### Overflow Compaction

overflow 触发的 compaction 需要排除导致溢出的 user message：

- 从 compaction parent 前向前找到最近的非 compaction user message作为 replay 候选。
- summary 上下文只取 replay 之前的消息，避免把超大输入送进 summary 模型。
- 若剩余上下文没有普通 user 内容，则取消 replay，回到普通 compaction。
- summary 成功后重新创建 user message 注入 replay parts；media file 会替换为文本 `[Attached <mime>: <filename>]`。
- 若 compaction 自身仍 overflow，写 `ContextOverflowError`；有 replay 时错误语义为“conversation history too large to compact”，无 replay 时为“session too large to compact”。

#### Summary Template

默认 summary prompt 必须输出固定 Markdown 结构，章节顺序不可变：

1. `Goal`
2. `Constraints & Preferences`
3. `Progress`，含 `Done`、`In Progress`、`Blocked`
4. `Key Decisions`
5. `Next Steps`
6. `Critical Context`
7. `Relevant Files`

规则：保留所有章节；使用短 bullet；保留准确路径、命令、错误字符串和标识符；不得提到 summary 或 context compacted 过程。插件 `experimental.session.compacting` 可追加 context 或完全替换 prompt；`experimental.compaction.autocontinue` 控制自动继续消息。

重复 compaction 需要 anchored previous summary：

- `completedCompactions()` 收集已完成的 compaction user message 及其 summary assistant；assistant 必须 `summary = true`、`finish` 存在、无 error。
- summary 文本来自该 assistant 的 text part，去空白后用双换行连接。
- 后续 compaction 会隐藏历史已完成 compaction 的 user/assistant pair，避免旧 summary 本身再次进入 summary 上下文。
- 若存在上一版 summary，prompt 前置 `<previous-summary>...</previous-summary>` anchor，并要求模型保留仍然正确的细节、删除过期细节、合并新事实。
- 若不存在上一版 summary，则使用“Create a new anchored summary...”路径。
