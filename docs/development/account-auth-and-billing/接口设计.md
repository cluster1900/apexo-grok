# Account、Auth 与 Billing接口设计

## 1. 接口形态

- Account repo/service。
- Provider/cloud auth API key/OAuth/login/logout。
- Console account/billing/usage exceeded status。
- Settings/connect-provider UI。

## 2. 请求 / 响应 schema

- Account: id、kind、profile、state。
- CredentialRef: source、secret ref、scopes。
- BillingState: plan、quota、usage exceeded。

## 3. 错误码

- AccountNotFound
- AuthMethodUnsupported
- CredentialMissing
- OAuthCallbackInvalid
- BillingBlocked

## 4. 兼容性

- 外部路径、operationId、CLI 参数、配置字段和事件名以调研附件与上游源码为基线，Rust 实现不得无迁移说明地改名。
- 新增字段必须显式版本化；删除字段必须先提供兼容层和 progress 记录。
- 所有外部输入进入 application 前必须 schema 校验；外部文本进入 prompt 前必须截断并包裹 `<untrusted_input>`。

## 5. 示例

- 成功：provider login 写入 CredentialRef 和 account_state.active_account_id，provider catalog refresh。
- 失败：billing blocked 状态映射为 BillingBlocked；logout 不存在账号返回 AccountNotFound。

## 6. Account/Auth Ownership — 2026-05-27

- provider-model-and-auth owns provider catalog and provider auth protocol behavior.
- account-auth-and-billing owns account、account_state、legacy control_account migration, active account/org, device-code polling state, console login/logout/switch/orgs/open, billing blocked/usage exceeded states.
- Control endpoint PUT/DELETE /auth/:providerID mutates credential refs and must publish provider/account refresh events without leaking secret values.
