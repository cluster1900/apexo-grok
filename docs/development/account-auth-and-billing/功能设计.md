# Account、Auth 与 Billing 开发设计

## 1. 目标与非目标

- 目标：迁移 account state、provider/cloud auth、API key、console account、billing/usage account 关联。
- 非目标：云端 billing UI 和支付系统重写。

## 2. 背景

上游入口：`account/*`、`auth/*`、`provider/auth.ts`、`packages/console/core/*`、`packages/app/src/components/dialog-connect-provider.tsx`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `Account` | id、provider/cloud kind、profile、state。 |
| `CredentialRef` | env/secret manager/local secure storage 引用。 |
| `AuthFlow` | OAuth/API key/manual login/logout/callback。 |
| `BillingState` | account quota、usage exceeded、plan/status。 |

## 4. 用例编排

- connect provider/cloud -> auth method -> credential secret ref -> account state。
- logout/remove -> revoke or remove secret ref -> catalog/settings refresh。
- usage exceeded -> provider/cloud status -> UI/CLI error mapping。

## 5. 关键边界

- `AccountRepository`、`CredentialStore`、`AuthFlowPort`、`BillingStatusPort`。

## 6. 错误模型

`AccountNotFound`、`AuthMethodUnsupported`、`CredentialMissing`、`OAuthCallbackInvalid`、`BillingBlocked`。

## 7. 测试与验收

- account repo/service、auth tests、provider auth, connect dialogs, usage exceeded behavior, secret redaction。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 Account Repo 绑定

`account/repo.ts` 负责 repo-level account 绑定：同一用户可能有全局 account、workspace/project/repo 绑定和 provider-specific credential。Rust 版需要在 account repository 中保留 source/scope/active org 信息，provider catalog refresh 要监听 account lifecycle。

### 8.2 Account URL 解析

`account/url.ts` 解析 account-specific URL 路由，影响 console workspace、Go settings、OAuth callback 和 provider connect dialog。URL parser 必须校验 host/path/query，避免把未信任 URL 直接写入 auth、retry action 或 UI open-link。
