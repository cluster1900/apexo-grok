# LSP、PTY 与 IDE 开发设计

## 1. 目标与非目标

- 目标：迁移 LSP lifecycle/diagnostics/symbols/hover/definition/references、PTY CRUD/ticket/WebSocket、IDE bridge、formatter/image helpers。
- 非目标：terminal UI 视觉层和 provider/tool 逻辑。

## 2. 背景

上游入口：`lsp/*`、`pty/*`、`ide/*`、`format/*`、`image/*`、`packages/app/src/context/terminal.tsx`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `LspServer` | language、command、status、diagnostics、capabilities。 |
| `PtySession` | shell、cwd、size、title、buffer、cursor、exit status。 |
| `PtyTicket` | 短期连接凭证和权限边界。 |
| `IdeContext` | editor selection、open files、diagnostics bridge。 |

## 4. 用例编排

- LSP launch -> config resolve -> spawn -> initialize -> diagnostics/project events。
- PTY create -> ticket -> WS connect -> replay buffer/cursor -> write/resize/output/remove。
- IDE attach -> validate path/range -> create external reference -> append prompt context。

## 5. 关键边界

- `LspClientPort`、`PtyBackend`、`PtyWebSocketGateway`、`IdeAdapter`、`FormatterPort`。

## 6. 错误模型

`LspLaunchFailed`、`LspUnsupportedLanguage`、`PtyNotFound`、`PtyTicketExpired`、`PtyWriteFailed`、`IdeContextInvalid`。

## 7. 测试与验收

- LSP launch/lifecycle/client、PTY output isolation/session/shell/ticket、WS replay、terminal URL。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 Formatter

`format/formatter.ts` 支持多 formatter：`gofmt`、`mix format`、`prettier`、`oxfmt`、`biome`、`zig fmt`、`clang-format`、`ktlint`、`ruff`、`black`、`rubocop`、`rubyfmt`、`erb-formatter`、`dart format`、`ocamlformat`、`terraform fmt`、`latexindent`、`gleam format`、`shfmt`、`nixfmt`、`rustfmt`、`php-cs-fixer`、`haskell-language-server-wrapper`、`cljfmt`、`dfmt` 等。启用条件要按 config 文件、package dependency、PATH/Npm.which、`experimentalOxfmt` 和 extension mapping 判断。

formatter resolution order：

| 阶段 | 规则 |
|---|---|
| 全局开关 | `cfg.formatter` falsy 时禁用全部 formatter；`true` 时启用全部内置 formatter 默认定义。 |
| 内置注册 | 从 `format/formatter.ts` 读取所有内置 formatter，按模块导出顺序放入 registry。 |
| 配置覆盖 | `cfg.formatter` 为对象时逐项处理：`disabled` 删除 formatter；自定义 formatter 与内置同名时 merge extensions/environment/command；无内置同名时作为自定义 formatter 加入。 |
| linked disable | `ruff` 与 `uv` 共享后端，任一配置 disabled 时同时删除两者。 |
| command 优先级 | 若配置提供 `command`，使用配置 command；否则使用内置 `enabled(context)` 探测。 |
| 探测上下文 | `enabled(context)` 收到 `directory`、`worktree`、`experimentalOxfmt`；可用 `Filesystem.findUp`、package dependency、config 文件、`which()`、`Npm.which()` 判断。 |
| 文件匹配 | 格式化单文件时按扩展名选出所有 matching formatter，并对每个 formatter 缓存 command 探测结果。 |
| 执行顺序 | 所有 enabled matching formatter 顺序执行，cwd 为 instance directory，`$FILE` 替换为目标路径，stdout/stderr ignore；spawn 失败或非 0 exit 只记录错误，不阻塞后续 formatter。 |

### 8.2 Image / Audio

`image/image.ts` 使用 `@silvia-odwyer/photon-node` / photon-wasm normalize 图片：默认 `MAX_BASE64_BYTES = 5 * 1024 * 1024`、`MAX_WIDTH = 2000`、`MAX_HEIGHT = 2000`、`AUTO_RESIZE = true`、`JPEG_QUALITIES = [80, 85, 70, 55, 40]`；按模型/配置限制自动 resize，必要时 JPEG 压缩，失败要返回可诊断错误。`audio.d.ts` 声明 `.wav`、`.mp3` 模块类型，Rust/WebJS 接口需要保留音频附件声明边界。

Image normalize 算法基线：

- 只接受 base64 data URL；否则返回 `ImageInvalidDataUrlError`。
- 读取 `config.attachment.image`，默认 `auto_resize=true`、`max_width=2000`、`max_height=2000`、`max_base64_bytes=5MB`。
- photon-wasm / photon-node 加载失败返回 `ImageResizerUnavailableError`。
- decode 失败返回 `ImageDecodeError`。
- 若原图宽高和 base64 bytes 都在限制内，原样返回。
- 若超限且 `auto_resize=false`，返回 `ImageSizeError`。
- resize 候选最多 32 个尺寸：首个尺寸按 `min(1, max_width/original_width, max_height/original_height)` 缩放并四舍五入；后续每步 `floor(prev * 0.75)`，宽高最低 1，重复尺寸跳过。
- 每个尺寸先尝试 PNG，再按 JPEG quality `[80, 85, 70, 55, 40]` 生成候选，选择第一个 base64 bytes <= 限制的候选。
- 全部候选失败时返回 `ImageSizeError`。
- processor 处理 tool-result image attachment 时：`ResizerUnavailableError` 静默 fallback 原附件；`SizeError` / `DecodeError` 等其他错误会 omit 该图片，并在 tool output 追加“图片因无法缩到限制内被省略”的警告文本。

### 8.3 PTY 字段与平台适配

PTY 包含 ticket、input、output、resize、close、session/window 关联等字段。上游有 `pty.bun.ts`、`pty.node.ts` 两套平台适配；Rust 版需要明确 Unix/Windows PTY backend、ticket TTL、WS 连接校验、输出隔离和 replay buffer。

### 8.4 LSP Language Mapping / Download

`lsp/server.ts` 中 language -> server binary/extension/config root 是大表：TypeScript、Vue、ESLint/OXC/Biome、Go、Ruby、Python、Elixir、Zig、C#、Swift、Rust、C/C++、Svelte、Astro、Java、Kotlin、YAML、Lua、PHP、Prisma、Dart、OCaml、Shell、Terraform、LaTeX、Dockerfile、Gleam、Clojure、Nix、Typst、Haskell、Julia 等都要进入映射 fixture。自动下载受 `disableLspDownload` 控制；关闭后只能使用本机已安装 binary。

LSP auto-download 三类策略：

| 策略 | 适用 | 机制 |
|---|---|---|
| GitHub Release Asset | Zig（zls）、Go（gopls）等 | 查询 `/repos/{owner}/{repo}/releases/latest` JSON → 按 platform/arch 选择 asset → 下载解压。 |
| ZIP fetch + build | ESLint、elixir-ls 等 | 下载 ZIP/tarball → 解压 → 运行 build/install 命令。 |
| PATH-only fallback | 大部分语言 | 不自动下载，仅在 `$PATH` 或 `Npm.which()` 中查找已安装 binary。 |

Rust 版需要为每种策略实现 download adapter，并在映射表中标注每个 language server 使用哪种策略。下载完成后 binary path 需要缓存，避免重复网络请求。
