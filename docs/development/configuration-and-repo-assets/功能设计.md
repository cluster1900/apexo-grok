# 配置与 Repo-local 资产开发设计

## 1. 目标与非目标

- 目标：迁移 JSONC config、加载链、managed/remote config、env/CLI 覆盖、formatter/LSP/MCP/provider/tool/permission 配置、`.opencode` 资产。
- 非目标：具体 tool/provider 执行逻辑。

## 2. 背景

上游入口：`config/*`、`.opencode/*`、`command/*`、`skill/*`、`packages/app/src/context/settings.tsx`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `ResolvedConfig` | defaults -> files -> env -> CLI 合并后的配置。 |
| `ConfigSource` | global/project/repo-local/managed/remote/env/CLI。 |
| `RepoLocalConfig` | `.opencode` agent/command/skill/tool/theme/glossary。 |
| `ConfigMigration` | legacy `autoshare/mode/tools` 等迁移规则。 |

## 4. 用例编排

- discover config paths -> parse JSONC/Markdown -> validate schema -> merge -> publish config event。
- repo asset load -> workspace guard -> hash/version -> register agent/command/skill/tool/theme。
- config change -> invalidate cache -> reload affected provider/tool/MCP/LSP without global restart。

## 5. 关键边界

- `ConfigLoader`、`ConfigValidator`、`RepoAssetLoader`、`SecretPolicy`、`ConfigMigrationRunner`。
- secret 字段只能来自 env/secret manager；配置文件中出现 secret 直接失败。

## 6. 错误模型

`ConfigParseError`、`ConfigSchemaError`、`SecretInConfig`、`RepoAssetInvalid`、`AssetPathViolation`、`ConfigMigrationFailed`。

## 7. 测试与验收

- JSONC parse、merge order、legacy migration、repo-local assets、path traversal、settings UI contract。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 Config 模块边界

配置功能至少覆盖 18 个核心子模块：`agent`、`attachment`、`command`、`formatter`、`layout`、`lsp`、`managed`、`mcp`、`model-id`、`parse`、`paths`、`permission`、`plugin`、`provider`、`reference`、`server`、`skills`、`variable`。当前上游目录还包含 `console-state`、`entry-name`、`error`、`markdown` 等支撑模块，迁移时应作为同一上下文的辅助能力记录。

`OPENCODE_DISABLE_PROJECT_CONFIG` 环境变量：设为 truthy 时跳过项目祖先链 `.opencode` 目录扫描，仅保留 global config。用于隔离调试或容器环境。

### 8.2 Remote / Managed Config

remote config 不只是 URL 字段。well-known config 可返回 `remote_config`，其中 `url` 和 `headers` 都要经过 `ConfigVariable.substitute()` 后再 fetch。header 变量可来自 account/auth 注入的 env map，不能落日志。

### 8.3 ConfigVariable 替换

必须支持：

- `{env:NAME}`：从传入 env 或 process env 取值；缺失按 `missing` 策略处理。
- `{file:path}`：相对配置文件目录或绝对路径读取文件内容；`~/` 展开到 home；注释行中的 token 不替换。
- `missing = "error" | "empty"`。

该能力被 opencode config、remote headers、TUI config、provider auth 等共同依赖。

### 8.4 Legacy Migration

必须覆盖 legacy global `config` TOML -> `config.json`，`provider + model` 迁移为 `model = "{provider}/{model}"`；server config 中 `tui` key 废弃并迁移到 `tui.json`；旧 theme/keybinds/thinking_visibility 等 TUI 状态需要 warn 或自动迁移。迁移要保留 backup/可回滚信息。

### 8.5 Console State / Env Service

`console-state.ts` 是云端 console 状态缓存的一部分，影响 settings/account/provider UI。另有独立 `env/index.ts` 服务，按 instance state 管理环境变量快照，提供 `get`、`set`、`remove`、`all`；config、auth、provider runtime 均不得直接散落读取可变 env。

### 8.6 ConfigMarkdown

`config/markdown.ts` 是 command、prompt、skill 共用的 Markdown 解析辅助模块，必须从 ConfigVariable 中拆开建模。

语法基线：

- file reference 使用 `@filepath`，匹配相对路径、带扩展名路径和点号路径；匹配结果进入 file part 或 loader dependency，后续必须走 workspace guard。
- shell substitution 使用反引号命令片段，形式为 ``!`command` ``；命中后由调用方执行 shell 并把输出替换进模板。
- `files(template)` 和 `shell(template)` 只负责解析匹配项，不直接执行 I/O；执行责任留给 command/prompt/skill loader。

Markdown frontmatter 使用 `gray-matter` 解析。遇到 Claude Code 风格或包含未转义 `:` 的非法 YAML 时，上游通过 `fallbackSanitization()` 只处理 frontmatter block：跳过注释/空行/缩进行，把带冒号的未引用值转换为 block scalar，再重试解析。最终仍失败时抛出包含 path 和 message 的 `ConfigFrontmatterError`。

### 8.7 Config.Info 顶层字段

Rust config schema 必须覆盖上游 `Config.Info` 顶层字段，不得只按模块名占位：

| 字段 | 类型 / 语义 |
|---|---|
| `$schema?` | JSON schema ref。 |
| `shell?` | terminal/bash tool 默认 shell。 |
| `logLevel?` | 日志级别。 |
| `server?` | serve/web server config。 |
| `command?` | slash command config map。 |
| `skills?` | additional skill folder paths。 |
| `reference?` | named git/local references。 |
| `watcher?` | `ignore? string[]`。 |
| `snapshot?` | 是否启用 snapshot tracking；false 时 undo/revert 不恢复文件变化。 |
| `plugin?` | plugin specs；`plugin_origins?` 是 derived state，不落持久配置。 |
| `share?` | `manual | auto | disabled`。 |
| `autoshare?` | deprecated，迁移到 `share`。 |
| `autoupdate?` | `boolean | "notify"`。 |
| `disabled_providers?` / `enabled_providers?` | provider allow/deny list。 |
| `model?` / `small_model?` | `provider/model` config model id。 |
| `default_agent?` | 默认 primary agent。 |
| `username?` | conversation username override。 |
| `mode?` | deprecated agent config，必须迁移到 `agent` 并设置 `mode = "primary"`。 |
| `agent?` | built-in 与 custom agent config map。 |
| `provider?` | custom provider/model overrides。 |
| `mcp?` | MCP server config 或 legacy `{ enabled: false }`。 |
| `formatter?` / `lsp?` | formatter / LSP enable 或 per-entry config。 |
| `instructions?` | instruction 文件、glob 或 URL 列表。 |
| `layout?` | deprecated。 |
| `permission?` | permission rules。 |
| `tools?` | legacy tool enable map。 |
| `attachment?` | attachment processing config，当前含 image config。 |
| `enterprise?` | enterprise URL。 |
| `tool_output?` | `max_lines?`、`max_bytes?` truncation thresholds。 |
| `compaction?` | `auto?`、`prune?`、`tail_turns?`、`preserve_recent_tokens?`、`reserved?`。 |
| `experimental?` | `disable_paste_summary?`、`batch_tool?`、`openTelemetry?`、`primary_tools?`、`continue_loop_on_deny?`、`mcp_timeout?`。 |

完整加载顺序（后覆盖前，managed 除外是 concat+override）：

1. 内置 defaults。
2. well-known remote config：fetch `{enterprise_url}/.well-known/opencode` → 读取 `remote_config.url`（经 `ConfigVariable.substitute()`）→ fetch 远端 JSON → merge as `"global"` scope。
3. managed directory 文件（`/Library/Application Support/opencode` 等，见 §8.8）。
4. global config files（`~/.config/opencode/config.json` 等）。
5. project config files（worktree 祖先链 `.opencode/config.json`）。
6. `OPENCODE_CONFIG_CONTENT` env var：若存在，作为 `"local"` scope 合并在 project files 之后。
7. CLI flags / env vars（`OPENCODE_*`）。
8. macOS MDM managed preferences（最高优先级覆盖，见 §8.8）。

merge 规则：普通对象 deep merge；`instructions` 是 concat + dedup，不是后写覆盖；legacy `provider + model` 迁移为 `model = "{provider}/{model}"`；legacy `mode` 迁移到 `agent`；`autoshare` 写入 `share`；旧 `disable_auto_compact` / `disable_auto_prune` 等键迁移到 `compaction.auto/prune`。

legacy `tools` 迁移规则必须保留：遍历 `tools` enable map，`true -> allow`、`false -> deny`；`write`、`edit`、`patch` 三个 legacy tool key 统一映射为 `permission.edit`，其他 key 映射为同名 permission。最终执行 `permission = mergeDeep(perms_from_tools, existing_permission)`，因此显式 `permission` 字段可覆盖 legacy tools 迁移结果。

image attachment config 基线：`attachment.image.auto_resize?`、`max_width?`、`max_height?`、`max_base64_bytes?`，默认分别为 true、2000、2000、5MB。

### 8.8 Managed Config / MDM

macOS MDM managed preferences 作为配置加载链的**最高优先级**覆盖，在所有其他来源之后合并。

系统级管理目录（`managedConfigDir()`）：

| 平台 | 路径 |
|---|---|
| macOS | `/Library/Application Support/opencode` |
| Windows | `%ProgramData%\opencode` |
| Linux / 其他 | `/etc/opencode` |

该目录下 `opencode.json` / `opencode.jsonc` 以 global 权限加载。

macOS managed plist 流程（仅 macOS 生效）：

- domain：`ai.opencode.managed`。
- 搜索路径顺序：`/Library/Managed Preferences/{username}/{domain}.plist` → `/Library/Managed Preferences/{domain}.plist`。
- 使用 `plutil -convert json -o -` 将 plist 转为 JSON。
- 解析时剔除 MDM payload 元数据 key：`PayloadDisplayName`、`PayloadIdentifier`、`PayloadType`、`PayloadUUID`、`PayloadVersion`、`_manualProfile`。
- 转换后的 JSON 作为最终配置层覆盖到 result（使用 `mergeConfigConcatArrays`，即 instructions 仍走 concat + dedup）。

测试可通过 `OPENCODE_TEST_MANAGED_CONFIG_DIR` 环境变量覆盖系统管理目录路径。Rust 版必须保留平台条件判断和 plist meta 过滤逻辑。
