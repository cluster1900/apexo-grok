# 可观测、Background 与事件总线开发设计

## 1. 目标与非目标

- 目标：迁移 bus、event-v2 bridge、server projectors、background jobs、Effect runtime flags 等可观测和异步运行基座。
- 非目标：每个业务事件的完整处理逻辑。

## 2. 背景

上游入口：`bus/*`、`event-v2-bridge.ts`、`server/projectors.ts`、`server/init-projectors.ts`、`background/*`、`effect/*`。

## 3. 领域模型

| 对象 | 说明 |
|---|---|
| `DomainEventEnvelope` | schema_version、trace_id、aggregate_id、occurred_at。 |
| `EventProjector` | 订阅事件并幂等更新 projection。 |
| `BackgroundJob` | long-running/cancellable task。 |
| `RuntimeFlag` | feature/runtime flags 和 instance state。 |

## 4. 用例编排

- domain fact -> event envelope -> bus publish -> SSE/projector/storage subscribers。
- background job -> cancellation token -> trace/span -> completion/error event。
- runtime flag/config change -> update instance state -> notify affected services。

## 5. 关键边界

- `EventBus`、`ProjectorRegistry`、`BackgroundJobRunner`、`TraceContextPropagator`、`RuntimeFlagStore`。

## 6. 错误模型

`EventSchemaInvalid`、`ProjectorFailed`、`JobCancelled`、`JobTimeout`、`TraceContextMissing`。

## 7. 测试与验收

- bus unit/integration、projector idempotency、background cancellation、trace fields、global/session SSE bridge。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 Bus Subscription 模型

Instance `Bus` 支持：

- `publish(def, properties, options?)`
- `subscribe(def)`：订阅单一 typed event。
- `subscribeAll()`：订阅 wildcard 全事件。
- `subscribeCallback(def, callback)` 与 `subscribeAllCallback(callback)`：callback 版本，返回 unsubscribe。

订阅是 eager acquire，避免 lazy stream 首次 pull 前丢事件。publish 同时写 typed pubsub 和 wildcard pubsub。

### 8.2 GlobalBus vs InstanceBus

`Bus` 是 instance-scope，持有 directory/project/workspace context。`GlobalBus` 是跨 instance 的 EventEmitter，payload 可补 `evt` ascending id，供 HTTP global event stream、多窗口、多 instance 生命周期使用。两者不能合并成单例。

### 8.3 Event V2 Bridge

`event-v2-bridge.ts` 是过渡层：core EventV2 是新的发布路径，但 opencode 旧 HTTP event stream 和 sync 仍依赖 legacy bus/sync payload。Bridge 将 versioned aggregate event 转成 SyncEvent，其他 event 转成 Bus/GlobalBus。文档和实现应标注该层可删除条件。

### 8.4 RuntimeFlags

当前上游 `RuntimeFlags.Info` 字段基线：`autoShare`、`pure`、`disableDefaultPlugins`、`disableChannelDb`、`disableEmbeddedWebUi`、`disableExternalSkills`、`disableLspDownload`、`skipMigrations`、`disableClaudeCodePrompt`、`disableClaudeCodeSkills`、`enableExa`、`enableParallel`、`enableExperimentalModels`、`enableQuestionTool`、`experimentalScout`、`experimentalBackgroundSubagents`、`experimentalLspTy`、`experimentalLspTool`、`experimentalOxfmt`、`experimentalPlanMode`、`experimentalEventSystem`、`experimentalWorkspaces`、`experimentalIconDiscovery`、`acpNext`、`outputTokenMax`、`bashDefaultTimeoutMs`、`experimentalNativeLlm`、`client`。实现必须保留 env 名称、默认值和 `OPENCODE_EXPERIMENTAL` 对 `enabledByExperimental` 的影响。

广播 env 别名：`OPENCODE_DISABLE_CLAUDE_CODE=true` 同时启用 `disableClaudeCodePrompt` 和 `disableClaudeCodeSkills`，实现时需要先读广播变量再读单独变量。

### 8.5 InstanceState

`InstanceState` 是上游 Effect runtime 的 per-instance 可变状态容器，不是事件总线。Rust 迁移需要有等价 scoped state management 方案。

能力基线：

- state 按 instance directory/workspace context 隔离，不能落成全局 mutable singleton。
- `make()` 创建带 disposer 的 state slot；`get()` 取当前 instance 下的 state。
- `context`、`workspaceID`、`directory` 暴露当前 Effect/runner 作用域信息。
- `use()` / `useEffect()` 临时绑定 instance context 执行任务，结束后恢复。
- `has()` / `invalidate()` 支持生命周期管理和测试清理。

底层实现使用 `ScopedCache` keyed by `directory`：`invalidate()` 通过 `ScopedCache.invalidate` 触发，并注册到 `registerDisposer` 确保 instance dispose 时自动清理。Rust 版对应设计应确保同一 directory 共享缓存条目，不同 directory 隔离，dispose 时按 directory key 回收。

该机制被 instruction、tool registry、env、provider、workspace runtime 等模块依赖；Rust 版可以用 typed context + scoped registry 实现，但必须保留 instance 隔离和清理语义。

### 8.6 EffectBridge 与 Runner

`effect/bridge.ts` 负责把 Effect world 暴露为 Promise/async 边界，并捕获当前 InstanceRef、WorkspaceRef/WorkspaceContext。Rust 版的等价层需要统一处理：

- 从外部 async 调用进入 application service 时绑定 instance/workspace context。
- fork long-running task 时继承 trace、runtime flags、cancellation 和 state context。
- `fromPromise`/外部 future 进入 runtime 时保留错误分类和 cancellation。

`effect/runner.ts` 是 session runner 生命周期核心，状态至少覆盖 `Idle`、`Running`、`Shell`、`ShellThenRun`。`startShell()` 可在 shell 执行时排队后续 run，`ensureRunning()` 防重复启动，`cancel()` 必须通知当前运行任务并在 UI/CLI 侧映射为 busy/cancelled 状态。该 runner 行为直接影响 prompt、shell prompt、permission resume 和 session busy 判定。

### 8.7 BackgroundJob Schema

`background/job.ts` 是 per-instance background job service，需要作为 application 层可观测对象迁移。

`BackgroundJob.Info` 字段：

| 字段 | 语义 |
|---|---|
| `id` | job id；未传时使用 ascending `job_` id。 |
| `type` | job 类型。 |
| `title?` | UI 展示标题。 |
| `status` | `running`、`completed`、`error`、`cancelled`。 |
| `started_at`、`completed_at?` | 毫秒时间戳。 |
| `output?` | 成功输出。 |
| `error?` | 失败文本。 |
| `metadata?` | 任意 metadata；session 级联 cancel 使用 `sessionId` / `parentSessionId`。 |

接口基线：

- `list()`：按 `started_at` 排序返回 snapshot。
- `get(id)`：返回 job snapshot 或 undefined。
- `start(input)`：`{ id?, type, title?, metadata?, run }`；同 id 且仍 running 时返回 existing，不启动第二个 fiber。
- `wait({ id, timeout? })`：无 timeout 等待完成；`timeout <= 0` 立即返回 running snapshot + `timedOut = true`；超时返回当前 snapshot。
- `cancel(id)`：running job 通过 fiber interrupt 取消，等待 fiber 结束后状态写为 `cancelled`；已完成 job 直接返回 snapshot。

状态转换：`running -> completed | error | cancelled`。run 成功写 `output`；非 interrupt 失败写 `error`；interrupt 写 `cancelled`。该服务依赖 `InstanceState`，不能跨 workspace 共享 mutable jobs map。
