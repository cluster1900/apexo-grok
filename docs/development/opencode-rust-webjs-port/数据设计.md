# opencode Rust + WebJS desktop 迁移数据设计

## 1. 数据形态

SQLite schema 以 [SQLite 存储表清单](../../research/opencode-upstream-analysis/附件/storage-schema.generated.md) 为迁移基线。

| 数据 | 表 | 生命周期 |
|---|---|---|
| Project | `project` | 打开项目时创建，icon/name/init/worktree 更新，删除暂不自动级联到磁盘。 |
| Workspace | `workspace` | workspace adapter/worktree 创建，remove 时删除记录。 |
| Session | `session` | create/fork/import 创建，update/share/revert/archive 更新，delete 级联 message/part/todo/share。 |
| Message | `message` | prompt/provider stream/tool 更新时创建/更新。 |
| Part | `part` | message part 创建/流式更新/完成/删除。 |
| Todo | `todo` | `todowrite` 或 session todo 更新时覆盖。 |
| Permission | `permission` | project 级 ruleset，配置迁移和用户审批更新。 |
| Account/Auth | `account`、`account_state`、legacy `control_account` | console/provider auth 保存和迁移。 |
| Share | `session_share` | share 创建，unshare/delete 清理。 |
| Sync | `event_sequence`、`event` | sync replay/history append，按 aggregate seq 管理。 |
| Migration | `data_migration` | 记录迁移完成状态。 |
| Release manifest | 文件型 release manifest + artifact checksum/signature manifest；若实现选择表化，必须新增 deployment migration | 记录 artifact、platform target、checksum、签名、发布时间。 |
| Integration dedupe | integration dedupe store，由 `external-integrations-github-slack-editors` 负责持久化或外部平台幂等确认 | 记录 GitHub/Slack/editor 事件去重 key 和回复状态。 |
| Cloud usage queue | local outbox，由 `cloud-console-stats-enterprise` 负责 schema 和 replay 语义 | 本地离线时缓存 usage/share sync，恢复后幂等上报。 |
| Prompt asset registry | 文件 hash cache + repo asset registry，由 `configuration-and-repo-assets` 负责 schema | 记录 `.opencode` 和 `prompts/` 资产版本、hash、加载错误。 |
| Recorder cassette | 文件系统 cassette | provider/HTTP/WS 录制回放数据，必须脱敏。 |

## 2. 内存结构

| 结构 | 用途 |
|---|---|
| Session runner map | 防止同 session 并发 prompt/tool。 |
| Permission pending map | 等待用户审批或自动规则。 |
| Question pending map | 等待用户回答。 |
| PTY registry | 活跃 PTY、buffer、cursor、WS clients。 |
| MCP registry | server status、transport、tools/resources/prompts。 |
| Plugin registry | loaded plugins、hooks、dispose handles。 |
| File watcher state | workspace changed paths debounce。 |
| Config cache | resolved config、source directories、dependency install fibers。 |
| Integration event cache | webhook/editor event dedupe、external reference resolve cache。 |
| Prompt asset cache | agent/command/skill/tool/theme/glossary 解析结果和 hash。 |
| Release manifest cache | artifact/platform metadata，避免重复下载 manifest。 |

## 3. 索引与查询模式

- session 按 `project_id`、`workspace_id`、`parent_id` 查询。
- message 按 `session_id,time_created,id` 查询。
- part 按 `message_id,id` 和 `session_id` 查询。
- todo 按 `(session_id, position)` 主键排序。
- sync event 按 `aggregate_id, seq` 查询增量历史。
- workspace 按 `project_id`、`time_used` 列表。
- integration dedupe 按 `(platform, external_event_id)` 查询幂等状态。
- prompt asset 按 `(workspace_root, asset_type, asset_name)` 查询 hash 和解析结果。
- release artifact 按 `(version, platform_target, artifact_kind)` 查询 checksum/signature。

## 4. 迁移脚本

首阶段不做破坏性 schema 变更，只做兼容读取和 JSON -> SQLite 迁移。后续每次新增/改表必须：

1. 在 `docs/deployment/migration/<date>-<name>.md` 记录 up/down。
2. 提供可回滚 SQL 或 Rust migration。
3. 补 `data_migration` 标记。
4. 在 Desktop sidecar 通过 migration progress 上报。

## 5. 保留兼容

- 保留 legacy `control_account` 迁移路径。
- 保留 session share secret/url 字段但日志脱敏。
- 保留 message/part JSON data 以兼容未完全结构化的新 part 类型。
- 保留 sync event data JSON，并通过 schema version 校验。
- 保留上游 provider/HTTP recorder cassette 的脱敏语义；格式是否直接兼容需实现阶段确认。
- 保留 `.opencode` repo-local 资产的文件结构兼容，但 Rust 内部 registry 可重新建模。
- 保留云端 share/usage/account 的外部 contract；本地存储可用 outbox/projection 重建。
