# CLI、HTTP、SDK 与 ACP 开发设计

## 1. 目标与非目标

- 目标：迁移 CLI 命令树、default TUI、run/serve/web/acp、HTTP/SSE/WS、OpenAPI public compatibility、JS SDK、ACP/ACP-next。
- 非目标：Desktop native API 和 Web UI 组件。

## 2. 背景

上游入口：`index.ts`、`cli/*`、`server/*`、`acp/*`、`acp-next/*`、`packages/sdk/js/*`。

## 3. 领域模型

| 对象 | 说明 |
|---|---|
| `CliInvocation` | command、flags、cwd、env、format、interactive mode。 |
| `HttpOperation` | method/path/params/query/body/success/error。 |
| `SseEvent` | session/global event stream frame。 |
| `AcpRequest` | editor/agent client protocol request。 |

## 4. 用例编排

- CLI parse -> bootstrap runtime/project -> execute command or TUI。
- HTTP request -> auth/CORS/workspace routing -> DTO validate -> application use case -> response。
- OpenAPI generate -> apply public compatibility patch -> JS SDK generation/diff。
- ACP stdio -> decode frame -> session/tool/provider intent -> event response。

## 5. 关键边界

- `CliCommandRegistry`、`OpenApiSchemaProvider`、`HttpRouter`、`SsePublisher`、`SdkCodegenRunner`、`AcpAdapter`。

## 6. 错误模型

`CliUsageError`、`HttpBadRequest`、`Unauthorized`、`OperationNotFound`、`SseDisconnected`、`SdkSchemaDrift`、`AcpFrameInvalid`。

## 7. 测试与验收

- CLI 33 command modules、HTTP 131 source endpoints、OpenAPI 131 operations、SDK error shape、ACP-next tests。

## 8. 上游细节基线（2026-05-27 回补）

### 8.2 CLI Run 模式

`run` 需要覆盖 streaming/text、JSON output、attach existing session、interactive mode、non-interactive prompt、permission footer 展示、question reply/reject、share flag、model/agent/variant 指定、恢复 pending permission 等场景。输出格式和 event ordering 需要 snapshot。

### 8.3 Server Middleware / Discovery

HTTP server 必须覆盖：

- `mdns.ts` 局域网服务发现。
- `proxy-util.ts` HTTP 代理处理。
- `global-lifecycle.ts` 全局生命周期和多 instance 协调。
- `cors.ts`：允许 localhost、127.0.0.1、`oc://renderer` 等来源策略。
- workspace routing middleware：通过 workspace key 路由到正确 instance。

HTTP API route groups（v2 + 特殊 group）：

| Group | 路由前缀 | 关键端点 |
|---|---|---|
| v2/session | `/api/session` | `GET /api/session`（列表）、`POST /api/session/:id/prompt`（发消息）、`POST /api/session/:id/compact`、`POST /api/session/:id/wait`、`GET /api/session/:id/context`。 |
| v2/message | `/api/session/:id/message` | session 的 v2 message 分页列表。 |
| v2/model | `/api/model` | 可用模型列表。 |
| v2/provider | `/api/provider` | provider 列表和 `GET /api/provider/:providerID` 详情。 |
| pty | `/pty` | `GET /pty/shells`、`GET /pty/list`、`POST /pty/create`、`GET /pty/:id`、`PUT /pty/:id`、`DELETE /pty/:id`、`POST /pty/connectToken`、`GET /pty/connect`（WebSocket）。 |
| sync | `/sync` | `POST /sync/start`、`POST /sync/replay`（payload: `ReplayEvent[]`）、`POST /sync/steal`、`POST /sync/history`（payload: `Record<aggregateID, knownSeq>`）。 |

v2 API 是 Desktop/Web UI 和 SDK 的主要消费路径，不能只实现 legacy v1 端点。Rust 实现必须为每个 v2 route group 落 OpenAPI schema 和 golden response 测试。

当前 HTTP API 还包含非 v2 的 instance route groups（均为活跃端点，非 deprecated）：

| Group | 路由前缀 | 关键端点 |
|---|---|---|
| config | `/config` | `GET`（读取）、`PATCH`（更新）、`GET /providers`。 |
| tui | `/tui` | `appendPrompt`、`openHelp`、`openSessions` 等 TUI 控制。 |
| permission | `/permission` | `list`、`reply`。 |
| file | `/file` | `findText`、`findFile`、`findSymbol`、`list`、`content`、`status`。 |
| mcp | `/mcp` | `status`、`add`、`auth/start`、`auth/callback`、`auth/authenticate`、`remove`、`connect`、`disconnect`。 |
| control | `/control` | `app.log`。 |
| experimental/workspace | `/experimental/workspace` | `adapters`、`list`、`create`、`warp` 等 workspace 管理。 |
| experimental | `/experimental` | `console`、`consoleOrgs`、`consoleSwitch`、`tool`、`toolIDs`、`worktree` CRUD、`session`、`resource`。 |
| v2/location | `/v2/location` | 地理/网络位置相关。 |

这些端点与 v2 route groups 共存于同一 HTTP server，Rust 版不能遗漏。

### 8.4 ACP-next

`acp-next` 子模块清单：`agent`、`session`、`tool`、`content`、`event`、`usage`、`directory`、`config-option`、`error`、`service`。Rust 版不能只声明“支持 ACP”，需要为每个模块落 schema、stdio frame、错误映射和 golden tests。

### 8.5 CLI Bootstrap

CLI bootstrap 不是简单 command dispatch。上游启动链路基线：

- 解析 cwd/directory 后加载 `InstanceRuntime`，并把 instance context 注入后续 command/server/TUI。
- 设置 `AGENT`、`OPENCODE`、`OPENCODE_PID` 等环境变量和 pure/logging/runtime 选项。
- 首次或升级后执行 JSON -> SQLite one-time migration；TTY 下展示进度，非 TTY 输出可解析的 migration progress 行。
- 注册 command tree 前完成 project discovery、server lifecycle、cleanup on exit 和 instance disposer。
- 退出时释放 global/instance lifecycle，避免残留 server、watcher、PTY 或 background job。

该流程需要独立 smoke tests：普通命令、默认 TUI、`run`、`serve`、migration 路径、Ctrl+C/SIGTERM cleanup。

### 8.6 Installation 服务

`installation/index.ts` 是 `upgrade` 命令背后的独立服务，不能只在 CLI 命令里写一次性脚本。

服务能力：

| 方法 | 语义 |
|---|---|
| `info()` | 返回当前版本和远端 latest。 |
| `method()` | 识别安装方式：`curl`、`npm`、`yarn`、`pnpm`、`bun`、`brew`、`scoop`、`choco`、`unknown`。 |
| `latest()` | 按安装方式查询 brew API、npm registry、Chocolatey、Scoop manifest 或 GitHub latest。 |
| `upgrade()` | 按安装方式执行 curl install、package manager install/upgrade、brew tap/pull/upgrade、choco/scoop upgrade。 |

事件基线：`installation.updated`、`installation.update-available`。错误基线：`UpgradeFailedError` 必须包含 method 和 detail，输出中脱敏路径和 token。`isPreview`、`isLocal`、`userAgent` 影响 latest/upgrade 行为，也要进入测试。

### 8.7 M1 Interface Foundation — 2026-05-28

调研结论见 `docs/research/m1-interface-foundation/调研报告_2026-05-28.md`。M1 先落下列最小闭环：

| 能力 | Rust 落位 | 验收 |
|---|---|---|
| HTTP router | `opencode_server::router()`，基于 `axum` | `GET /global/health` 返回 ready JSON；`GET /openapi.json` 返回 OpenAPI JSON。 |
| graceful shutdown | `opencode_server::serve(listener, CancellationToken)` | server runner 可由 CLI/Desktop sidecar 传入取消 token。 |
| OpenAPI seam | `opencode_server::openapi_document()` | 文档包含 `global.health` 与 `openapi.get` operation。 |
| SDK codegen seam | `opencode_server::generate_typescript_sdk()` | 从 OpenAPI 文档生成最小 `client.ts` 与 `index.ts`。 |

M1 明确不声称完成 CLI 33 command modules、HTTP 131 endpoints、SSE/WS、Basic Auth、workspace routing、ACP 或完整 JS SDK。上述范围必须在后续 endpoint contract diff 和真实 runtime PR 中补齐。
