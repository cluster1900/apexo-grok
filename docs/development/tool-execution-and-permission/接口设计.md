# Tool 执行与权限接口设计

## 1. 接口形态

- Provider tool-call schema: name、input、call_id。
- Tool result: title、output、metadata、attachments、truncated。
- Permission reply: payload.reply = once | always | reject；permission rule action 才使用 ask | allow | deny。
- 内置 tool: read/write/edit/apply_patch/shell/glob/grep/webfetch/websearch/task/todo/question/skill/lsp/repo_clone/repo_overview/plan。

## 2. 请求 / 响应 schema

- ToolDefinition: id、description、input_schema、permission_level、timeout、idempotent、output_schema。
- PermissionRequest: id、tool、input summary、patterns、risk level。
- ToolOutput metadata 必须携带 truncation 和附件路径时的 workspace 校验结果。

## 3. 错误码

- ToolNotFound=400
- ToolInputInvalid=400
- PermissionDenied=403/tool error
- WorkspaceViolation=403
- ToolTimeout=504
- PatchFailed=400

## 4. 兼容性

- 外部路径、operationId、CLI 参数、配置字段和事件名以调研附件与上游源码为基线，Rust 实现不得无迁移说明地改名。
- 新增字段必须显式版本化；删除字段必须先提供兼容层和 progress 记录。
- 所有外部输入进入 application 前必须 schema 校验；外部文本进入 prompt 前必须截断并包裹 `<untrusted_input>`。

## 5. 示例

- 成功：provider 请求 bash tool，经 permission.reply once 后执行，返回 title/output/metadata.truncated 并更新 tool part。
- 失败：permission.reply reject 返回模型可见拒绝信息；apply_patch patchText 空或语法错误返回 PatchFailed=400。

## 6. Tool 与 Permission Contract — 2026-05-27

### Built-in tool schema table

| tool id | 入参字段 | 关键输出/副作用 |
|---|---|---|
| apply_patch | patchText | freeform patch grammar；写文件前走 workspace guard 和 snapshot。 |
| edit | filePath、oldString、newString、replaceAll | 精确替换；oldString 不匹配返回业务错误。 |
| glob | pattern、path | 文件路径列表，受 ignore/protected 规则影响。 |
| grep | pattern、path、include | ripgrep match 列表和截断 metadata。 |
| invalid | tool、error | provider 调错 tool 时返回模型可见错误。 |
| lsp | operation、filePath、line、character、query | diagnostics/symbol/hover/definition/reference。 |
| plan_exit | 无 | 退出 plan mode 的 question/confirmation 语义。 |
| question | questions | 创建 pending question，等待 question.reply 或 question.reject。 |
| read | filePath、offset、limit | 文件内容、binary/image metadata、truncation。 |
| repo_clone | repository、refresh、branch | repository cache clone/fetch/reset。 |
| repo_overview | repository、path、depth | repository tree/overview。 |
| bash | command、timeout、workdir、description | 参数化 shell adapter、arity permission、stdout/stderr 截断。 |
| skill | name | 加载 skill context。 |
| task | description、prompt、subagent_type、task_id、command、background | foreground/background subagent。 |
| todowrite | todos | 覆盖 session todo。 |
| webfetch | url、format、timeout | network permission、HTML/markdown/text 输出。 |
| websearch | query、numResults、livecrawl、type、contextMaxCharacters | network permission、search result truncation。 |
| write | content、filePath | 写入新内容，必须 snapshot 和 workspace guard。 |

### Permission reply semantics

- permission.reply payload 的 reply 值是 once、always、reject。
- permission rule action 才是 ask、allow、deny；两者不得混淆。
- always 会把 request 中通过 arity/evaluate 推导出的 pattern 写入 allow 规则；reject 需要保留 feedback 给 tool part。
