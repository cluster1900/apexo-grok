- 目标：迁移 `packages/core` v2 schema/hook、`packages/llm` provider protocols、`http-recorder` cassette、scripts/codegen、`specs/*`。
- 非目标：把 Effect/Drizzle runtime 机械翻译为 Rust。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 ID 生成策略

`id/id.ts` 需要迁移为 shared kernel：支持 `ascending`、`descending` 和显式 `create(prefix, direction, timestamp?)`。prefix 基线包括 session、message、part、tool、event 等领域 id；ascending id 使用时间字节 + base62 随机尾部，支持从 ascending id 反解 timestamp。所有 Rust newtype id 必须校验 prefix。

完整 prefix map：

| 领域名 | wire prefix | 示例形态 | 约束 |
|---|---|---|---|
| job | `job_` | `job_<26 chars>` | background job id。 |
| event | `evt_` | `evt_<26 chars>` | Bus/EventV2/Sync event id；GlobalBus 缺 id 时补 ascending `evt_`。 |
| session | `ses_` | `ses_<26 chars>` | session aggregate id。 |
| message | `msg_` | `msg_<26 chars>` | user/assistant message id。 |
| permission | `per_` | `per_<26 chars>` | permission/question pending workflow 的 permission id。 |
| question | `que_` | `que_<26 chars>` | structured question id。 |
| part | `prt_` | `prt_<26 chars>` | message part id；注意不是 `part_`。 |
| pty | `pty_` | `pty_<26 chars>` | PTY session/ticket 关联 id。 |
| tool | `tool_` | `tool_<26 chars>` | tool call / truncation output file id。 |
| workspace | `wrk_` | `wrk_<26 chars>` | workspace routing 和 sync ownership id。 |

生成算法约束：`LENGTH = 26`，格式为 `{prefix}_{6 byte time+counter hex}{base62 random tail}`；6 byte 编码值为 `BigInt(timestamp_ms) * 0x1000 + counter`（高位为毫秒，低 12 bit 为同毫秒内计数器），同一毫秒内 counter 自增保证单进程单调；descending id 对 time bytes 取反。只有 ascending id 支持 `timestamp(id)` 反解：定位 6 byte hex 后将其解析为 BigInt 再 `/= 0x1000n` 得到毫秒时间戳。反解时根据第一个 `_` 前的 prefix 长度定位 6 byte hex。

### 8.2 Protocol / Recorder 归属

Provider 协议、HTTP recorder、OpenAPI schema 和 ID/错误类型属于 shared library 级 contract，不应散落在功能模块中。后续实现应由共享 crate 输出 schema/golden，再由 session/tool/provider/interface 功能消费。

### 8.3 Provider Transform

`provider/transform.ts` 属于协议 adapter 核心，不只是 provider SDK key 映射。Rust shared/protocol crate 需要集中实现并测试以下变换：

- message normalization：user/assistant/tool/result part 转 provider messages，按模型能力处理 tool result、reasoning、cache control 和 unsupported media。
- text/tool output sanitization：调用 `sanitizeSurrogates()` 清理孤立 UTF-16 surrogate，避免 provider JSON 序列化失败。
- `maxOutputTokens(model, outputTokenMax = OUTPUT_TOKEN_MAX)`：默认 `OUTPUT_TOKEN_MAX = 32_000`，最终值为模型 output limit 与配置上限的较小值；模型无 output limit 时使用配置上限。
- encrypted reasoning include：OpenAI 多轮 reasoning 状态需要带 `INCLUDE_ENCRYPTED_REASONING = ["reasoning.encrypted_content"]`，不能在消息转换中丢失。
- modality -> mime 映射：`image/*` -> image，`audio/*` -> audio，`video/*` -> video，`application/pdf` -> pdf；模型不支持的 modality 要转成可解释文本错误或拒绝。
- providerOptions namespace：结合 provider package 的 `sdkKey()`，把 dotted options 路由到 openai/anthropic/azure/gateway/openrouter/openaiCompatible 等正确命名空间。
- providerOptions special routing：Azure 必须同时写 `openai` 和 `azure`；Gateway 保留 `gateway` namespace，并把其他 options 路由到 upstream slug，`amazon/*` 特判为 `bedrock`；dot-split fallback **仅限** npm package 为 `@ai-sdk/openai-compatible`、`@ai-sdk/openai`、`@ai-sdk/anthropic` 三者之一时生效（按 provider id 的点号前缀映射），其他 npm package 使用 raw `model.providerID` 作为 key。

这些变换必须有 recorded/golden tests 覆盖，否则 provider 层很容易出现同一 session 在不同模型间行为不一致的问题。

### 8.4 Provider Schema Transform

`ProviderTransform.schema()` 是 tool/input JSON Schema 发给 provider 前的兼容层，需要与 message transform 放在同一 shared protocol contract。

Moonshot / Kimi 规则：

- 递归遍历 schema。
- 任意对象节点只要存在 `$ref`，只保留 `$ref`，移除同级 `description` 等 sibling keyword。
- tuple-style `items: [schema, ...]` 转成单一 `items` schema：取 `items[0]`；空数组时 `items = {}`。

Google / Gemini 规则：

- 递归遍历 schema。
- `enum` 内所有值转 string；如果节点原 `type` 是 `integer` 或 `number`，改成 `string`。
- object 节点的 `required` 只保留存在于 `properties` 的 key。
- array 节点无 combiner 且缺 `items` 时补 `{}`；若 `items` 不具备 schema intent，则补 `items.type = "string"`。
- 非 object 且无 `anyOf/oneOf/allOf` combiner 的节点，移除 `properties` 和 `required`，避免 Gemini 拒绝。

这些规则要用 schema golden tests 覆盖 `$ref` sibling、tuple items、number enum、invalid required、array items 缺失、non-object properties 六类 fixture。
