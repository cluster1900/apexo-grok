# MCP、Plugin 与 Skill 开发设计

## 1. 目标与非目标

- 目标：迁移 MCP local/remote transport、OAuth、tools/resources/prompts、plugin loader/hooks/custom provider/tool/TUI plugin、skill discovery。
- 非目标：每个内置 tool 的本地实现。

## 2. 背景

上游入口：`mcp/*`、`plugin/*`、`skill/*`、`packages/plugin/*`、`.opencode/skills/*`。

## 3. 领域模型

| 聚合/对象 | 说明 |
|---|---|
| `MCPServerConnection` | server name、transport、status、auth、tools/resources/prompts。 |
| `PluginRuntime` | origin、permissions、hooks、dispose、provided tools/providers。 |
| `SkillAsset` | SKILL.md、引用文件、metadata、scope。 |

## 4. 用例编排

- config server -> connect local/remote -> OAuth start/callback -> list tools/resources/prompts。
- plugin load -> validate manifest/origin -> register hooks/tools/providers -> isolate failures。
- skill discovery -> parse SKILL.md -> expose as tool/context asset。

## 5. 关键边界

- `McpTransport`、`McpOAuthStore`、`PluginHost`、`PluginHookDispatcher`、`SkillRegistry`。
- 外部 MCP/plugin 默认不受信，权限不高于 `ask`。

## 6. 错误模型

`McpServerNotFound`、`McpAuthRequired`、`McpFrameInvalid`、`PluginLoadFailed`、`PluginHookFailed`、`SkillInvalid`。

## 7. 测试与验收

- MCP lifecycle/OAuth/browser/callback/header、plugin loader/install/concurrency/workspace-adapter、skill discovery。

## 8. 上游细节基线（2026-05-27 回补）

### 8.1 内置 Provider Plugin

默认 internal plugin 列表必须覆盖：`codex`、`github-copilot`、`gitlab`、`poe`、`cloudflare-workers`、`cloudflare-ai-gateway`、`azure`、`digitalocean`、`xai`。`disableDefaultPlugins` 或 `pure` 模式会影响加载，plugin 来源需要记录 scope/source，便于诊断和卸载。

### 8.2 Plugin Install / Loader

`plugin/install.ts` 的流程需要迁移为显式状态机：解析 npm/file/http spec -> 拉取/读取 meta -> install package 或登记本地 loader -> 校验入口 -> 写 plugin metadata -> runtime loader 加载 -> onDispose 清理。`loader.ts`、`meta.ts`、`shared.ts` 的权限检查、路径解析、错误隔离和 dedupe 需要作为公共 utility，而不是分散在 CLI/TUI。

### 8.3 Skill 依赖文件

Skill 不只有 `SKILL.md`，loader 要解析 prompt 中引用的相邻文件和依赖资源，纳入 hash/version、路径越界校验、禁 secret 泄漏和 prompt snapshot。外部 skill 受 `disableExternalSkills`，Claude Code skill 受 `disableClaudeCodeSkills`。

### 8.4 MCP OAuth Callback

MCP OAuth 需要覆盖 `oauth-provider.ts` / `oauth-callback.ts` 的浏览器跳转流程：start auth -> 生成 callback URL/state -> 打开浏览器 -> 接收 redirect -> 校验 state/code -> 存 token -> reconnect/list tools。失败时必须能向 HTTP/CLI/UI 返回可操作错误。

### 8.5 MCP Prompt 转 Slash Command

MCP server 暴露的 prompts 可转换为内置 slash command。转换后的 command 仍要走 schema 校验、permission 上限、prompt untrusted 包裹和来源标记，不能绕过 command registry。

### 8.6 Plugin Hooks 清单

`packages/plugin/src/index.ts` 暴露的 hook 名称必须完整进入 Rust plugin boundary。hook 失败要隔离，dispose 失败只记录错误。

| Hook | 语义 |
|---|---|
| `dispose` | plugin unload/instance dispose 清理。 |
| `event` | 订阅 opencode event。 |
| `config` | 读取/调整 config。 |
| `tool` | 注册 plugin tool map。 |
| `auth` | provider auth hook。 |
| `provider` | provider/model 注入 hook。 |
| `chat.message` | 新 user message 到达后修改 message/parts。 |
| `chat.params` | 修改 temperature/topP/topK/maxOutputTokens/options。 |
| `chat.headers` | 修改 provider request headers。 |
| `permission.ask` | 修改 permission ask 输出状态。 |
| `command.execute.before` | slash command 执行前修改 parts。 |
| `tool.execute.before` | tool 执行前修改 args。 |
| `shell.env` | shell 执行前注入 env。 |
| `tool.execute.after` | tool 执行后修改 title/output/metadata。 |
| `tool.definition` | 修改发给 LLM 的 tool description/parameters。 |
| `experimental.chat.messages.transform` | provider 请求前修改 message history。 |
| `experimental.chat.system.transform` | provider 请求前修改 system prompt。 |
| `experimental.session.compacting` | compaction 前追加 context 或替换 prompt。 |
| `experimental.compaction.autocontinue` | compaction 成功后控制 synthetic continue 是否注入。 |
| `experimental.text.complete` | text part 完成时修改最终文本。 |

core v2 plugin 还包含 `catalog.transform`、`account.switched`、`aisdk.language`、`aisdk.sdk`、`agent.update`、`agent.remove`、`agent.default` 等 Effect hook。Rust 版若分 v1/v2 plugin API，需要明确兼容层和隔离策略。

### 8.7 MCP Transport 超时与 Tool 调用

MCP client 连接和 tool 调用的超时基线：

- `DEFAULT_TIMEOUT = 30_000ms`，作为 `listTools`、`callTool` 等所有 MCP RPC 调用的默认超时。
- 可通过 `experimental.mcp_timeout` config 字段覆盖；plugin / 单个 MCP server config 也可设置独立 timeout。
- `listTools` 超时时返回空 tool 列表并记录警告，不终止整个 MCP server 连接。
- `callTool` 超时时归类为 `ToolTimeout` 错误，进入 tool part error 状态。
- transport 连接自身（`connectTransport`）使用独立的 connect timeout 参数，与 RPC timeout 分开。

Tool name sanitization 与 registry key 规则：

- `sanitize(s) = s.replace(/[^a-zA-Z0-9_-]/g, "_")`——非字母数字下划线横线替换为 `_`。
- **tool** registry key：`sanitize(clientName) + "_" + sanitize(mcpTool.name)`（下划线分隔）。
- **resource/prompt** registry key：`sanitize(clientName) + ":" + sanitize(item.name)`（冒号分隔）。
- tool 与 resource/prompt 使用不同分隔符，Rust 版不能混淆。

`listTools` fallback：首次 list 失败且错误消息匹配 `outputSchema` 关键词时，使用容忍 schema（忽略 `outputSchema` 字段）重试一次。这兼容返回 `outputSchema` 的 MCP server。

Local transport 特殊处理：当 MCP command 字面值为 `"opencode"` 时，子进程环境注入 `BUN_BE_BUN: "1"`。

### 8.8 Skill Discovery 扩展

远程 skill URL 协议：

- fetch `{url}/index.json` → 解析 `{ skills: [{ name: string, files: string[] }] }`。
- 每个 skill 必须在 files 中包含 `SKILL.md`，否则跳过。
- 每个文件下载 URL 为 `{url}/{skill.name}/{file}`。
- 缓存位置：`Global.Path.cache/skills/{skill.name}/`。
- 并发：skill 级 concurrency = 4，文件级 concurrency = 8。
- `disableExternalSkills` 控制远程 skill 拉取。

内置 skill：`customize-opencode` 在磁盘扫描前预注册，用户 skill 同名时可覆盖。

### 8.9 Internal Plugin 完整列表

上游 `INTERNAL_PLUGINS` 实际包含：`codex`、`github-copilot`、`gitlab`、`poe`、`cloudflare-workers`、`cloudflare-ai-gateway`、`azure`、`digitalocean`、`xai`。`disableDefaultPlugins` 或 `pure` 模式跳过这些内置 plugin 加载。
