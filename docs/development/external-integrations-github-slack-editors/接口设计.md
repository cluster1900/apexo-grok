# 外部集成：GitHub、Slack 与编辑器接口设计

## 1. 接口形态

- GitHub Action action.yml inputs/env and event payloads。
- Slack events/commands。
- VS Code commands/keybindings/file reference。
- Zed extension manifest/sync。

## 2. 请求 / 响应 schema

- IntegrationEvent: platform、actor、reference、command、dedupe_key。
- ExternalReference: issue/PR/comment/review/file/range/thread。
- IntegrationReply: platform reply id/share url/artifact。

## 3. 错误码

- IntegrationUnauthorized
- ExternalEventIgnored
- ReferenceResolutionFailed
- PlatformRateLimited
- ReplyFailed

## 4. 兼容性

- 外部路径、operationId、CLI 参数、配置字段和事件名以调研附件与上游源码为基线，Rust 实现不得无迁移说明地改名。
- 新增字段必须显式版本化；删除字段必须先提供兼容层和 progress 记录。
- 所有外部输入进入 application 前必须 schema 校验；外部文本进入 prompt 前必须截断并包裹 `<untrusted_input>`。

## 5. 示例

- 成功：GitHub issue_comment 含 /opencode 触发 action，解析 thread/diff context 后创建 session 并回复 share URL。
- 失败：actor 无 write/admin 权限返回 IntegrationUnauthorized；重复 webhook dedupe 后不重复评论。

## 6. External Platform Contract — 2026-05-27

- GitHub Action: action.yml inputs/env, OIDC/PAT/GITHUB_TOKEN behavior, issue_comment/pull_request_review_comment payloads, /opencode and /oc triggers, branch/PR/share/comment artifacts.
- VS Code: commands/keybindings, terminal reuse/new terminal, file reference @File#Lx-y, /tui/append-prompt or CLI invocation, packaging/publish scripts.
- Zed: extension manifest/icon, ACP/CLI invocation, platform archive/sync workflow.
- Slack: socket-mode/env, thread-session mapping, share/tool-update reply contract.
