# 部署、发布与安装测试矩阵

## 1. 单元测试

- installer args/targets。
- local binary/no path。
- Nix eval metadata。

## 2. 场景测试

- 覆盖 application 主流程、失败分支和取消/重试路径。
- 验证领域事件顺序、状态机不变量和 repository 持久化结果。

## 3. 功能完整性测试

- installer args/targets。
- local binary/no path。
- Nix eval metadata。
- container build script。
- release manifest。
- patch audit。

## 4. E2E 测试

- 从 CLI/HTTP/SDK/WebJS/外部集成中适用入口发起请求，使用 mock provider、mock cloud 或临时 workspace。
- 验证用户可见输出、事件流、日志脱敏和清理行为。

## 5. 模糊测试

- 对本功能所有外部输入 parser、schema decoder、路径/URL/事件帧解析器建立 fuzz target。
- 新 crash 必须入 corpus，并在修复 PR 中引用。

## 6. 对抗性测试

- workspace 越界、prompt injection、secret 泄漏、未授权外部事件、危险操作审批绕过。
- 对外部文本、工具输出、MCP/plugin/cloud/editor payload 断言 `<untrusted_input>` 包裹策略。

## 7. Prompt 回归

- 涉及 agent、tool description、provider prompt、repo-local asset 或用户可见 summary/title 时，必须维护 prompt 快照和回归报告。

## 8. Agent Eval

- 涉及 agent loop、tool、provider、MCP、session、prompt 的变更必须跑 trajectory、tool-use accuracy、LLM-as-judge、cost-latency budget 和上游基线对照。

## 9. Release/CI 用例 — 2026-05-27

- Installer: local binary, missing binary, unsupported OS/arch, Linux musl, x64 baseline, --no-modify-path, release not found, checksum mismatch.
- Nix: flake eval for four systems, overlay packages, hash updater fake hash flow.
- Containers: base/bun-node/rust/tauri-linux/publish build with amd64/arm64 and push/no-push.
- GitHub workflows: beta/publish/deploy/test/typecheck/nix/docs/stats/containers/vscode/github-action/zed sync trigger and secret requirements.
- Patches: each patched dependency has keep/remove/replacement decision and CI drift check.
