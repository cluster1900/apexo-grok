# M1 Interface Foundation crate 选型调研报告 — 2026-05-28

- **触发**：M1 需要把 Rust server skeleton、OpenAPI/SDK 生成链路和 WebJS desktop sidecar 协议占位闭环；新增 HTTP/router/cancellation 依赖前必须完成维护性、许可证和安全检查。
- **结论**：M1 采用 `axum` + `tokio` + `tokio-util` + `tower` 的最小 interface 基础栈。OpenAPI 文档和 TypeScript SDK 先由仓库内静态 contract/codegen 生成，不在 M1 引入 `utoipa`、`aide` 或外部 SDK generator；Desktop sidecar 先落纯 `serde` contract 类型。

## 1. 问题陈述

本次调研回答四个问题：

1. M1 HTTP server skeleton 是否需要引入 Rust Web framework，还是继续保持纯类型占位？
2. 若引入框架，哪组 crate 满足许可证兼容、近 12 个月维护、与 Tokio runtime 一致、能支持后续 SSE/WS 扩展？
3. M1 OpenAPI/SDK 是否应直接引入 OpenAPI generator crate？
4. Desktop WebJS sidecar 的最小 Rust contract 应如何落位，避免提前绑定 Electron 实现细节？

## 2. 候选方案 / 调研对象

### 2.1 `axum`

`axum` 是 Tokio 生态内的 HTTP routing/request handling 框架。`cargo info axum` 返回：

| 字段 | 数据 |
|---|---|
| 版本 | `0.8.9` |
| 许可证 | MIT |
| Rust version | 1.80 |
| repository | `https://github.com/tokio-rs/axum` |
| documentation | `https://docs.rs/axum/0.8.9` |

适合 M1 的原因：

- 与 Tokio/Tower/Hyper 同生态，后续 SSE/WS、middleware、graceful shutdown 扩展路径清晰。
- `Router` 可直接做 handler 单元测试，不需要先启动真实端口。
- MIT 许可证兼容仓库当前 `MIT OR Apache-2.0` 策略。

### 2.2 `tower`

`tower` 提供 `Service` 抽象和测试用 `ServiceExt::oneshot`。`cargo info tower` 返回：

| 字段 | 数据 |
|---|---|
| 版本 | `0.5.3` |
| 许可证 | MIT |
| Rust version | 1.64 |
| repository | `https://github.com/tower-rs/tower` |
| documentation | `https://docs.rs/tower/0.5.3` |

M1 只启用 `util` feature，用于 router contract 测试；生产路径不依赖 tower 的复杂 middleware 组合。

### 2.3 `tokio-util`

`tokio-util` 提供 `CancellationToken`。`cargo info tokio-util` 返回：

| 字段 | 数据 |
|---|---|
| 版本 | `0.7.18` |
| 许可证 | MIT |
| Rust version | 1.71 |
| repository | `https://github.com/tokio-rs/tokio` |
| documentation | `https://docs.rs/tokio-util/0.7.18` |

M1 server skeleton 需要 graceful shutdown；用 `CancellationToken` 比自己维护 channel 更直观，也与后续 agent runner / sidecar supervisor 的取消语义一致。

### 2.4 OpenAPI generator crate

候选包括 `utoipa`、`aide`、`paperclip` 或直接使用外部 JS SDK generator。M1 暂不引入，原因：

- 当前只需要 `/global/health` 与 `/openapi.json` 的最小 contract；引入完整 OpenAPI derive 会先增加依赖面，却不能解决后续 131 endpoints 的 schema drift 问题。
- 上游 OpenAPI public compatibility patch 还需要单独复刻；M1 应先建立可测试的 `OpenApiSchemaProvider` 形态。
- 后续进入 131 endpoint codegen 时再做专门调研，避免在 skeleton 阶段锁死 generator。

### 2.5 Desktop sidecar contract

Desktop sidecar M1 不需要 Electron runtime crate。先用 `serde` 类型固定 sidecar 初始化与 ready/error frame：

- `InitStep`：`server_waiting`、`sqlite_waiting`、`done`。
- `ServerReadyData`：`url`、`username`、`password`，Debug 必须脱敏 password。
- `SidecarEvent`：`ready`、`sqlite`、`stopped`、`error`。

## 3. 评估维度

| 维度 | 说明 |
|---|---|
| 维护性 | 最新版本、repository、近 12 个月是否发布或有活动。 |
| 许可证 | 必须落在 `deny.toml` allow list。 |
| DDD 边界 | interface crate 不能把业务逻辑或外部 DTO 泄漏到 domain/application。 |
| M1 闭环价值 | 是否能跑通 router -> OpenAPI -> SDK -> sidecar contract 的最小验证。 |
| 后续扩展 | 能否扩展到 SSE/WS、Basic Auth、workspace routing、OpenAPI diff。 |

## 4. 对比分析

| 方案 | 优点 | 风险 | M1 决策 |
|---|---|---|---|
| `axum` router | 生态成熟、测试方便、Tokio/Tower 一致 | 引入 HTTP 栈依赖 | 采用，功能限制在 health/openapi route。 |
| 自写 Hyper service | 依赖更少 | handler/middleware/测试样板更多，后续 SSE/WS 成本高 | 不采用。 |
| `tower` test util | 让 router contract 测试无需端口 | 作为直接 dev dependency 增加一项依赖 | 采用，只启用 `util`。 |
| `tokio-util` cancellation | 与长任务取消语义一致 | 需要新增直接依赖 | 采用。 |
| `utoipa`/`aide` | 可生成 OpenAPI | 当前 endpoint 太少，后续 public patch 未定 | M1 不采用，后续 codegen 专项调研。 |
| 纯 `serde` sidecar contract | 依赖少，契约清晰 | 不验证 Electron utility process | 采用，Electron 集成留到后续 prototype。 |

安全检查：

- `cargo audit --stale` 已在当前锁文件上通过，RustSec advisory-db 加载 1098 条公告，当前 183 个依赖未命中漏洞。
- 新增依赖后仍必须跑 `cargo deny check` 与 `cargo audit`；结果写入 testing 报告。

## 5. 决策与理由

M1 interface foundation 采用：

```text
opencode_server
├── axum Router: /global/health, /openapi.json
├── OpenAPI static contract: health/openapi 两个 operation
├── TypeScript SDK generator: 从 OpenAPI contract 生成最小 client 文件
└── serve(listener, CancellationToken): 支持 graceful shutdown

opencode_desktop
└── serde sidecar contract: InitStep / ServerReadyData / SidecarEvent
```

暂不引入：

- `utoipa`、`aide`、`paperclip`
- 外部 JS SDK generator
- Electron/Tauri Rust 绑定

理由：

- M1 的目标是闭环 skeleton，不是一次性补齐 131 endpoints。
- `axum` 能提供真实可测试 HTTP router，避免 server skeleton 停留在纯类型。
- OpenAPI/SDK 先用仓库内最小 generator，让后续 131 endpoint migration 有落脚点。
- sidecar 先固定 JSON frame 和 secret redaction，再进入 Electron utility process 集成。
