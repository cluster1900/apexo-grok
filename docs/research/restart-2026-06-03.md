# 重新初始化调研记录

日期：2026-06-03

## 背景

旧仓库在真实 agent 主链路落地前，已经提前拆出了大量 architecture、development、progress、testing 子目录。M2 又横跨 provider、session、tool、config、desktop、HTTP、observability 等切片，导致维护对象多于可运行能力。

## 问题判断

- 文档粒度过细，读者需要在多个目录间跳转才能确认一个事实。
- 进度表暗示了多个功能边界，但代码仍然只是 skeleton。
- crate 边界提前固化，容易把未验证的 DDD 拆分变成实现负担。
- 测试门禁过早要求全量类型覆盖，不适合重新设计初期的小步验证。

## 决策

将仓库重置为最小基线：

- 文档只保留六类入口，不保留旧功能目录。
- Rust workspace 只保留 `opencode-core` 和 `opencode-cli`。
- 当前不实现完整 provider、完整 tool、完整 session runtime、完整 MCP、desktop、HTTP API；精简 ContextPack / Skill / MCP Lite 会在 `minimum-agent` 阶段内进入。
- 新功能先写最小调研记录，再由人类确认是否进入设计和实现。

## 非目标

- 不恢复旧 M1/M2 设计。
- 不在本次重置里重新实现真实 agent loop。
- 不提前建立完整 OpenAPI、SDK、desktop sidecar 或 provider adapter。
- 不为了未来可能需要的能力新增 trait、feature flag 或公共 crate。

## 下一步需要确认的问题

1. 第一条可运行主线已确认：`minimum-agent`。
2. 兼容目标已收敛：先复刻上游 opencode 的核心链路和扩展边界，不一次性复刻完整 CLI/TUI/MCP/provider catalog。
3. 第一个 milestone 已确认：M1 只做 domain kernel；后续按 M0-M9 进入 mock CLI、ContextPack、session store、provider、capability、read/skill tool、MCP Lite、write/shell permission。
