## 3. 评估维度

- **功能完整性**：是否覆盖 CLI、HTTP、SDK、Tool、Desktop、Web UI、TUI、MCP、Provider、Plugin、PTY、LSP、share、sync、stats、console、GitHub/Slack/VS Code/Zed、install/Nix/CI/container/release、infra/cloud、`.opencode` 资产、shared libraries。
- **入参/出参可验性**：是否能从源码/生成清单定位每个接口的 params/query/payload/success/error。
- **DDD 适配性**：domain 是否零 I/O，application 是否编排用例，infrastructure/interface 是否只做适配。
- **安全边界**：workspace 路径、命令执行、权限审批、外部内容、secret、MCP/plugin 隔离、trace。
- **迁移可分阶段**：Rust core 与 WebJS desktop 是否能先协议兼容，再逐步替换 TS 实现。

## 4. 对比分析

| 层 | 上游事实 | Rust + WebJS 迁移判断 |
|---|---|---|
| domain | 上游使用 Effect service 和 Schema 混合领域、I/O、HTTP。 | Rust domain 拆纯模型：Session、Message、ToolCall、Project、ProviderCatalog、PermissionWorkflow、PtySession、MCPServerConnection。 |
| application | 上游 `SessionPrompt`、`Processor`、`ToolRegistry`、`MCP`、`ShareNext` 承载用例编排。 | Rust application 定义 use case：send prompt、run tool、approve permission、sync replay、share、workspace warp、PTY attach。 |
| infrastructure | 上游直接依赖 SQLite、git、ripgrep、LSP、node-pty、AI SDK、Electron utilityProcess。 | Rust infrastructure 用 `sqlx/rusqlite`、`git2`/process git、`ignore`/ripgrep wrapper、LSP client、PTY crate、provider adapters。 |
| interface | 上游 yargs CLI、Effect HttpApi、SSE/WS、Electron preload。 | Rust 提供 CLI + HTTP/SSE/WS server；WebJS desktop 保留 preload API 和 sidecar 启停协议。 |
| WebJS | 上游 Solid Web UI 依赖 SDK v2、global sync、PTY websocket、native preload。 | 保留 WebJS UI 与 desktop shell，改为连接 Rust server，生成兼容 JS SDK。 |

## 5. 决策与理由

1. **协议优先迁移**：先固定 HTTP/CLI/Tool/Desktop preload 入参出参，Rust server 实现兼容协议，WebJS 不先重写。
2. **DDD 划分以业务上下文为准**：Session/Tool/Provider/Project/Config/MCP/Storage/Interface/Desktop 加上 Deployment/External/Cloud/Prompt Assets/Shared Libraries 分上下文，避免把上游文件夹机械翻译成 crate。
3. **入参出参以生成清单为规划基线**：`附件/http-api-inventory.generated.md`、`openapi-schema-inventory.generated.md`、`cli-command-inventory.generated.md`、`tool-inventory.generated.md` 是本轮规划的接口索引；字段级类型由 OpenAPI component schema、SDK `types.gen.ts` 和后续 Rust OpenAPI schema 对齐。
4. **Desktop 作为 WebJS 适配层保留**：Electron 仍负责窗口、updater、native picker、clipboard、deeplink、sidecar 启停；Rust sidecar 替换 TS server。
5. **子 agent 核对纳入验收证据**：Hubble 覆盖 CLI/HTTP/SDK，Nash 覆盖核心领域，Arendt 覆盖 Desktop/WebJS/外围包。
6. **全仓缺口复核纳入基线**：第一版 package 清单漏掉 root 级和无 package.json 目录，本报告以 `repository-scope-gap-analysis_2026-05-27.md` 修正完整性边界。
7. **开发文档按功能拆分**：总迁移文档只保留跨功能计划，具体开发拆到 18 个 feature 目录，避免实现阶段没有明确 owner、接口、数据和测试入口。
8. **sub-agent 验证闭环**：Wegener、Plato、Huygens 的缺口反馈已转为文档修复，包括 question 事件名、permission reply 语义、MessageV2 part union、Desktop preload/IPC、installer/Nix/cloud/specs/perf 等 contract。
