## 4. 插件化与分层判断

必须是核心分层，不能直接插件化：

- `ContextPackBuilder`：负责把 instruction、skill index、memory snapshot 拼成 provider-neutral prompt 上下文。
- `WorkspaceRoot` / `WorkspacePath`：所有本地 instruction、skill、tool 都依赖它。
- `PermissionEvaluator`：MCP tool、skill tool、write/shell 都走同一权限层。
- `ToolRegistry`：统一 builtin / skill / mcp / plugin 来源，保证 schema 和输出处理一致。
- `SessionRepository`：memory snapshot 和 session history 的唯一写入边界。

可以插件化：

- skill source：本地、全局、远程 URL、marketplace。
- memory source：session summary、project memory、user memory、embedding memory。
- MCP server source：配置文件、plugin manifest、marketplace 安装。
- prompt asset：system prompt、skill、command、agent template。

不能插件化绕过：

- workspace containment。
- permission。
- secret redaction。
- tool schema revalidation。
- MCP 子进程隔离和 timeout。
- `ContextPack` 的不可信内容标记。

## 5. 对阶段拆分的修正

原 M0-M7 缺少前期 context/skill/memory/MCP 精简版。修正为 M0-M9：

- M3 新增 `Context Pack`：instruction + skill index + memory snapshot。
- M4 保留 session store，但同时持久化 memory snapshot。
- M7 新增 `Workspace Read + Skill Tool`，把 skill 从静态 index 变成可加载内容。
- M6 新增 `Extension Kernel`，把 provider/tool/prompt/memory/mcp 扩展纳入 capability。
- M8 新增 `MCP Lite Bridge`，只做 local stdio + tool/resource，不做 OAuth/remote。
- M9 再进入 write/shell + permission。

这样能前期覆盖重能力的最小版本，又不把完整 MCP runtime、长期记忆和动态插件运行时一次性压到首个实现里。
