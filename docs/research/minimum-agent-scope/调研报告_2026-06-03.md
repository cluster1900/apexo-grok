# minimum-agent 最小实现范围调研报告 — 2026-06-03

## 1. 调研目标

本调研用于回答一个问题：当前文档是否足以支撑先做出一个最小可运行的 opencode-rs，并保证后续 Provider、Tool、Prompt、MCP、TUI/Web/Desktop 等能力可以通过插件或扩展点逐步安装。

结论：

- 可以先做 `minimum-agent`，但必须严格按 M0-M9 小阶段推进。
- 第一段开发只允许进入 M1：纯 domain kernel，不写 CLI、Provider、Storage、Tool、Plugin。
- 上游 opencode 的完整能力不能一次性复刻到代码层，只能先复刻核心链路和扩展边界。
- 插件化第一步不是运行插件进程，而是先定义 capability manifest、注册校验和权限上限。
- Skill、MCP、memory/context 不能全部后置；前期要做精简 `ContextPack`、`skill` 和 `McpLite`，完整 runtime 后置。

## 3. 最小链路

最小 opencode-rs 只保留下列纵向闭环：

```text
CLI prompt
  -> application run use case
  -> ContextPackBuilder
  -> Session aggregate
  -> Provider stream as LlmEvent
  -> SessionProjector
  -> optional Tool loop
  -> stdout + SessionRepository
```

阶段内必须保留的安全边界：

- workspace 路径必须由 `WorkspaceRoot` 产生 `WorkspacePath`。
- tool call 参数必须 schema 校验后执行。
- write / shell / network / dangerous 必须经过 permission。
- provider、tool、plugin 都不能直接修改 session storage。
- 外部内容进入 prompt 前必须包裹 `<untrusted_input>`。
- secret 只能来自 env / secret provider。
- instruction、skill、MCP resource、memory snapshot 都必须通过 `ContextPack` 进入模型上下文。

## 4. 阶段取舍

| 阶段 | 为什么需要 | 为什么不更早做后续能力 |
|---|---|---|
| M0 文档确认 | 先让范围、非目标、测试门禁被人工确认。 | 未确认前开发会再次膨胀。 |
| M1 Domain Kernel | 上游 processor 的最小可测试核心是事件投影和 session 不变量。 | CLI / provider / storage 都会引入 I/O 和依赖选型。 |
| M2 Mock CLI Run | 建立一个用户可运行入口，证明 application 编排成立。 | 真实 provider 会把 auth、streaming、错误协议提前带入。 |
| M3 Context Pack | 上游 instruction/skill/context 是 prompt 入口前置能力。 | 不做远程 skill、全局 skill、真实 compaction。 |
| M4 Session Store | 最小 agent 需要可恢复 session 和 memory snapshot。 | SQLite / migration 需要单独选型；可先用临时 JSON repository。 |
| M5 Provider Adapter | 真实 agent 需要 provider streaming。 | 完整 provider catalog 和 OAuth 不属于最小实现。 |
| M6 Extension Kernel | provider/tool/prompt/memory/mcp 扩展需要先有 capability 边界。 | 不运行外部插件进程。 |
| M7 Workspace Read + Skill Tool | coding agent 需要读项目文件，也需要按 skill index 加载 skill 正文。 | 不写文件、不执行 shell、不做外部 skill marketplace。 |
| M8 MCP Lite Bridge | 上游 MCP 连接 tool/resource；最小实现要有 local stdio 桥。 | 不做 remote HTTP/SSE、OAuth、动态 add。 |
| M9 Write/Shell + Permission | coding agent 需要改文件和运行命令。 | 默认不能自动执行危险操作，TUI 审批不是最小必需。 |

## 5. 插件化边界

核心必须长期保留：

- Session 聚合和 message / part schema。
- Workspace guard。
- Permission evaluator。
- Secret redaction。
- Trace / event schema version。
- Tool 参数 schema 重校验。
- Provider stream 到 `LlmEvent` 的协议边界。
- ContextPack 组装规则和不可信标记。
- MCP 子进程隔离、timeout 和 tool/resource schema 边界。

插件可以扩展：

- provider adapter。
- tool definition + executor。
- prompt asset。
- event subscriber。
- UI slot。
- MCP server bridge。
- memory source。
- formatter / LSP / snapshot / stats / sync 等后置能力。

插件不允许：

- 绕过 workspace guard。
- 绕过 permission。
- 直接写 session repository。
- 替换 secret redaction。
- 降低 capability 声明的权限上限。
- 注入未校验 system prompt 字段。
