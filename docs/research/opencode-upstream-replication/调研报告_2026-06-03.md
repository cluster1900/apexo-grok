## 3. 顶层架构判断

上游不是“CLI 直接调用模型”的结构，而是：

```text
CLI/TUI/Web/Desktop/Slack/GitHub/SDK
  -> HTTP API / SDK / in-process server
  -> Instance Runtime
  -> Application Services
  -> Domain-like protocol models
  -> Infrastructure adapters
```

核心运行时以 Effect Layer/Service 组合，服务包括：

- Config、Plugin、Project、File、FileWatcher、Vcs、LSP、Format。
- Session、SessionPrompt、SessionProcessor、SessionRunState、SessionStatus、SessionCompaction、SessionSummary、SessionRevert。
- Provider、ProviderAuth、Agent、Command、Skill、MCP。
- ToolRegistry、Permission、Question。
- Storage/Database、Bus/Event、SyncEvent、Pty、Workspace/Worktree。

关键特征：

1. **Instance Runtime**：按 directory/worktree/project 加载实例，并缓存、reload、dispose。
2. **Session 主聚合**：会话、消息、part、tool state、todo、permission、snapshot、summary 都围绕 session 运转。
3. **Provider 协议隔离**：不同 provider 最终映射成统一 `LLMEvent`。
4. **Tool/Permission 一体化**：工具执行前后走 schema、权限、metadata、trace、输出截断。
5. **Plugin/MCP 非边缘功能**：插件可改配置、注册工具、改 prompt、改 params/headers、监听事件，MCP 提供外部 tool/prompt/resource。
6. **UI 只消费事件和 SDK**：Web/TUI/Desktop 不拥有核心业务规则。

## 4. 主运行链路

### 4.1 非交互 `opencode run`

入口：`packages/opencode/src/cli/cmd/run.ts`。

能力：

- 解析 prompt、文件附件、agent、model、variant、session、share、format、permission、port、replay、demo。
- 支持 `--interactive`、`--attach`、`--continue`、`--session`、`--fork`、`--command`、`--format json`、`--dangerously-skip-permissions`。
- 可以启动本地 server，也可以连接已存在 server。
- 通过 SDK 调用 session API，再订阅事件输出。

核心链路：

```text
run command
  -> bootstrap InstanceRuntime or connect server
  -> session create/get/fork/share
  -> SessionPrompt.prompt
  -> createUserMessage
  -> runLoop
  -> resolve Agent/Model/Tools/MCP/Permission
  -> LLM.Service stream
  -> SessionProcessor consumes LLMEvent
  -> Session DB + Bus/Event + UI/SSE output
```

### 4.2 交互 TUI / split-footer runtime

入口：`packages/opencode/src/cli/cmd/run/runtime.ts` 和 `cli/cmd/tui/*`。

TUI 不是简单 shell prompt，而是一套 OpenTUI app：

- keymap、command palette、dialogs、theme、mouse、clipboard、audio。
- session list、model/agent/provider/mcp/theme/status/help dialogs。
- prompt stash/history/frecency。
- permission/question/subagent 状态展示和回复。
- stream reducer、scrollback、diff view、tool output、session replay。
- TUI 插件 slot/route/keymap API。

迁移判断：Rust 最小实现不应先复刻完整 TUI。先做纯 CLI 输出和简单交互 REPL；等事件协议稳定后再接 TUI。

## 7. Agent Loop 实现

核心位置：

- `packages/opencode/src/session/prompt.ts`
- `packages/opencode/src/session/processor.ts`
- `packages/opencode/src/session/tools.ts`
- `packages/opencode/src/session/run-state.ts`
- `packages/opencode/src/session/status.ts`
- `packages/opencode/src/session/compaction.ts`

`SessionPrompt.prompt` 做：

1. 清理/处理 revert。
2. 解析用户输入中的 file/resource/reference/agent mention。
3. 处理附件和图片。
4. 选择 agent/model/variant。
5. 写入 user message 和 parts。
6. 进入 `runLoop`。

`runLoop` 做：

1. 加载 compacted message stream。
2. 判断是否已结束或需要继续工具循环。
3. 首轮自动生成 title。
4. 解析 agent、model、tools、MCP tools、structured output。
5. 构造 system prompt、reminders、skills、instructions。
6. 调插件 hook：message/system/params/headers/messages transform。
7. 调 `LLM.Service.stream`。
8. 用 `SessionProcessor` 将 LLMEvent 转成 message/part/event。
9. 处理 overflow、compaction、summary、retry、stop/continue。
10. 运行结束后 prune tool output。

`SessionRunState` 保证同一 session 同时只有一个主循环/shell，并负责取消运行和取消子任务。

迁移判断：

- Rust 最小 agent 的核心验收就是这条 loop 的小版本。
- M1 可 text-only，但 M2 必须加入 tool loop，否则不是 coding agent。

## 8. LLM/Provider 协议

`packages/llm` 是上游正在收敛的 native LLM core。

核心协议：

- `LLMRequest`：model、system、messages、tools、toolChoice、generation、providerOptions、http、responseFormat、cache。
- `Message`：role + content parts。
- ContentPart：text、media、tool-call、tool-result、reasoning。
- `ToolDefinition`：name、description、JSON Schema。
- `LLMEvent`：step/text/reasoning/tool/finish/provider-error。
- `Usage`：input/output/total/cache/read/write/reasoning 标准化。

Provider route 由四部分组成：

```text
Route = Protocol + Endpoint + Auth + Framing/Transport
```

- Protocol 负责 provider native body 构造和流式事件解析。
- Endpoint 负责 URL。
- Auth 负责 bearer/header/SigV4 等。
- Framing/Transport 负责 SSE、AWS event stream、WebSocket 等。

`packages/opencode/src/session/llm/*` 还有两条运行路径：

- 默认 AI SDK path：`streamText` -> `ai-sdk.ts` -> `LLMEvent`。
- 实验 native path：`native-request.ts` -> `@opencode-ai/llm` -> `native-runtime.ts` -> `LLMEvent`。

两条路径最终都收敛到统一 `LLMEvent`，下游 SessionProcessor 不关心 provider 差异。

迁移判断：

- Rust 版不需要复刻 AI SDK path。
- 应直接实现 `LlmRequest` + `LlmEvent` + provider adapter。
- 第一个 provider 建议做 OpenAI-compatible 或 OpenAI Responses 子集；其它 provider 延后为 adapter/plugin。
- Provider crate 选型必须另开 research，不能在本报告里拍板。

Tool 协议包括：

- description。
- Effect schema / JSON Schema 参数。
- execute(ctx)。
- ctx 包含 sessionID、messageID、callID、agent、abort、messages、metadata、ask。
- 执行前 decode，执行中 trace，执行后输出截断和格式化。
- 插件和 MCP 工具统一并入 registry。

Permission 模型：

- 规则 `{ permission, pattern, action }`。
- action 为 `allow | deny | ask`。
- read/edit/shell/network/doom_loop/external_directory/question/plan 等都通过规则判定。
- ask 会产生 pending request，等待 once/always/reject。
- always 会持久化并可自动满足同 session 同类请求。

迁移判断：

- Permission 是安全不变量，不能插件化为最终判定。
- Tool 可以插件化，但工具参数重校验、workspace path guard、permission ask、输出审计必须在 core/application。
- Rust M2 的最小工具建议：read、grep/glob、edit/write 二选一、shell。

## 17. Rust DDD 拆分建议

这是调研草案，不是最终架构冻结。

| 限界上下文 | 领域对象 | 应用用例 | 基础设施适配 |
|---|---|---|---|
| Workspace / Project | `WorkspaceRoot`、`WorkspacePath`、`ProjectId`、`WorktreeRef` | 解析 root、路径规范化、越界拒绝、VCS 摘要。 | git、filesystem、watcher。 |
| Conversation / Session | `Session`、`Turn`、`Message`、`Part`、`RunState`、`Usage` | 创建/恢复会话、追加消息、记录事件、取消、summary/compaction。 | SQLite repository。 |
| Agent Orchestration | `AgentProfile`、`PromptPlan`、`LoopPolicy` | 选择 agent/model/tools、构造 prompt、执行 loop、step 限制。 | provider/tool ports。 |
| Provider / Model | `ProviderId`、`ModelId`、`ModelRef`、`LlmRequest`、`LlmEvent` | provider-neutral request/stream/usage。 | OpenAI-compatible/Anthropic 等 adapter。 |
| Tool / Permission | `ToolDefinition`、`ToolCall`、`ToolResult`、`PermissionRule`、`PermissionRequest` | 注册工具、decode、权限判定、执行审计。 | shell、ripgrep、editor、network。 |
| Extension Platform | `PluginManifest`、`Hook`、`ExtensionCapability` | 插件发现、能力注册、hook 调用、隔离。 | WASM/子进程/JSON-RPC runtime。 |
| Interface Delivery | CLI、HTTP、TUI、Desktop、SDK | 输入输出、事件订阅、权限交互。 | clap/axum/ratatui/electron sidecar 等。 |

依赖方向：

```text
interface
  -> application
    -> domain
application
  -> ports
infrastructure
  -> ports implementations
plugin runtime
  -> extension ports
  -> cannot bypass core invariants
```

## 18. 最小实现路线

建议不要一次性复刻所有上游功能。最小实现应该是可运行的纵向链路。

### M1：Text-only Agent

说明：本节是最初的复刻建议，已经被 `docs/research/minimum-agent-scope/调研报告_2026-06-03.md` 和 `docs/research/opencode-context-extension-surfaces/调研报告_2026-06-03.md` 修正。当前阶段计划以 `docs/development/minimum-agent/阶段拆分.md` 的 M0-M9 为准。

目标：

- `opencode run "prompt"` 创建 session。
- 读取最小 config：provider、model、api key、workspace root。
- 构造 `LlmRequest`。
- 调一个 OpenAI-compatible provider。
- 流式输出 text。
- 保存 user/assistant message、text part、usage、finish reason。

非目标：

- 不执行工具。
- 不做 HTTP/OpenAPI/SDK。
- 不做 TUI/Desktop。
- 不做完整 MCP/plugin；精简 ContextPack / Skill / MCP Lite 已前移到 M3/M7/M8。

### M2：Coding Minimum

目标：

- Workspace path guard。
- read、grep/glob、edit/write、shell 最小工具。
- Permission allow/deny/ask。
- Tool call/result/error part。
- Tool loop 最多 N step。
- provider stream fixture 测试。

非目标：

- 不做完整 LSP/formatter/snapshot/revert。
- 不做 subagent/background task。
- 不做 websearch/MCP。

### M3：Extension Host

目标：

- 定义插件 manifest。
- 工具注册。
- provider adapter 注册。
- prompt/params/header hook 子集。
- event subscriber。

非目标：

- 不允许插件接管权限和 workspace。
- 不实现完整 TUI plugin。

### M4：API/UI

目标：

- HTTP API。
- SSE event。
- SDK 生成。
- TUI/Web/Desktop 接入。

非目标：

- 不改变 core event/session/tool/provider 协议。

## 19. 插件化边界

可以插件化：

- Provider adapter、model catalog、auth method。
- Tool。
- Command、Skill、Prompt asset。
- Formatter/LSP/workspace adapter。
- Prompt/system/messages/params/headers hook。
- TUI/UI extension。
- Event subscriber、stats/sync/share adapter。

不能插件化为最终裁决：

- Workspace 越界判定。
- Permission 最终判定。
- Secret redaction 和禁止落盘策略。
- Session/message/event schema 版本。
- Tool 参数 schema 重校验。
- Shell argv 参数化、timeout、资源上限。
- 外部内容进入 prompt 前的不可信标记。
- RunState cancellation 和孤儿进程清理。

## 20. 关键迁移风险

1. **过早横向拆分**：还没跑通主链路就拆 provider/tool/session/plugin 会重复上次失败。
2. **消息模型过简**：后续 tool/replay/compaction/UI 必返工。
3. **provider 直接绑定业务**：Session 不应知道 provider native 协议。
4. **权限做成 UI 行为**：权限必须是 application/core 判定，UI 只负责回答。
5. **插件绕过安全边界**：插件只能注册能力，不能接管不变量。
6. **HTTP/API 先行**：接口会冻结未验证模型。
7. **TUI 先行**：会消耗大量工程量却不证明 agent loop 正确。

## 21. 后续必须补充的专题 research

1. Provider crate/HTTP streaming 选型：`reqwest`/`eventsource`/SSE/WebSocket/Anthropic/OpenAI-compatible。
2. SQLite/storage 选型：`sqlx`、`rusqlite`、migration、event store。
3. JSON Schema/tool schema 选型。
4. Plugin runtime 选型：WASM、子进程 JSON-RPC、动态库、配置驱动。
5. TUI 技术选型：ratatui/crossterm 与事件协议绑定。
6. Snapshot/revert 设计。
7. Prompt asset 和 skill 目录规范。
